# 결정 사항 (확정 · 미정)

> 마지막 정리: 2026-10-31 (팀 결정 반영) · 관리: 문서 담당자
> 확정·미정 상태를 바꾸는 것은 사람(문서 담당자)이 한다. AI는 제안만 한다.

## AI 규칙

- **확정** 항목은 그대로 따른다. `features.md`와 다른 확정 항목은 이 파일을 따르고, 다르다는 사실을 사용자에게 알린다.
- **미정** 항목은 AI가 스스로 판단해 정하지 않는다. **AI의 판단보다 사용자의 의견이 우선이다.** 선택지와 장단점을 보여 주고 사용자가 고르게 한다.
- 값이 당장 필요하면 상수·설정으로 분리하고 `TODO(D-xx)`를 단다. 구현 방향이 크게 갈리면 작업을 멈추고 사용자에게 묻는다.

| 대출 상품 | 실제 대출 상품의 금리·한도를 참고해 더미 대출 상품 데이터를 만든다. 화면에서는 같은 점수대의 참고 정보로 표시한다 (D-12, N-18) |
| 신고 처리 | 신고 기준·숨김·차단 방식은 게시판 담당 팀이 정한다. AI는 정하지 말고 담당자에게 확인한다 (N-33, N-34) |
| 월별 데이터 | 입력 데이터를 DB에 저장할 때 날짜 데이터를 함께 저장해 월별 이력을 남긴다 (D-16, N-19·N-21·N-22) |

| 결과 공개 | 대안 점수가 더 낮거나 개선이 없는 집단도 숨기지 않는다 (N-12, N-25) |

| AI 요약 입력 | 계산된 숫자만 AI에 넘긴다 (N-31) |
| 개인정보 | 이름·휴대폰·이메일은 마스킹 값만 저장. 개인정보가 담긴 데이터는 저장소에 올리지 않는다 (N-02) |
| 선개발 | 모델 서버 완성 전에는 mock 응답으로 개발한다 |
| 실험 기록 | 사용 변수·설정값·성능을 기록해 같은 결과를 재현할 수 있게 한다 |
| Git | `feature/기능명`(Jira 키 권장 `feature/FP-12-…`) → PR → `develop` → `main`, PR은 형상 관리자 확인을 거쳐 병합. 커밋 `행위 - 내용` (D-17) |
