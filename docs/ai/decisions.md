# 결정 사항 (확정 · 미정)

> 마지막 정리: 2026-11-09 (기능 명세서 v3 + 11/06 확정 UI 반영, 11/09 N-22 수정) · 관리: 문서 담당자
> 확정·미정 상태를 바꾸는 것은 사람(문서 담당자)이 한다. AI는 제안만 한다.
> **정리 원칙: 11/06 확정 UI(Avenue 기능 데모 v2)에 구현된 결정은 UI를 따른다.** UI에 없는 것은 기능 명세서 v3를 따른다. 근거가 UI인 항목은 `(UI)`로 표시했다.

## AI 규칙

- **확정** 항목은 그대로 따른다. `features.md`와 다른 확정 항목은 이 파일을 따르고, 다르다는 사실을 사용자에게 알린다.
- **미정** 항목은 AI가 스스로 판단해 정하지 않는다. **AI의 판단보다 사용자의 의견이 우선이다.** 선택지와 장단점을 보여 주고 사용자가 고르게 한다.
- 값이 당장 필요하면 상수·설정으로 분리하고 `TODO(D-xx)`를 단다. 구현 방향이 크게 갈리면 작업을 멈추고 사용자에게 묻는다.
- (UI) 표시 값 중 "예시 기준"은 시연용 값이다. 코드에 박지 말고 설정 상수로 둔다.

### 1-2. 계정·인증·개인정보

| 시연 계정 | 로그인 화면 '시연 계정'의 [채우기]로 아이디·비밀번호를 채운 뒤 일반 로그인한다. **비밀번호 없이 진입하지 않는다** (UI) — N-01-5 문구보다 우선 |

| 비밀번호 규칙 | **영문과 숫자를 섞어 8자 이상** (기호 요구 없음) (UI) — N-02-1의 "영문·숫자·기호"보다 우선 |
| 가입 나이 | 출생연도 **1930~2006**, 만 20세 이상만 가입 (DDL v0.3.2). 상한 연도는 해마다 바뀌므로 최종 검사는 Spring에서 한다 |

| 가입 동의 | 필수 2개(서비스 이용약관, 개인정보 수집·이용) + 선택 1개(점수 변동 알림·혜택 안내) (UI) |

| 개인정보 데이터 | 개인정보가 담긴 실제 데이터는 저장소에 올리지 않는다. 합성 데이터만 쓴다 |

### 1-4. 점수·데이터

| 구분 | 내용 |
|---|---|
| 신용 등급 | 3단계 **Good · Standard · Caution** (UI) — "Poor"는 쓰지 않는다 |
| 점수 범위·경계 | 점수 **0–1000**. 경계는 **665·780**(Caution 664 이하 / Standard 665~779 / Good 780 이상)을 설정 상수로 둔다. 시연용 임시값이며 모형 확정 후 바뀔 수 있다 (D-01, UI). 점수 범위 0–1000은 DDL의 점수 제약과 같고 11/12에 확정했다 |
| 대안 데이터 | **5종**: 간편결제, 통신비, 국민연금, 건강보험료, 공과금(11/12 추가, DDL v0.3.1 U1). 공과금은 전기·가스·수도 합계를 월 1행으로 저장하고 상태는 ON_TIME·LATE·UNPAID다. 모델에 쓰는 값은 미납 개월 수(LATE+UNPAID, 12개월 중 0~12)다. 더미 기관 응답은 5종 모두 12개월분이다 (N-05-6) |
| 가산점 | **N-23 가산점 기능 전부 제거**(11/06). 대안 데이터는 별도 가산점이 아니라 **모델 피처로 점수에 들어간다** (UI) |
| 등급·성능 기준 | 등급과 모형 성능 비교(N-25)는 **모델 점수** 기준이다 (투표 D3에서 가산점 문구 제거) |
| 모델 결과 | 대안 모델 결과는 점수와 3등급으로 보여 준다(투표 D2). 모델 버전을 함께 저장하고 모델 교체는 하지 않는다(투표 D8). 두 합성 집단은 합쳐 보여 주되 집단별로도 볼 수 있다(투표 D6) |
| SHAP 표시 | 항목명과 증감 점수를 표시한다(D-11). "작용한 정도"로만 쓰고 원인처럼 쓰지 않는다. 대안 데이터 항목에 [대안] 표시. 기준점 639는 시연용 예시 (UI) |
| 결과 공개 | 대안 점수가 더 낮거나 개선이 없는 집단도 숨기지 않는다 (N-12, N-25) |
| 소득 입력·점수 산출 | **월 소득 12개월 입력으로 확정**(11/09, N-05-2·N-05-8). 자영업자·프리랜서는 최근 12개월 월별 소득을 모두, 급여소득자는 월급(보너스 제외)을 입력해야 점수를 산출한다. [점수 산출하기]는 소득·기간·자산·카드/부채·지출·대안 데이터(4종 중 1개 이상) 6항목이 모두 차야 열린다 (UI) |
| 정보 부족 | N-22-2 "6개월 미만 정보 부족" 처리는 **삭제**(11/09). 화면에 정보 부족 안내를 두지 않는다 |
| 재직·운영·활동 기간 | 소득 입력(N-05-2)에서 함께 받는다 (UI) |
| 연소득 집계 | 자영업자·프리랜서는 월별 소득 합, 급여소득자는 월급 × 12 (보너스 제외) (투표 D9) |
| 월별 데이터 | 입력 데이터를 저장할 때 기준월(날짜)을 함께 저장해 월별 이력을 남긴다 (D-16) |
| 위험 단계 (예시 기준) | 상환 부담률(DSR) 30% 주의 / 40% 위험, 자산 대비 부채 40% / 60%, 순자산 대비 부채 70% / 100% (N-16-2, N-20-4) (UI) |
| 소득 부족 달 알림 | 최근 12개월 중 소득이 월 고정지출보다 적은 달을 찾아, 마지막 입력월 다음부터 다시 오기까지 남은 개월 수와 모자랐던 금액(미리 모아 둘 금액)을 가장 가까운 달부터 알린다. 부족한 달이 없으면 알리지 않는다 (N-22-5·6, 11/09) |
| 소득 변동 표시 (예시 기준) | 월 소득 변동 계수 12% 초과를 "변동이 큼"으로 표시한다 (N-22-3 변동성 지표) (UI) |
| 모형 비교 | 컷오프 550~750점(기본 650). 비교 표 지표 6개(ROC-AUC, 정확도, 오분류 비용, 우량 고객 오거절률, 부도 고객 오승인률, 승인률). 오분류 비용은 부도 오승인을 5배로 계산 (N-25) (UI) |
| 부도 확률 표시 | 신용 리포트에는 표시하지 않고, 시뮬레이터 결과에 "예상 부도 확률"(현재 → 변경 후)로 표시한다 (N-12-7, N-18-6) (UI) |
| 선개발 | 다른 서버가 준비되기 전에는 실제 응답과 같은 모양의 mock으로 개발한다 |
| 실험 기록 | 사용 변수·설정값·성능을 기록해 같은 결과를 재현할 수 있게 한다 |

### 1-5. 대출 상품·커뮤니티·AI

| 구분 | 내용 |
|---|---|
| 대출 상품 | 실제 상품의 금리·한도를 참고한 **더미 상품**(시연 9종)을 목록·상세·즐겨찾기(N-37)로 보여 주고, 시뮬레이터에서 점수에 맞는 3종을 추천한다(N-18-7). "더미 상품 · 실제 상품 아님"을 표시하고, [신청하기]는 안내만 한다. 금리·한도는 같은 점수대의 참고 정보다 (D-12, UI) |
| 신고 처리 | 글·댓글 **각각** 신고를 모으고, 기준 **5건**(관리자가 3~10건으로 조정)이 되면 자동 숨김("신고로 숨김 처리된 글입니다") → 관리자가 숨김 유지·삭제·반려. 신고는 하루 3번, 본인 글·중복 신고 불가, 사유 5개 중 선택(기타만 상세 입력). 처리하면 신고자에게 알리고, 삭제하면 작성자에게도 알린다 (D-10, UI). 세부 조정은 게시판 담당 팀이 정한다 |
| AI 요약 입력 | 요약(N-31)에는 계산된 숫자·라벨만 AI에 넘긴다 |
