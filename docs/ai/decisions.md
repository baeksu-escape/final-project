> 처음 정리: 2026-11-09 (기능 명세서 v3 + 11/06 확정 UI 반영) · 관리 방식(🆕 11/20): 결정을 정하거나 바꾼 사람이 같은 PR에서 이 파일을 고친다(누가·언제·근거). 문서 담당자는 리뷰에서 검수한다. **확정 결정을 바꾸면 PR에 조장 동의 댓글을 남긴다.**
>
> 🆕 최근 변경(11/20, FP-246): develop 기준으로 옛 내용 정리 — 관리자 2단계 인증은 이메일, 가입 휴대폰 인증 필수, 직군 변경(MEM-05), 표 48개, 대출 상품 17종, SHAP 기준점, D-30 구현 완료. 미정에서 확정으로: D-15·D-17·D-20·D-29·D-31, D-18(FastAPI 부분). 색인에 빠진 번호 추가
>
> 확정·미정 상태를 바꾸는 것은 사람이 한다. AI는 제안만 한다.
> **정리 원칙: 11/06 확정 UI(Avenue 기능 데모 v2)에 구현된 결정은 UI를 따른다.** UI에 없는 것은 기능 명세서 v3를 따른다. 근거가 UI인 항목은 `(UI)`로 표시했다.

## AI 규칙

- **확정** 항목은 그대로 따른다. `features.md`와 다른 확정 항목은 이 파일을 따르고, 다르다는 사실을 사용자에게 알린다.
- **미정** 항목은 AI가 스스로 판단해 정하지 않는다. **AI의 판단보다 사용자의 의견이 우선이다.** 선택지와 장단점을 보여 주고 사용자가 고르게 한다.
- 값이 당장 필요하면 상수·설정으로 분리하고 `TODO(D-xx)`를 단다. 구현 방향이 크게 갈리면 작업을 멈추고 사용자에게 묻는다.
- (UI) 표시 값 중 "예시 기준"은 시연용 값이다. 코드에 박지 말고 설정 상수로 둔다.

| 회원 탈퇴 | **상태 변경**이다. 계정 상태를 탈퇴로 바꾸고 회원 행은 지우지 않는다. 이름·이메일 등 개인정보는 대체값으로 덮어쓴다. 동의로 불러온 대안 데이터는 삭제하고 그 밖의 딸린 데이터(진단 내역 등)는 보관한다. 신용 라운지 글은 '탈퇴한 회원'으로 표시한다. 소셜 연결과 인증 기록은 삭제한다(인증 기록은 회원 번호뿐 아니라 이메일·휴대폰 HMAC으로도 찾아서 지운다. 가입 인증은 회원 번호가 비어 있기 때문이다). 탈퇴 직후 같은 아이디·이메일·소셜 계정으로 다시 가입할 수 있다(재가입 제한 없음) (N-04-7, DDL v0.3.2 W1, 11/12) |
| 보관 기간 | 직접 입력한 데이터와 평가는 탈퇴 후 5년, 시스템 로그와 관리자 열람 기록은 2년 이상 보관한다. 게시판 기록은 기간 없이 남긴다. 교육용이라 실제 파기 기능은 만들지 않는다 (DDL v0.3.2 W1~W6) |
| 가입 동의 | 필수 2개(서비스 이용약관, 개인정보 수집·이용) + 선택 1개(점수 변동 알림·혜택 안내) (UI) |
| 개인정보 저장 | 비밀번호는 BCrypt 해시. 이름·휴대폰·이메일은 **AES 암호화 저장**, 검색용으로 이메일·휴대폰 HMAC 값을 함께 저장. 화면·로그에는 마스킹한 값만 보이고, 비밀번호를 다시 확인하면 가림을 해제한다 (N-02-4, N-04-2, 투표 D5). UI의 '가림 해제'는 원래 값을 저장해야 동작하므로 이 방식과 맞다 |
| 개인정보 데이터 | 개인정보가 담긴 실제 데이터는 저장소에 올리지 않는다. 합성 데이터만 쓴다 |

### 1-4. 점수·데이터

| 구분 | 내용 |
|---|---|
| 신용 등급 | 3단계 **Good · Standard · Caution** (UI) — "Poor"는 쓰지 않는다 |
| 점수 범위·경계 | 점수 **0–1000**. 경계는 11/23부터 **CUT-0.3**(Caution 653 이하 / Standard 654~726 / Good 727 이상, 모델 0.2 점수 분포 25/50/25)이다(D-01, 정의서 C28). 이전 시연용 임시값은 665·780(CUT-0.1)이며 최종 값은 FP-144 이후 다시 확인한다. 점수 범위 0–1000은 DDL의 점수 제약과 같고 11/12에 확정했다 |
