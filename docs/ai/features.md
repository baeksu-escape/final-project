## 2. 기능 상세

### 회원관리

#### N-01 로그인·로그아웃 (일반·관리자 공통) — P0
- **설명:** 아이디와 비밀번호로 로그인하고 세션을 종료한다. 일반 사용자와 관리자가 같은 로그인 화면을 쓰고, 로그인한 계정의 역할에 따라 이동할 화면이 정해진다.
- **입력:** 아이디, 비밀번호
- **처리:** 계정과 비밀번호를 확인하고 세션을 만든다. 계정의 역할(일반 또는 관리자)을 확인해 이동 경로를 정한다. 로그아웃하면 세션을 지운다. 잠긴 계정은 로그인을 막고 안내한다.
- **출력:** 성공 시 일반 사용자는 신용 리포트, 관리자는 모형 성능 비교로 이동. 실패 시 오류 안내(아이디나 비밀번호 중 무엇이 틀렸는지는 알려 주지 않는다).
- **사용 테이블:** app_user
- **비고:** 소셜 로그인과 이중 안전장치(2단계 인증)는 제외(P3). 시연은 비밀번호 없이 진입하는 데모 계정을 쓴다.
- ⚠️ 인증은 세션이 아니라 토큰(JWT) 방식으로 확정 → decisions.md. 데모 계정 진입 방식은 D-06

#### N-02 회원가입 — P0
- **설명:** 사용자 계정을 만든다. 직군과 연령대를 함께 받아 이후 화면과 비교 집단을 정하고, 개인신용정보 수집·이용에 필수 동의해야 가입할 수 있다.
- **입력:** 이름, 휴대폰, 이메일, 비밀번호, 연령대, 필수 동의 체크
- **처리:** 입력 형식을 검사하고 비밀번호 규칙(8자 이상, 영문·숫자·기호)을 안내한다. 필수 동의가 없으면 가입을 막는다. 이름, 휴대폰, 이메일은 마스킹한 값만 저장하고 동의 이력을 남긴다.
- **출력:** 가입 완료 안내 또는 항목별 오류 안내
- **사용 테이블:** app_user, dim_worker_type, 신규 테이블(동의 이력)
- **비고:** 취미·관심상품 입력은 추천 상품 기능을 만들 때만 필요하다.
- ⚠️ 설명에는 직군을 받는다고 되어 있으나 입력 칸에는 직군이 없다 → D-04

#### N-03 아이디·비밀번호 찾기 — P0
- **설명:** 가입 정보로 아이디를 찾아 일부를 가려서 보여 주고, 비밀번호는 메일 인증코드로 재설정한다.
- **입력:** 아이디 찾기: 가입 시 입력한 정보. 비밀번호 찾기: 아이디, 이메일, 인증코드
- **처리:** 아이디 찾기는 입력 정보로 계정을 조회해 아이디 일부를 마스킹한다. 비밀번호 찾기는 인증코드를 만들어 메일로 보내고, 입력값과 맞으면 재설정 화면을 연다.
- **출력:** 마스킹된 아이디, 비밀번호 재설정 화면
- **사용 테이블:** app_user
- **비고:** 아이디 찾기(U-01)는 UI에 구현되어 P0. 비밀번호 메일 인증은 구현이 부담되면 이 부분만 P2로 내린다.

#### N-04 마이페이지 — P0
- **설명:** 내 정보를 보고 수정하고, 신용 등급 기준과 내 점수의 위치를 함께 확인한다.
- **입력:** 수정할 정보, 비밀번호 재입력(마스킹 해제 시)
- **처리:** 개인정보를 암호화하거나 마스킹해서 저장한다. 마스킹 해제 전에 비밀번호를 다시 확인한다. 등급 구간과 등급별 고객 비율을 조회하고 내 점수를 점수 막대 위에 표시한다.
- **출력:** 내 정보 화면, 등급 기준 카드(Good 780점 이상, Standard 665~779점, Caution 664점 이하), 등급별 고객 비율, 안내 문구
- **사용 테이블:** app_user, score_grade_band, assessment
- **비고:** UI에서는 등급 기준이 마이 페이지에 있어 한 화면으로 합쳤다.
- ⚠️ 등급 경계 점수는 아직 확정 전 → D-01

#### N-05 데이터 입력 화면 (소득, 대출, 자산, 월 지출) — P0
- **설명:** 평가에 쓰는 값을 입력한다. 공공 마이데이터(국민연금·건강보험료 납부내역) 간편 스크래핑은 모의 연동 화면으로 만든다.
- **입력:** 월별 소득, 대출, 자산, 월 고정지출, 기타 지출
- **처리:** 입력값을 검사해 저장한다. 모의 연동은 합성 데이터를 불러온다.
- **출력:** 입력 완료 현황
- **사용 테이블:** user_income_month, user_loan, user_asset_snapshot, user_expense_item, user_telecom_payment, user_easypay_usage
- **비고:** 직접 입력을 먼저 만들고 모의 연동을 얹는다. 국민연금·건강보험료 납부내역은 저장할 테이블이 없어 추가가 필요하다. 현금흐름·납부 조건 입력은 N-18, N-21에서 다룬다.

#### N-06 게시판 — P2
- **설명:** 사용자가 글을 쓰고 읽는 게시판.
- **입력:** 글 제목, 내용, 댓글, 신고(제목, 내용)
- **처리:** 글과 댓글을 저장하고 조회한다.
- **출력:** 글 목록, 상세 화면, 신고 화면
- **사용 테이블:** 신규 테이블 필요
- **비고:** 단순 CRUD라 구현은 쉽지만 핵심 가치와 거리가 있다. 직군별 게시판은 팀이 결정한다.
- **메모:** 게시글마다 신고하기 버튼이 추가되고 버튼을 누르면 제목과 내용을 쓰는 칸이 나오고 완료버튼을 누르면 관리자에게 전달이 된다. (상세 규칙은 N-33, N-34)

#### N-07 1:1 채팅 기능 — P4
- **설명:** 1:1 채팅.
- **입력:** 메시지
- **처리:** 실시간으로 메시지를 전달하고 저장한다.
- **출력:** 채팅 화면
- **사용 테이블:** 신규 테이블 필요
- **비고:** 구현 비용이 크고 핵심 목표와 관련이 적다. 정적 문의 게시판이나 챗봇(N-32)으로 대체할 수 있다.

#### N-33 게시글·댓글 신고하기 — P2
- **설명:** 사용자가 게시판에서 부적절한 글이나 댓글을 신고한다. 접수된 신고는 관리자가 신고 접수 게시판(N-34)에서 확인한다. 게시판(N-06)을 만들 때 함께 구현한다.
- **입력:** 신고 대상(게시글 또는 댓글), 신고 사유(목록에서 선택: 욕설·비방, 광고·스팸, 개인정보 노출, 허위 정보, 기타), 상세 내용(선택)
- **처리:** 로그인한 사용자만 신고할 수 있다. 본인이 쓴 글은 신고할 수 없고, 같은 사용자가 같은 대상을 중복 신고할 수 없다. 신고를 접수 상태로 저장한다. 같은 대상의 신고가 기준 건수(예: 3건, 팀 확정) 이상 쌓이면 일반 사용자 화면에서 임시로 숨기고 관리자 검토를 기다린다.
- **출력:** 신고 접수 완료 안내. 본인 글, 중복 신고, 로그인 필요 시 오류 안내. 임시 숨김 처리된 글은 '신고 검토 중인 글입니다'로 표시
- **사용 테이블:** 게시판 테이블(N-06), 신규 테이블(신고 접수: 신고 대상, 신고자, 사유, 상세 내용, 상태, 접수 시각)
- ⚠️ 신고 기준 건수·숨김·차단 방식은 게시판 담당 팀이 정한다. 구현 전 사용자에게 확인 → decisions.md

### 공통

#### N-08 역할·직군별 화면 분기 — P1
- **설명:** 로그인한 역할에 따라 사용자 화면과 관리자 화면을 나누고, 사용자 화면은 직군에 따라 보이는 서브탭과 카드를 다르게 한다. 시연용으로 헤더에서 직군을 바꿔 볼 수 있다.
- **입력:** 로그인 계정, 직군 선택(시연용)
- **처리:** 계정의 역할로 탭 구성을 정한다. 직군별 규칙: 회사원은 현금흐름 서브탭을 숨기고, 프리랜서는 현금흐름을 보이되 상권 지표를 숨기고, 자영업자는 모두 보여 준다. 직군 전환을 고르면 해당 직군의 시연 사용자로 바꾼다.
- **출력:** 사용자 탭: 신용 리포트, 직군별 재무 진단, 점수·금리 시뮬레이터, 마이 페이지. 관리자 탭: 모형 성능 비교, 직군·연령별 통계, 계정·권한 관리. 직군별 서브탭 구성과 안내 배지
- **사용 테이블:** app_user, dim_worker_type
- **비고:** 직군 전환은 시연 전용이라 실서비스에는 필요 없다(이 부분만 P4).

#### N-09 화면 환경 설정 (카드 편집·테마) — P2
- **설명:** 카드별로 화면 표시와 숨김을 켜고 끄고, 기본과 블랙 두 가지 테마로 바꾼다.
- **입력:** 카드별 표시 토글, 이 화면 모두 표시, 기본값으로, 완료, 테마 선택
- **처리:** 선택한 카드만 화면에 표시하고 색 테마를 바꾼다. 설정은 화면에서만 적용한다.
- **출력:** 편집된 화면, 테마가 바뀐 화면
- **사용 테이블:** 없음
- **비고:** 카드 편집은 개발·시연용이다. 테마 전환만 필요하면 P3.

#### N-10 로그인 화면 홍보 그래프 — P3
- **설명:** 로그인 화면에서 대안 신용평가를 적용하기 전과 후의 점수와 12개월 추이 예시를 보여 준다.
- **입력:** 없음
- **처리:** 고정된 예시 시나리오를 그래프로 그린다.
- **출력:** 전후 점수 카드, 12개월 추이 그래프 2개, 광고용 예시 안내 문구
- **사용 테이블:** 없음(고정 예시 데이터)
- **비고:** UI 구현됨. 예시 값은 640점(Caution)과 778점(Standard).

### 신용평가

#### N-12 나의 신용 리포트 — P0
- **설명:** 기존 방식과 대안 방식의 점수를 나란히 비교해 보여 준다. 프로젝트의 핵심 주장을 보여 주는 화면이다.
- **입력:** 사용자 입력 데이터, CB 프로필
- **처리:** 기존 방식과 대안 방식으로 각각 평가해 점수와 등급을 저장하고, 점수 차이와 등급 변화를 계산한다. **대안 점수가 더 낮은 경우도 숨기지 않고 그대로 보여 준다.**
- **출력:** 두 점수, 등급, 부도 확률, 점수 차이, 등급 변화
- **사용 테이블:** assessment, score_grade_band, user_credit_profile

#### N-13 동일 직군 대비 백분위 — P1

- **입력:** 내 점수, 직군
- **처리:** 같은 직군의 점수 분포에서 백분위를 계산한다. 표본이 적으면 안내 문구를 붙인다.

- **사용 테이블:** assessment, app_user

#### N-14 영역별 영향도(SHAP) — P0
- **설명:** 점수를 올리고 내린 항목을 보여 주고 개선 미션(시뮬레이터)으로 연결한다.
- **입력:** 평가 1건
- **처리:** 항목별 SHAP 점수를 정렬해 증감이 큰 항목을 뽑는다.
- **출력:** 항목명, 증감 점수, 개선 미션 바로가기
- **사용 테이블:** assessment_factor
- **비고:** 신용점수 회복 방안은 N-23 시뮬레이터와 연결한다.
- **메모:** SHAP는 예측 해석 후 화면에 표시 없이 전달
- ⚠️ 메모와 출력 항목의 해석이 엇갈림 → D-11

#### N-15 동년배 비교 — P1

- **입력:** 내 연령대, 소득, 자산, 부채
- **처리:** 공공통계의 같은 연령대 평균과 내 값을 비교한다.

#### N-16 자산·부채 건전성 (스마트 가계부) — P0
- **설명:** 자산 대비 부채 비율을 진단하고, 총자산·연소득·총부채를 슬라이더로 바꿔 보면 비율과 위험 단계가 바로 다시 계산된다. 보유 대출 목록도 함께 보여 준다.
- **입력:** 총자산, 연소득, 총부채(슬라이더 또는 직접 입력). 저장된 대출 목록
- **처리:** 순자산, 상환 부담률, 자산 대비 부채, 순자산 대비 부채 비율을 계산하고 안전·주의·위험 단계를 나눈다. 값이 바뀌면 비율과 배지를 다시 계산하고, 내 실제 값으로 되돌릴 수 있다. 대출은 저장된 값을 조회한다.
- **출력:** 총자산·총부채·순자산 요약, 비율 막대, 위험 배지, 보유 대출 표(종류, 잔액, 금리, 고정·변동, 남은 기간, 월 원리금)
- **사용 테이블:** user_asset_snapshot, user_income_month, user_loan, dim_loan_type
- **비고:** 대출 목록 표만 P2로 나눠도 된다.

#### N-17 시나리오 시뮬레이터 (금리·소득 스트레스) — P1
- **설명:** 금리 변동이나 소득 변동 등의 요인들로 인한 변화를 예측해 준다.
- **입력:** 시나리오(금리 증감, 소득 증감)
- **처리:** 시나리오를 반영해 월 잉여와 상환 부담률을 다시 계산한다. N-18, N-21과 계산 구조를 공유한다.
- **출력:** 월 잉여, 상환 부담률, 추가 이자
- **사용 테이블:** user_loan, user_income_month, fact_policy_rate
- **비고:** 점수 변화를 예측하는 기능은 N-21이고, 이 기능은 상환 여력을 본다.

#### N-18 점수·금리 시뮬레이터 → 신용케어 시뮬레이터, 행동 예측형 신용·한도 분석기 — P1
- **설명:** 납부·이용 행동을 바꾸면 점수가 어떻게 달라지는지, 그 점수대의 대출 금리와 한도가 어떤지 보여 준다.
- **입력:** 슬라이더 5개: 통신비 정시 납부 기간, 최근 1년 연체 횟수, 현금서비스 이용 기간, 최근 3개월 신규 대출 건수, 간편결제 월 이용 건수. 금액 입력 4개: 카드 한도, 월 카드 사용액, 대출 잔액, 대부업 대출 잔액
- **처리:** 예상 점수 계산하기 버튼을 누르면 점수를 다시 계산한다. 변화를 모형 재계산분과 대안 데이터 가점으로 나누고, 등급 변화와 부도 확률 변화를 계산한다. 같은 점수대의 금리와 한도를 조회한다. 내 실제 값으로 되돌리기 버튼으로 처음 값으로 돌아간다.
- **출력:** 현재와 변경 후 점수, 모형 재계산분, 대안 데이터 가점, 등급 변화, 부도 확률 변화, 예상 금리, 예상 한도
- **사용 테이블:** user_telecom_payment, user_easypay_usage, user_credit_profile, user_loan, assessment, assessment_factor, score_band_offer
- **비고:** 금리와 한도는 상품 권유가 아니라 같은 점수대 차주의 제시 이력을 보여 주는 참고 정보임을 표시한다.
- **메모:** 대출과 관련된 추천 기능으로 활용해 보자. ex) 대출 상품 안내 등 / 설명, 처리 수정
- ⚠️ 메모(상품 안내)와 비고(상품 권유 아님)가 충돌 → D-12

#### N-19 금융 이력·자산 이력 알림 — P3
- **설명:** 저번 달에 비해서 부족하면 팝업 알림을 띄운다.
- **입력:** 이번 달과 지난달 데이터
- **처리:** 두 달 값을 비교해 기준에 못 미치면 알림을 만든다.
- **출력:** 팝업 알림
- **사용 테이블:** user_income_month
- **비고:** 지난달 데이터를 저장해야 한다. 현재 DB는 기준월이 하나라 설계 변경이 필요하다.

#### N-20 DSR 계산기 — P1
- **설명:** 연소득 대비 부채상환비율을 계산한다. 직군마다 입력 항목이 다르다.
- **입력:** 연소득과 대출 원리금. 근로소득자: 재직기간, 월소득, 기존 부채. 자영업자: 월평균 매출, 사업장 업종, 공과금 납부율. 프리랜서: 최근 소득 변동폭, 프로젝트 주기성
- **처리:** 연간 원리금 상환액을 연소득으로 나눠 DSR을 계산한다. DSR은 1년 동안 번 돈 중 빚(원금+이자) 상환에 들어간 비율이다.
- **출력:** DSR, 위험 단계
- **사용 테이블:** user_loan, user_income_month
- **비고:** 화면의 상환 부담률(N-16)과 같은 계산을 쓰므로 함수를 공유한다.

#### N-21 소득·지출 변화 점수 예측 (전 현금흐름 시뮬레이터) — P1
- **설명:** 월 소득이나 지출, 정기 납부 성실도가 바뀔 때 대안 점수가 어떻게 달라질지 예측한다.
- **입력:** 월 소득 변동률, 월 생활비, 정기 납부 성실도, 예측 기간(3·6·12개월), 기타 지출 항목(종류, 내용, 월 금액)을 추가·삭제
- **처리:** 소득과 지출을 기간별로 전망해 가장 나쁜 달과 순현금을 계산한다. 최근 12개월 실적 뒤에 전망 기간을 이어 그린다. 예상 점수 계산하기 버튼을 누르면 예상 대안 점수를 다시 구한다. 간편결제 이용 내역은 보류 행으로 표시하고 합계에서 뺀다.
- **출력:** 월 지출 합계, 월 원리금, 전망 순현금, 가장 나쁜 달, 12개월 후 점수(점선), 최근 12개월 적자 개월 수, 성수기·비수기 소득 격차
- **사용 테이블:** user_income_month, user_asset_snapshot, user_expense_item, user_easypay_usage, assessment
- **비고:** 옛 이름은 현금흐름 시뮬레이터. 비금융 정보(통신·간편결제 등)가 바뀌는 경우는 N-18에서 다룬다.

#### N-23 가산점 현황 카드 — P1
- **분류:** 신용평가(공통)
- **설명:** 변수별로 가산점을 더 받으려면 무엇이 필요한지 보여 준다.
- **입력:** 평가 1건
- **처리:** 변수별 가산 여부를 계산해 부족한 항목의 확보 방법을 안내한다.
- **출력:** 가산점 카드
- **사용 테이블:** assessment_factor
- **비고:** 이력이 짧은 사람에게 불리한 기준이 되지 않게 정해야 한다. 소득 안정성 지표로 바꾸는 방안이 있다.

### 직군별

#### N-22 소득 변동성 진단 (자영업자·프리랜서) — P0
- **설명:** 월별 수입 편차를 보여 주고 비수기를 미리 경고한다.
- **입력:** 최근 12개월 소득, 월 고정지출
- **처리:** 12개월 평균과 중앙값, 가장 낮은 달 대비 고정지출, 소득 0원인 달 수, 최근 3개월 대비 12개월 평균을 계산한다. **12개월을 모두 입력하지 않았으면 입력 부족으로 표시하고 감점하지 않는다.**
- **출력:** 월별 소득 차트, 변동성 지표, 비수기 경고
- **사용 테이블:** user_income_month, user_asset_snapshot
- **비고:** 프리랜서 대표 기능. 성수기·비수기 소득 격차는 N-21과 같은 계산을 쓴다.

#### N-24 상권 분석 (차트·지도) (자영업자) — P1
- **설명:** 내 상권의 폐업률과 매출을 분석하고, 지도 히트맵으로도 보여 준다. 차트를 먼저 만들고 지도를 얹는다.
- **입력:** 행정동, 업종
- **처리:** 최근 4분기 매출 추세, 점포 수, 폐업률을 같은 행정동과 업종에서 조회한다. 비공개 처리된 칸은 자료 없음으로 표시한다. 지도에서는 행정동 경계 위에 매출과 폐업률을 색으로 표시한다.
- **출력:** 매출 추세와 경쟁 밀집도 요약(차트), 상권 히트맵(지도)
- **사용 테이블:** fact_dong_sales, fact_dong_store, dim_adm_dong, dim_service_category
- **비고:** 차트는 P1, 지도 히트맵만 P2. 지도 API와 행정동 경계 데이터가 필요하다.

### 관리자

#### N-25 모형 성능 비교 — P0
- **설명:** 기존 모형과 대안 모형의 성능을 고객 집단별로 비교한다. 컷오프를 바꾸면 지표가 다시 계산되고 ROC 곡선으로도 비교한다.
- **입력:** 비교할 고객 집단(전체, 금융 이력 부족 등), 점수 컷오프(슬라이더)
- **처리:** 컷오프 미만은 부도로 예측해 지표를 다시 계산한다. AUC, 승인률, 오분류율과 직군별 우량 고객 오거절률을 계산하고 두 모형의 ROC 곡선과 AUC를 그린다.
- **출력:** 비교 표(ROC-AUC, 정확도, 오분류 비용, 우량 고객 오거절률, 부도 고객 오승인률, 승인률, 등급 분포), ROC 곡선
- **사용 테이블:** assessment, score_grade_band
- **비고:** 오거절률이 있어야 가혹하지 않은 평가라는 주장을 검증할 수 있다. **개선이 없는 집단도 숨기지 않고 보여 준다.**

#### N-26 직군·연령별 통계 — P0
- **설명:** 직군별 또는 연령대별로 소득, 상환 부담, 현금흐름, 대안 데이터 이용 현황을 비교한다.
- **입력:** 구분(직군별, 연령대별), 비교 지표, 연령대
- **처리:** 선택한 지표로 요약 수치, 상자 그림, 직군×연령대 히트맵, 통계 표, 직군별 대안 신용점수·등급 표를 만든다.
- **출력:** 전체 고객 수(12,000명), 중위 연소득, 상환 부담률, 소득 20% 감소 시 적자 비율, 통신비 연체 경험 등 요약과 차트, 표
- **사용 테이블:** assessment, app_user, user_income_month
- **비고:** 직군은 근로소득자, 사업소득자, 인적용역 소득자(프리랜서), 기타 소득자로 나눈다.
- ⚠️ 직군은 3분류(급여소득자·자영업자·프리랜서)로 확정 → decisions.md. 이 4분류 문구는 쓰지 않는다

#### N-27 관리자 계정·권한 관리 — P0
- **설명:** 회원 계정을 조회·잠그고, 관리자 계정을 추가하며, 역할에 따라 볼 수 있는 화면과 변경 권한을 나눈다.
- **입력:** 회원 검색어, 계정, 역할, 잠금 사유, 새 관리자의 아이디·이름·업무 이메일·역할
- **처리:** 계정 목록(역할, 상태, 2단계 인증 여부, 최근 로그인)을 조회한다. 잠글 때 사유를 남기고 역할 변경을 반영한다. 역할(최고 관리자, 리스크 관리자, 조회 전용, 일반 사용자)별로 접근을 제한한다. 관리자 추가 시 계정을 만들고 초대한다(시연에서는 초대 메일을 보내지 않는다).
- **출력:** 계정 목록, 처리 결과, 역할별 화면, 추가된 계정
- **사용 테이블:** app_user, 신규 테이블(역할·권한)
- **비고:** 권한 체계(U-21)와 관리자 추가(U-23)가 P0, 회원 정지·잠금(F-18, U-20)은 P3. 구현 범위를 나눌 때 이 기준을 쓴다.
- ⚠️ 역할은 `ROLE_USER`·`ROLE_ADMIN` 2개로 확정 → decisions.md. 위 4역할 문구는 쓰지 않는다

#### N-28 접근·시스템 로그 — P4
- **설명:** 인증, 정보, 경고 로그를 시간순으로 보여 준다.
- **입력:** 없음
- **처리:** 로그를 조회한다.
- **출력:** 시간, 구분(AUTH, INFO, WARN), 내용
- **사용 테이블:** 신규 테이블(로그)
- **비고:** UI 구현됨. 예: 관리자 로그인 2단계 인증 통과, 배치 스코어링 완료, 로그인 실패 횟수.

#### N-34 신고 접수 게시판 (관리자 전용) — P2
- **설명:** 관리자만 볼 수 있는 화면에서 접수된 신고를 목록으로 확인하고 처리한다. 일반 사용자는 이 화면에 접근할 수 없다.
- **입력:** 상태(접수, 검토 중, 처리 완료, 반려)·사유·기간 필터, 처리할 신고 선택, 처리 결과(숨김 유지, 삭제, 반려), 처리 메모
- **처리:** 관리자 역할인지 확인한 뒤에만 목록을 보여 준다. 같은 대상의 신고를 묶어 누적 건수와 사유별 건수를 계산한다. 처리 결과를 저장할 때 처리자와 처리 시각을 남기고, 숨김 유지나 삭제는 게시글에 반영하며 반려는 숨김을 해제한다. 신고자는 마스킹해서 보여 준다.
- **출력:** 신고 목록(접수 시각, 대상 글, 사유, 누적 신고 건수, 상태), 신고 상세(원문, 사유별 건수, 마스킹된 신고자), 처리 결과 안내
- **사용 테이블:** 신규 테이블(신고 접수), 게시판 테이블(N-06), app_user

### 언어·AI 서비스

#### N-29 다국어 지원 — P3
- **설명:** 여러 언어로 화면을 보여 준다.
- **입력:** 언어 선택
- **처리:** 문구를 언어별로 바꾼다.
- **출력:** 번역된 화면
- **사용 테이블:** 제외
- **비고:** 범위 밖이다. 해외 데이터 연계도 제외한다. 한다면 영어부터.

#### N-30 쉬운 금융사전 — P2
- **설명:** 툴팁을 누르면 금융 용어가 직관적이고 이해하기 쉬운 말로 바뀐다.
- **입력:** 버튼 선택
- **처리:** 용어 사전으로 단어를 바꿔 보여 준다.
- **출력:** 쉬운 말로 바뀐 화면
- **사용 테이블:** 용어 사전 테이블 필요
- **비고:** 용어에 마우스를 올리면 뜻이 나오는 툴팁으로 대체할 수 있다.

#### N-31 AI 요약 서비스 — P2
- **설명:** 리포트 내용을 쉬운 말로 요약한다.
- **입력:** 평가 결과, 영향 요인 상위 항목
- **처리:** **계산된 숫자만 AI에 넘겨** 3문장 이내로 요약하고, 결과를 저장해 다시 쓴다.
- **출력:** 요약 문장
- **사용 테이블:** assessment, assessment_factor
- **비고:** 템플릿 문장으로 먼저 만들고 AI 요약으로 바꾼다.

#### N-32 금융 용어 검색·질문 챗봇 — P2
- **설명:** 어려운 금융 용어나 질문을 입력하면 의미와 관련 내용을 쉽게 설명한다.
- **입력:** 금융 용어 또는 질문
- **처리:** 용어 사전과 AI로 설명을 만든다. 질문 버튼 방식으로 먼저 만들고, 무료 AI 한도에 맞춰 호출 횟수를 제한한다.
- **출력:** 용어 설명
- **사용 테이블:** 용어 사전 테이블 필요
