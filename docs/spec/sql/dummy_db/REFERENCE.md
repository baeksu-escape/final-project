# 더미 시드 참고

이 문서는 초기 설정 이후 필요한 원천·시드 규칙만 정리한다. 서비스 회원 데이터는 합성 데이터이며 실제 심사 기준이 아니다.

## 개인정보 암호화 (N-02-4)

- 저장값은 UTF-8 원문을 AES-256-GCM으로 암호화한다. 값마다 12바이트 난수 IV를 쓰고, `v1:` 뒤에 Base64(`IV + 암호문 + 16바이트 인증 태그`)를 둔다.
- 검색용 값은 별도 키의 HMAC-SHA256(64자 소문자 16진수)이다. 이메일은 앞뒤 공백 제거 후 소문자, 휴대폰은 ASCII 숫자만 남겨 정규화한다.
- AES·HMAC 키와 시연 비밀번호는 저장소 밖의 팀 보안 경로로 관리한다. 원문·키를 SQL이나 로그에 남기지 않는다.

## 대출 없음·자산 미입력 (N-05, O-15 A안)

- `TOTAL_ASSET_AMT = NULL`은 자산 미입력, `0`은 확인된 자산 0원이다.
- `NO_LOAN_YN`: `Y`는 사용자가 대출 없음 선택, `N`은 대출 있음, `NULL`은 미입력·미확인이다.
- 대출 없음 선택 시 자산 행이 없어도 `TOTAL_ASSET_AMT = NULL`, `NO_LOAN_YN = 'Y'`를 저장한다. 기존 자산 값은 보존한다. 대출 행이 삭제됐다는 이유만으로 `Y`로 바꾸지 않는다.
- 기존 DB에는 [변경 SQL](../alter_user_asset_snapshot_no_loan.sql)을 적용한다. 기존 행은 자동 보정되지 않는다.

## 납부 상태·카드 한도·점수대

- 납부 상태: `ON_TIME`은 기한 내 납부, `LATE`는 기한 후 납부, `UNPAID`는 기준일 현재 미납(납부일 NULL)이다.
- `CARD_LIMIT_AMT = (KC1000001 - L00000002) × 1000`원이며 반올림하지 않는다. 계산값이 없거나 음수면 NULL이다. 현재 보증 금액이 있으면 계산에서 함께 뺀다.
- 점수대 안내는 시연 가정이다: 은행 780점, 상호금융 665점, 카드·저축은행·캐피탈 0점부터 참고 범위에 포함한다. 실제 승인·심사 기준이 아니다.

## 키 생성과 파일 안전

- 팀 개발 키 파일은 저장소 밖에서 한 번 생성한다: `python docs/spec/sql/dummy_db/tools/gen_dev_keys.py "$env:USERPROFILE\avenue-secrets\avenue_dev.env"`. 키 값은 저장소·이슈·PR에 올리지 않는다.
- `build_db.py` 출력은 저장소의 `dummy_db` 폴더 또는 저장소 밖 OS 임시 폴더만 허용하며, 원천 폴더와 겹치면 안 된다.
- `00_drop_all.sql`은 첫 DROP 전에 옛 DB 표식(`APP_MEMBER`, `MEMBER_MONTHLY_INPUT`, `MEMBER_LOAN`, `EXTERNAL_API_RESPONSE`)이 있으면 오류로 중단한다. 그래도 별도 개발 스키마에서만 사용한다.
