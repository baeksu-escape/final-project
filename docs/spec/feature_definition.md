- v0.2 변경(11/13): 11/12 회의 결정에 따라 **신용평가사 API를 서비스에서 제외**한다(필요하면 나중에 추가). 서비스 모델은 화면 입력(UI 데이터 입력 화면)에 대응하는 피처만 쓴다. 이 결정은 `docs/ai/decisions.md`에 아직 기록되지 않았다.
- v0.3 변경(11/13): 데이터 담당 답변을 반영해 기존 모델 피처를 16개에서 19개로 늘렸다. 신용평가사 207열 중 화면 입력과 맞는 7개만 남기고 나머지는 보류(4장)한다.
- 기준: 학습 데이터 v3.6.1, DDL v0.3.2(`docs/spec/sql/avenue_ddl.sql`), 기능 명세 v3(`docs/ai/features.md`)
- 담당: B팀(대안 모형·SHAP·평가)
- 모든 값은 합성 데이터다. 아래 통계는 실제 분포가 아니라 이 패키지의 생성 결과이며, 점수·금리·한도는 실제 심사 결과가 아니다.

## 1. 개요

이 문서는 모델이 입력으로 쓰는 피처(열)의 이름, 뜻, 원천, 계산식, 단위, 0·결측 처리, 대안 데이터 여부를 정한다.
`DIM_FEATURE`(피처 코드·이름·단위·`ALTERNATIVE_YN`·`SIMULATABLE_YN`·표시 순서)와 `ASSESSMENT_FACTOR`(SHAP 요인)에 넣을 값의 근거가 된다.

| 구분 | 기존 집단 | 씬파일 집단 |
|---|---:|---:|
| 모델 표 열 수 | 252 | 261 |
| 모델 입력 피처(`role=feature`) | 235 | 243 |

위 표는 학습 데이터 묶음 전체의 열 수다. **서비스 모델이 실제로 쓰는 피처는 아래 두 모델이며, 대안 모델 기준 39개다.**

| 모델 | 구성 | 피처 수 |
|---|---|---:|
| 기존 모델 | 화면에서 받는 전통 신용평가 항목만 사용 (소득·지출·상환 9, 프로필 3, 신용 이력 7) — 3장 | 19 |
| 대안 모델 | 기존 모델 피처 + 대안 데이터 5종 — 3장 | 19 + 20 = 39 |

- 기존 모델은 "신용평가사의 기존 점수"가 아니라 **기존 신용평가에서 주로 쓰는 항목으로 만든 모델**이다. 두 모델의 점수를 비교하는 것이 서비스의 중심 기능이다.
- 대안 데이터 20개: 통신·공과금 3, 간편결제 4, 국민연금 6, 건강보험 6, `si_arrears_any` 1.
- 열 역할의 정본은 학습 데이터 묶음의 `1_model/model_table_columns.csv`다. 이 문서는 그 내용을 사람이 읽기 쉽게 풀어 쓴 것이다.
- 통계는 `1_model/legacy_model_table.csv`(기존 집단)와 `thinfile_model_table.csv`(씬파일 집단)에서 계산했다. 데이터가 다시 생성되면 숫자를 갱신한다.

## 2. 열의 역할

| 역할 | 열 | 모델 입력 |
|---|---|---|
| `feature` | 3장의 열(서비스 모델이 쓰는 39개). 4–5장의 열은 보류 | 3장은 예, 4–5장은 지금 서비스에서는 아니오 |
| `label` | `label_nonfin_effect_12m`(대안 점수 모형의 정답), `label_any_delinquency_12m`(발표용 대조) | 아니오 |
| `id` / `group` / `split` | `customer_id`, `dataset`, `cohort`, `data_split` | 아니오 |
| `compatibility_only` | 6개월 집계 11열(`income_6m_krw` 등) | 아니오(보존·참고용) |
| `eval_only` | `eval_future_credit_exposure`(씬파일) | 아니오(씬파일 학습·평가 대상을 거르는 데만 사용) |

## 3. 서비스 모델 피처 (기존 모델 + 대안 모델)

회원이 화면에서 직접 입력하거나 대안 데이터 API(통신·공과금·간편결제·국민연금·건강보험, 더미)로 받는 값에서 만들어지는 피처다.
`통계`는 기존 집단 12,000행 기준이다. 결측 수는 괄호 안에 적었다.

| 소절 | 내용 | 기존 모델 | 대안 모델 | 피처 수 |
|---|---|:---:|:---:|---:|
| 3-1 | 소득·지출·상환 (12개월, 서비스 정의) | 예 | 예 | 9 |
| 3-2 | 납부 이력: 통신·공과금 | 아니오 | 예 | 3 |
| 3-3 | 간편결제 | 아니오 | 예 | 4 |
| 3-4 | 국민연금·건강보험 | 아니오 | 예 | 13 |
| 3-5 | 프로필 | 예 | 예 | 3 |
| 3-6 | 신용 이력(화면 입력과 대응하는 207열 7개) | 예 | 예 | 7 |

- 3-5의 `debt_balance_krw`는 기존 모델 피처이고, 3-5의 `segment`, `age`도 기존 모델 피처다.
- 기존 모델 합계: 3-1(9) + 3-5(3) + 3-6(7) = 19. 대안 모델 합계: 19 + 3-2(3) + 3-3(4) + 3-4(13) = 39.
- 3-4의 13개는 국민연금 6 + 건강보험 6 + `si_arrears_any` 1이다.

### 3-1. 소득·지출·상환 (12개월, 서비스 정의)

원천: 회원 입력. 소득은 12개월 월별 입력(급여소득자는 기준월 1개월 값 × 12), 지출은 평균 월 지출 1개, 상환은 현재 월 상환액 1개.
기준월은 원천 마지막 달인 2026-08이며, 급여소득자 기준월은 팀 확인 전 임시값이다.

| 피처 코드 | 뜻·계산식 | 단위 | 통계 (최솟값 / 중앙값 / 최댓값) |
|---|---|---|---|
| `income_svc_12m_krw` | 12개월 소득 합계 | 원 | 1,053,084 / 37,087,830 / 145,743,804,000 (결측 120) |
| `income_cv_svc_12m` | 12개월 월소득의 표준편차 ÷ 평균 | 소수 | 0 / 0 / 1.214 (0인 행 9,410) |
| `zero_income_months_svc_12m` | 12개월 중 월소득이 0인 달 수 | 개월 | 0 / 0 / 4 |
| `expense_avg_month_krw` | 평균 월 생활지출 (정확히 .5이면 올림, `ROUND_HALF_UP`) | 원 | 212,743 / 1,505,780 / 8,029,802,000 (결측 120) |
| `debt_service_current_krw` | 현재 월 상환액(기준월 상환액) | 원 | -8,316,666 / 548,667 / 71,726,583 (결측 120, 0인 행 1,088) |
| `expense_ratio_svc_12m` | 평균 월 지출 × 12 ÷ 12개월 소득 합계 | 소수 | 0.022 / 0.532 / 3.033 |
| `dsr_svc_12m` | 현재 월 상환액 × 12 ÷ 12개월 소득 합계 (소득이 0이면 값을 만들지 않음) | 소수 | 0 / 0.163 / 21.53 |
| `deficit_months_svc_12m` | 12개월 중 (월 소득 − 평균 월 지출 − 현재 월 상환액) < 0인 달 수 | 개월 | 0 / 0 / 12 |
| `worst_month_net_cash_svc_12m_krw` | 12개월 중 가장 낮은 달의 (월 소득 − 평균 월 지출 − 현재 월 상환액) | 원 | -55,666,388 / 309,047 / 25,555,978 |

- `ALTERNATIVE_YN` 제안: 아니오. `SIMULATABLE_YN` 제안: 아니오(금액 입력 4개와 다른 항목이다).
- 이 9열은 이상치 처리가 필요하다(7장). 소득 최댓값이 약 1,457억 원, 지출 최댓값이 약 80억 원, 상환액 최솟값이 음수인 것은 데이터에 주입된 이상치다.

### 3-2. 납부 이력 (대안 데이터: 통신·공과금)

| 피처 코드 | 뜻 | 단위 | 통계 |
|---|---|---|---|
| `telecom_late_months` | 12개월 중 통신비 미납 달 수 | 개월 | 0–5, 0인 행 93.2% |
| `utility_late_months` | 12개월 중 공과금(전기·가스·수도 합산) 미납 달 수 | 개월 | 0–5, 0인 행 93.7% |
| `telecom_on_time_streak` | 관측된 최근 12개월 창 내 연속 정시 납부 개월 수 | 개월 | 0–12, 중앙값 12 |

- 설정 범위는 0–12이지만 생성된 미납 달 수는 0–5까지다.
- `ALTERNATIVE_YN` 제안: 예(3개 모두).

### 3-4. 국민연금·건강보험 (대안 데이터)

국민연금(`np_`)과 건강보험(`hi_`)은 같은 구조의 열을 가진다.

| 피처 코드 | 뜻 | 단위 | 값·통계 (국민연금 / 건강보험) |
|---|---|---|---|
| `np_coverage_status` / `hi_coverage_status` | 적용 상태 | 코드 | 국민연금: `covered` 9,026 / `not_covered` 2,430 / `exempt`(납부예외) 544. 건강보험: `covered` 11,508 / `dependent`(피부양) 368 / `not_covered` 124 |
| `np_payer_type` / `hi_payer_type` | 가입 유형 | 코드 | 국민연금: `workplace` 7,616 / `regional` 1,954 / `unknown` 2,430. 건강보험: `workplace` 9,280 / `regional` 2,228 / `household` 368 / `unknown` 124 |
| `np_due_months` / `hi_due_months` | 납부 의무가 있고 기한이 지난 달 수 | 개월 | 0–12 (납부 대상이 아닌 행: 국민연금 2,974, 건강보험 492) |
| `np_on_time_months` / `hi_on_time_months` | 기한 내 납부한 달 수 | 개월 | 0–12 |
| `np_arrears_months` / `hi_arrears_months` | 정시가 아닌 달 수 | 개월 | 0–12, 중앙값 0 |
| `np_on_time_rate` / `hi_on_time_rate` | 정시 납부율 | 소수 | 0–1. **납부 의무 달 수가 0이면 결측**: 국민연금 2,974(24.8%), 건강보험 492(4.1%) |
| `si_arrears_any` | 국민연금 또는 건강보험 비정시 1개월 이상 | 0/1 | 1이 18.8% |

- 납부예외·피부양·미적용 달은 고지액이 0이고 `payment_status=not_applicable`이다. 그래서 `*_on_time_rate`의 결측은 "정보 없음"이 아니라 "계산 대상 아님"이다. 모델에 넣을 때 0으로 채우지 않는다(7장).
- `ALTERNATIVE_YN` 제안: 예(14개 모두 + `si_arrears_any`). `SIMULATABLE_YN` 제안: 아니오.
- 국민연금·건강보험 열람의 감사 기록 포함 여부는 팀 결정 사항이다.

### 3-5. 프로필

| 피처 코드 | 뜻 | 단위 | 통계 |
|---|---|---|---|
| `segment` | 직군. `HAC_CD` 1/2/7을 `wage` / `selfemp` / `freelance`로 연결 | 코드 | `wage` 9,410 / `selfemp` 1,738 / `freelance` 852 |
| `age` | 연령(가정 연령). 신용거래 기간과 성인 시작 조건으로 하한 보정 | 세 | 20 / 48 / 69 |
| `debt_balance_krw` | 미상환 대출 총금액. 학습 데이터에서는 `L00000002` × 1,000으로 만들었고, 서비스에서는 화면에서 입력한 대출 목록의 잔액 합계를 쓴다 | 원 | 0 / 21,812,000 / 837,363,000 (0인 행 1,101) |

- 서비스 직군 코드와의 연결: `wage` ↔ `EMPLOYEE`, `selfemp` ↔ `SELF_EMPLOYED`, `freelance` ↔ `FREELANCER`.
- 나이는 연 나이인지 만 나이인지 서비스 표현이 정해지지 않았다(9장).
- `ALTERNATIVE_YN`: 모두 아니오. `SIMULATABLE_YN` 제안: `debt_balance_krw`는 예(대출 잔액 입력과 연결).

### 3-6. 신용 이력 (화면 입력과 대응하는 207열 7개)

학습 데이터의 신용평가사 207열 중 화면 입력과 가장 가까운 7개다. 학습 데이터에서는 신용평가사 값이지만, 서비스에서는 **회원이 화면에 입력한 값**을 같은 뜻으로 보고 모델에 넣는다. 정의가 완전히 같지는 않다(아래 "대응 정도").
기존 집단 12,000행 기준이며, 결측은 7개 모두 없다.

| 피처 코드 | 학습 데이터에서의 뜻 | 화면 입력 | 단위 | 통계 | 대응 정도 |
|---|---|---|---|---|---|

| `CF1231605` | 12개월 주사용 신용카드의 최근 12개월 현금서비스 사용 개월 수(15일 기준) | 현금서비스 이용(최근 12개월 중 개월 수) | 개월 | 0–10, 중앙값 1, 0인 행 4,209 | 대용치. 주사용 카드 기준이라 전체 카드 기준과 동일하지 않다 |
| `L22000900` | 최근 3개월(90일) 내 개설한 현재 미상환 대출 건수 | 최근 3개월 신규 대출 | 건 | 0–4, 중앙값 0, 0인 행 8,313 | 중간. 화면 문구를 "최근 3개월 신규 대출 중 상환 중인 건"으로 좁힌다(UI 담당 확인) |

## 7. 전처리 규칙

1. **0과 결측을 구분한다.** 0은 유효한 값(예: 미납 0개월, 대출 0건)이다. 결측(null)을 0으로 채우지 않는다.
2. **구조적 결측.** `np_on_time_rate`, `hi_on_time_rate`는 납부 의무 달 수(`*_due_months`)가 0이면 정시 납부율을 계산할 대상이 없어 NULL이다(데이터 담당 확인, 기존 집단 12,000행에서 국민연금 2,974행·건강보험 492행이 `due_months=0`과 일치). 0%나 100%로 단정하지 않는다. 데이터 담당 권고: 결측을 직접 처리하는 모델과 결측 지시 열을 함께 쓰는 보정을 비교한다. 중앙값 보정은 두 비율의 중앙값이 1.0이라 100%로 채워지므로 주의한다. 국민연금은 `np_coverage_status`가 이미 있어 별도 지시 열이 필요한지 확인한다. 최종 방식은 B팀 결정(미정).
3. **주입된 결측.** `income_svc_12m_krw`, `expense_avg_month_krw`, `debt_service_current_krw`는 기존 집단에서 각각 120행(1.0%) 결측이다. 데이터 담당 확인: 파생 열(`income_cv_svc_12m`, `expense_ratio_svc_12m`, `dsr_svc_12m`, `deficit_months_svc_12m`, `worst_month_net_cash_svc_12m_krw`)을 **먼저 만들고** 세 입력 열에 시연용 결측·이상치를 주입했다. 그래서 파생 열은 주입 전 값이고 결측이 없으며, 입력 열과 값이 어긋날 수 있다. CV·소득 0인 달 수·부족 달 수·최악 월 현금흐름은 월별 원천이 있어야 재계산되며 세 입력 열만으로는 만들 수 없다.
4. **이상치.** 소득·지출은 0.5%에 1,000배, 상환액은 0.3%에 음수가 주입되어 있다(`anomaly_log_12m_svc.csv`). 이 기록은 전처리 평가용 정답지이며 학습·모델 입력에 쓰지 않고, 서비스 추론에는 이 기록이 없다. 데이터 담당 권고: 입력 검증 기준으로 잘못된 값을 결측 처리하고, 학습 분할에서만 정한 보정 규칙을 평가·추론에도 같게 적용한다. DDL은 소득·지출·월 상환액의 음수를 금지한다. 큰 소득을 이상으로 보는 업무상 상한과 Spring 검증 구현은 확인되지 않았다. 최종 방식은 B팀 결정(미정).
5. **급여소득자 소득.** 기준월 소득 × 12로 펼친다. 이때 `income_cv_svc_12m`은 0, `zero_income_months_svc_12m`은 0이 된다(기존 집단 9,410행이 0).
6. **금액 단위.** 학습 데이터의 신용평가사 값은 천원, 서비스 입력과 DB는 원이다. `LA0099212`는 학습값에 1,000을 곱해 원 단위로 통일하고, 학습·추론 양쪽 단위를 동일하게 관리한다(데이터 담당 확인). `LRZ021201`(천원/년)도 같은 방식으로 통일한다. `debt_balance_krw`는 학습 데이터에서 `L00000002` × 1,000으로 만들었다.
7. **학습·평가 구분.** `data_split`(TRAIN/VALID/TEST = 70/15/15, 고객 ID 단위, 직군 × 연체 라벨 층화)으로 나누고, 성능 비교는 TEST만 쓴다.

### 8-3. 입력 화면과 피처의 대응

- 소득 입력: 급여소득자는 월급 1칸, 자영업자·프리랜서는 12칸 → 3-1의 9개 열을 만든다.
- 대안 데이터 5종(통신·공과금·간편결제·국민연금·건강보험)은 모두 동의해야 다음 화면으로 넘어간다. 동의 없이는 해당 피처가 만들어지지 않는다.
- 12개월 월 입력이 덜 찬 회원은 점수를 산출하지 않는다(`NOT_SCORABLE`, 학습 데이터에는 해당 사람이 없다).

## 11. DIM_FEATURE 입력용 표 (FS-V1 제안)

`DIM_FEATURE`(`FEATURE_SET_VERSION`, `FEATURE_CODE`, `FEATURE_NAME`, `UNIT_NAME`, `ALTERNATIVE_YN`, `SIMULATABLE_YN`, `DISPLAY_ORDER`)에 넣을 값이다. 피처 세트 버전은 `FS-V1`로 제안한다.
**코드·단위·`ALTERNATIVE_YN`은 위 정의를 따른다. 표시 이름, `SIMULATABLE_YN`, 표시 순서는 B팀의 제안이며 검토가 필요하다.** 표시 이름은 화면의 SHAP 요인 목록에 나타나므로 UI 담당 의견을 받는다.

- `FEATURE_CODE`는 학습 데이터의 열 이름 그대로 쓴다(`VARCHAR2(50)` 이내).
- 모델: 기존 = 기존 모델과 대안 모델 모두 사용, 대안 = 대안 모델만 사용.
- 문자 값(`segment`, `np_coverage_status` 등 코드형)은 숫자로 바꿔 모델에 넣는 방식을 학습 때 정한다(미정). `ASSESSMENT_FACTOR.FEATURE_VALUE`에는 문자열로 저장한다.
