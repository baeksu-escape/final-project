# 등급 경계 25/50/25 임시 결정 기록과 등급 구간 CUT-0.2(DRAFT) DB 기준 데이터 추가

- **날짜:** 2026-11-19
- **작성자:** 최재욱(B팀 모델·정의서 담당) / Claude Code
- **브랜치:** `feature-B/FP-139-grade-cutoff-draft` (Jira FP-139)
- **관련 N-ID:** N-04(등급 구간), N-12·N-18·N-25(등급 표시·비교)
- **관련 결정:** `decisions.md` D-01, 정의서 10장 C18·C24, 11/19 팀 임시 결정(점수 분포 25/50/25), 11/19 DDL·공용 md는 재욱 작업과 연계되면 직접 수정 가능

## 무엇을, 왜 바꿨나
- 11/19 팀이 등급 경계를 점수 분포 25% / 50% / 25%로 임시 결정했다. 이 결정과 경계 값을 기록하고, DB에 새 구간 버전을 넣어 두었다.
- 경계는 지금 서버 모델 파일로 C18 계산을 다시 해서 구했다. 기존 집단 VALID 1,800행의 대안 모델 점수 p25/p75 = 659 / 731이라 **CAUTION 0~659, STANDARD 660~730, GOOD 731~1000**이다(C18 제안과 같다). 기존·대안 모델은 같은 경계를 쓴다.
- **DRAFT로만 넣었다.** `CUT-0.2`는 DRAFT이고 ACTIVE는 계속 `CUT-0.1`(665·780)이다. 서비스·UI의 경계를 언제 바꿀지는 정의서에 "미정"이라 정하지 않았다(사용자 결정 11/19). 그래서 점수 저장, 화면, 대출 상품 기준이 달라지지 않는다.
- 이 경계의 VALID 비율(주의/보통/우수): 기존 집단 대안 모델 25.3/49.1/25.6%, 기존 모델 26.9/57.1/15.9%, 씬파일(노출 1, TRAIN+VALID) 대안 28.0/43.7/28.3%·기존 13.2/35.3/51.5%. 직군별(대안, VALID) 주의 비율은 급여소득자 23.1%, 자영업자 35.2%, 프리랜서 29.7%다.

## DB·API 변경
- DB: 구조 변경 없음. 기준 데이터만 늘었다(`SCORE_CUTOFF_VERSION` 1→2행, `SCORE_GRADE_BAND` 3→6행). `CUT-0.1` 행은 그대로.
- API: 없음. `GET`류 응답에서 ACTIVE 구간만 읽으므로 DRAFT 행이 보이지 않는다(`selectActiveGradeBand`는 ACTIVE 조인, `selectGradeBands`는 버전을 지정).
- 영향을 받는 기능·팀원: 이번 PR로는 없음. 서비스 전환 때 범영(FP-141 서비스, DB 적용), 광희(점수대별 금리·한도 FP-170), 프론트, A팀(등급 표시 mock)

## 확인
- 확인함: 새 시험 9개 포함 FastAPI 테스트 152개 통과, DB 도구 시험 52개 통과(건너뜀 3). DDL과 더미 DB 사본이 같고 `seed_report.json`의 `ddl_sha256`이 LF 정규화 DDL 해시와 같음. 경계 계산은 서버 모델 파일(`alternative.joblib`·`legacy.joblib`)과 학습 표로 다시 실행해 C18의 p5/p25/중앙값/p75/p95(590/659/697/731/778)와 같음.
- 확인 못 함: **Oracle에서 실행**(변경 SQL을 두 번 실행해 중복이 없는지, 빈 스키마에서 `avenue_ddl.sql`부터 `99_check.sql`까지 확인하는 일은 SQL Developer로 사용자가 해야 함), 공용 DB 적용(범영), 서비스 화면 영향(코드로 DRAFT 행이 쓰이지 않음을 확인했을 뿐 실행하지 않음).
