## 무엇을, 왜 바꿨나
- 서비스 DB의 기준 DDL을 `docs/spec/sql/avenue_ddl_v0.3.1.sql`(표 47개) 하나로 정했다. 옛 `dummy_db/` 14개 표(`APP_MEMBER` 계열)와 경환 v0.2(46개 표)를 대신한다.
- DB·데이터 관리자(범영)가 확정한 내용:
  - **A-1 점수 범위:** 0~1000
  - **U2:** 공과금 미납 개월 수는 `LATE`와 `UNPAID`를 모두 센다. 학습 데이터 `utility_late`와 같은 정의다.
  - **U3:** 상태와 납부일의 짝을 CHECK로 막는다.
  - **E2:** 암호문 앞에 `"v1:"` 키 버전 접두어를 붙인다. 우선 이대로 운영한다.
- 파일 내용은 SQL Developer에서 확인한 확정본과 바이트 단위로 같다(SHA256 `803f1f8f7e6ac6cfbee669bf81079fdb6fed5c9513b82bb4acb954f5ceb11b26`).

## DB·API 변경
- DB (경환 v0.2 `dummy_db/v0_2/01_create_tables.sql` 대비):
  - 표 추가: `USER_UTILITY_PAYMENT`. 공과금 청구·납부를 담고, 통신비 표와 같은 구조다.
  - 제약 추가: `CK_UTP_PAID_DATE`(통신비), `CK_UUP_PAID_DATE`(공과금). 규칙은 아래와 같다.
    - `ON_TIME`이면 납부일이 있고 기한 이전이다.
    - `LATE`이면 납부일이 있고 기한 이후다.
    - `UNPAID`이면 납부일이 없다(NULL).
  - 주석: 이름·휴대폰·이메일 암호문 형식 = `"v1:"` + Base64(IV 12바이트 + 암호문 + 태그 16바이트). HMAC은 접두어 없이 64자 소문자 16진수다.
  - 나머지 표·열·인덱스는 경환 v0.2와 같다(주석 제외 비교로 확인).
- API: 없음
- 영향을 받는 기능·팀원:
  - **경환 (시드 생성기 `build_db_v02.py`):**
    - 표 46개 고정 검사를 47개로 바꾼다.
    - 기관 응답의 "late + 납부일 없음"을 `UNPAID`로 바꿔 저장한다.
    - 암호문에 `v1:` 접두어를 붙인다.
    - 고치기 전의 옛 시드는 `CK_UTP_PAID_DATE`에서 거절된다.
  - **우찬 (Spring):** 가상 기관 납부 기록을 불러올 때 같은 `UNPAID` 변환이 필요하다. `v1:` 접두어를 보고 복호화한다.
  - **재욱 (피처 정의서):** `utility_late_months`를 "12개월 중 LATE 또는 UNPAID인 달 수(0~12)"로 정의한다.
  - **문서 담당자:** `decisions.md`의 점수 범위 "300~900"을 0~1000으로 맞춘다.

## 확인
- 확인함: 범영이 SQL Developer(Oracle 21c, 테스트 계정)에서 이 파일을 F5로 실행했다.
  - 표 47개, 인덱스 21개, 기준 데이터 25행이 만들어지고 커밋까지 오류가 없었다.
  - `SELECT COUNT(*) FROM USER_TABLES` = 47
  - `CK_UTP_PAID_DATE`, `CK_UUP_PAID_DATE`가 둘 다 있다.
  - CHECK 테스트: `UNPAID` + 납부일 없음은 저장된다. `LATE` + 납부일 없음은 `ORA-02290`으로 거절된다. 테스트 행은 ROLLBACK했다.
- 확인함: 저장소 파일과 확정본 원본의 SHA256이 같다.
- 확인 못 함:
  - 시드 적재: 생성기 수정 전이다.
  - Spring·MyBatis 연동: 백엔드 코드가 아직 없다.
