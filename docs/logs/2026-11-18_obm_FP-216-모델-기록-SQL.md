- **작성자:** 오범영 / Claude Code
- **브랜치:** `feature-B/FP-216-model-records` (Jira FP-216)
- **관련 N-ID:** N-25 모형 성능 비교, N-12-2 기존·대안 점수 계산·저장

## 무엇을, 왜 바꿨나
- 공용 DB를 실제 모델로 전환하기 전에, 그 모델이 **어떤 데이터로 학습됐고 어떤 파일인지** DB에 남긴다. `DATASET_VERSION`·`MODEL_ARTIFACT`가 지금 비어 있다.
- 11/18 결정: 학습 코드는 전처리를 메모리에서만 하고 정제 파일을 저장하지 않으므로, 실제로 있는 파일만 **RAW 1행**으로 기록한다(PROCESSED 행 없음, 전처리는 NOTE에 글로).
- 11/18 결정: `FILE_URI`에는 개인 PC 경로 대신 **디스코드 #파일공유 파일 이름**을 쓴다.

- DB: 구조 변경 없음. 기록 행 추가용 SQL만 추가(DDL·시드·`99_check.sql`은 바꾸지 않음)

## 확인
- 확인함:
  - 학습 표 `legacy_model_table.csv`(avenue_training_data_v3_6_1.zip)의 SHA-256을 직접 계산 → 두 모델 meta.json의 `data.table_sha256`(79511b5d…)과 같음. 행 12,000·열 252
  - 모델 파일 해시는 `fastapi_server/artifacts/SHA256SUMS.txt` 값(서버가 켜질 때 대조하는 값)
  - AUC_VALID = 서버에 올린 seed 11 모델의 검증 AUC(기존 0.6064, 대안 0.6565). meta.json `valid_auc.by_seed[0]`
  - SQL 안의 JSON 2개 파싱 OK, 해시 3개 모두 소문자 64자
  - **로컬 DB 실행(범영, SQL Developer F5):** DATASET_VERSION 1행(ID 1, RAW, 12,000·252, `79511b5d`), MODEL_ARTIFACT 2행(trad_legacy 0.6064 `c528d86e`, alt_legacy 0.6565 `f44af137`, 둘 다 학습 데이터 ID 1, AUC_TEST NULL). 두 번째 실행은 3행 모두 "이미 있음, 건너뜀"으로 오류 없음
- 확인 못 함: 공용 DB 실행(PR 병합 후 범영이 실행 예정)
