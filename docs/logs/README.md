# 작업 로그

여러 곳이 바뀐 작업을 **팀원 누구나, 그리고 AI도** 나중에 확인할 수 있게 남기는 기록이다.

## 언제 쓰나 (하나라도 해당하면 반드시)

- DB 관련 변경(테이블·컬럼·DDL) — 1건이라도
- API 경로나 요청·응답 필드 추가·변경
- 한 작업에서 백엔드 파일 3개 이상 변경
- 빌드·의존성 파일(`pom.xml`, `package.json`, `requirements.txt`)이나 공통 설정 변경

해당하지 않아도 남기고 싶으면 남겨도 된다.

## 어떻게 쓰나

- **작업 하나 = 파일 하나.** 한 파일에 이어 쓰면 브랜치를 합칠 때 충돌이 난다.
- 파일명: `YYYY-MM-DD_작성자_요약.md` (예: `2026-11-10_kim_N-12-리포트-API.md`)
- 양식: [_TEMPLATE.md](_TEMPLATE.md)를 복사해서 쓴다. 길게 쓰지 않는다.
- 기능 브랜치의 PR에 로그 파일을 함께 넣는다.
- 실제로 실행한 확인만 "확인함"에 적고, 못 한 것은 "확인 못 함"에 따로 적는다.

## 검수

검수는 아래 세 역할이 맡는다. 팀원은 로그를 읽고 문제가 보이면 Discord `#개발`에 알린다.

| 역할 | 하는 일 |
|------|---------|
| 문서 담당자 | 작업 전에 로그를 확인하고, 변경의 중요도·우선순위를 나눠 팀원의 작업물이 손상되지 않도록 조율한다 |
| 형상 관리자 (GitHub 관리) | 모든 PR은 반드시 형상 관리자의 확인을 거쳐 병합한다 |
| 조장 | 최종 작업물을 점검한다 |

- **최종 작업물은 이중 점검한다:** 조장 + (형상 관리자 또는 문서 담당자의 Claude 점검).
- 검수한 사람은 로그 맨 아래 **검수** 표에 이름·역할·날짜·의견을 한 줄 추가한다.

## AI가 지킬 것

- 작업을 시작하기 전에 최근 로그를 확인한다. 내가 건드릴 파일을 다른 사람이 최근에 바꿨다면 사용자에게 먼저 알린다.
- 위 조건에 해당하는 작업을 마치면 로그 파일을 만든다.
- 다른 사람의 로그 내용을 고치거나 지우지 않는다. 검수 칸에 대신 서명하지 않는다.
