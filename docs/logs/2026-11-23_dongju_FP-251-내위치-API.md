# N-13 비교 분석 '내 위치' API(RPT-05) 추가

- **날짜:** 2026-11-23
- **작성자:** 동주 / Claude Code
- **브랜치:** `feature-C/FP-251-scorePercentile` (Jira FP-251, develop `d735abc`에서 시작)
- **관련 N-ID:** N-13-1 저장 데이터 조회, N-13-2 같은 직군 점수 분포 조회, N-13-3 백분위 계산
- **관련 결정:** D-28(탈퇴 회원 평가 제외, N-26과 같은 기준)

## 무엇을, 왜 바꿨나
- 비교 분석 화면 '내 위치' 카드 3개에 쓸 API가 없었다(정의서 RPT-05 🟡 담당 미정). `GET /api/members/me/score-percentile`을 추가했다.
- 내 대안 점수가 같은 직군·연령대·직군+연령대 회원 안에서 상위 몇 %인지, 집단 평균과 차이가 얼마인지 돌려준다.
- 비교 대상은 관리자 통계(ADM-03, FP-161)와 숫자가 어긋나지 않게 같은 쿼리(`AdminStatsMapper`)를 불러 쓴다. 새 SQL은 없다.
- 화면(N-13-4)은 UI가 바뀌는 중이라 만들지 않았다.

## DB·API 변경
- DB: 없음 (`ASSESSMENT`, `APP_USER`, `MODEL_REGISTRY`를 읽기만 한다)
- API: RPT-05 추가. 정의서의 🟡 제안 경로 `/api/report/me/percentile`을 회원 데이터 규칙(`/api/members/me/**`)에 맞춰 `/api/members/me/score-percentile`로 바꿨다. 옛 경로는 구현된 적이 없어 쓰는 곳이 없다. 새 오류 code 없음(404 `ASSESSMENT_NOT_FOUND`는 RPT-02와 같은 코드).
- 영향을 받는 기능·팀원: 광희 님(FP-164 N-26-5~7이 같은 화면을 쓴다. `AdminStatsMapper`의 두 조회를 이 기능도 부르므로 조건을 바꾸면 '내 위치'도 바뀐다)

## 확인
- 확인함: `./mvnw test` 481개 통과(실패 0, 오류 0). 1등·꼴찌·동점, 반올림, 음수 차이, 4명·5명 경계, 세 집단 분리, 점수 없음·ACTIVE 모델 없음 404, 토큰 없음 401, 관리자 403.
- 확인함(11/23, 동주, 로컬 Oracle + 백엔드 실제 호출): 로그인 전 401 `UNAUTHORIZED`, `demo_employee` 로그인 뒤 200(내 점수 682, `LGBM-BASE-0.2`). 같은 직군·연령대에 임시 평가 4행(712·672·662·632점)을 넣고 다시 불러 세 집단 모두 인원 5, 상위 40%, 평균 672, 차이 10으로 손으로 계산한 값과 같았다.
- 확인 못 함: 실제 호출로 404·403과 표본 부족(null) 응답(시험 코드로만 확인), 회원 점수가 많이 쌓인 상태. 시드 `ASSESSMENT`가 0건이라 회원 점수를 산출해야 값이 나온다.

## 다음 사람이 알아야 할 것
- 상위 n% 식 `(나보다 높은 사람 수 + 1) ÷ 인원 × 100`은 명세 N-13-3에 없어 담당자가 정했다. 중앙값은 명세 제목에만 있고 처리·출력에 없어 넣지 않았다.
- 같은 집단에 ACTIVE 모델 점수를 낸 회원이 5명 미만이면 값이 null이다. 시연 전에 회원 점수를 미리 산출해 두어야 카드가 채워진다(FP-161·162 로그와 같은 내용, 한꺼번에 산출하는 도구는 아직 없다).
- 화면에서 막대 위 내 위치를 `100 − topPct`로 그리고 '평균' 눈금을 가운데(50%)에 고정하면, 점수가 한쪽으로 몰린 집단에서는 평균보다 높은데 눈금 왼쪽에 찍힐 수 있다.
- 정의서 1장은 고치지 않았다(새 오류 code 없음).
