# N-37 대출 상품 목록·상세·즐겨찾기 API와 화면 서버 연동 (LOAN-01~05)

- **관련 결정:** D-12 (더미 상품)

## 무엇을, 왜 바꿨나
- 화면 mock만 있던 대출 상품 API를 새 패키지 `com.baeksuescape.loan`에 구현했다. DB 시드 17종을 PRODUCT_ID 순 전체로 주고 필터·정렬은 화면이 한다.
- 상품 응답에는 내 점수·즐겨찾기 여부를 넣지 않는다(토큰 회원 저장 데이터를 읽는 API는 `/api/members/me/` 아래). 점수 조건 충족은 화면이 신용 리포트 점수로 계산하며, `minScore`가 null이면 조건 없음이다.
- 화면(`features/loans`)을 mock에서 실제 API로 전환했다. 상품 식별 키는 `productCode`, 즐겨찾기는 서버에 저장한다(sessionStorage 아님). 목록 필터는 주소 쿼리(`?filter=`)를 유지하고, 상세의 "목록으로"는 들어온 필터 목록으로 돌아간다.
- 백엔드는 모두 새 파일이라 기존 백엔드 파일을 수정하지 않았다. 공통 `AppRoutes.jsx`·`navigation.js`에는 대출 라우트만 추가했다. SIM-03(시뮬레이터 추천 API)은 이번에 만들지 않았다.

## DB·API 변경
- DB: 없음 (기존 LOAN_PRODUCT·LOAN_PRODUCT_WORKER_TYPE·LOAN_PRODUCT_FEATURE·LOAN_PRODUCT_FAVORITE 사용)
- API(신규):
  - `GET /api/loan-products` → `{ items: [상품] }`
  - `GET /api/loan-products/{productCode}` → 상품 1개
  - `GET /api/members/me/favorite-loan-products` → `{ items: ["LP001", ...] }` (최근에 담은 순)
  - `PUT`·`DELETE /api/members/me/favorite-loan-products/{productCode}` → 200 `{}` (멱등)
  - 상품 필드: productId, productCode, name, providerName, summary, description, eligibility, rateMinPct, rateMaxPct, limitAmount, minScore(null 가능), workerTypeCodes[], termText, repaymentMethod, requiredDocuments[], features[], cautionText, dummyYn(boolean)
  - 새 오류 code: 404 `PRODUCT_NOT_FOUND`
- 영향을 받는 기능·팀원: 프론트 `features/loans`(화면도 같은 모양으로 연결 완료). `summary`·`cautionText`·`dummyYn`은 화면 mock 이름 목록에 없던 추가 필드다. API 정의서 2-7·Q-9·SIM-03 반영은 `docs/spec/api/README.md` 2장대로 범영 님께 요청했다. 요청·응답 상세는 A팀 명세서(`api_spec_a.md`) 7장.

## 다음 사람이 알아야 할 것
- 즐겨찾기 INSERT는 `INSERT … SELECT … FROM DUAL WHERE NOT EXISTS`(Oracle 문법)이고 동시 중복은 `DuplicateKeyException`을 성공으로 처리한다. 11/19 로컬 Oracle에서 멱등 동작을 확인했다.
- REQUIRED_DOCUMENTS는 '·'로 나눈다. 서류 이름 안에 '·'가 있으면 쪼개진다(현재 시드에는 없음).
- 관리자가 더미 상품을 조회하는 것은 문제없다고 판단해 막지 않았다(`/api/loan-products/**`는 `/api/**` 로그인 규칙만 받는다, SecurityConfig 미수정).
- FP-90·91 mock 단계 기록(`2026-11-14` 로그)은 시뮬레이터 내용이 함께 있어 시뮬레이터(FP-91) PR에 넣는다.
