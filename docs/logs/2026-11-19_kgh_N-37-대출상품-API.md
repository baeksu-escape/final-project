- **브랜치:** `KGH_Work`

- **관련 결정:** D-12 (더미 상품)

## 무엇을, 왜 바꿨나
- 화면 mock만 있던 대출 상품 API를 새 패키지 `com.baeksuescape.loan`에 구현했다. DB 시드 17종을 PRODUCT_ID 순 전체로 주고 필터·정렬은 화면이 한다.
- 상품 응답에는 내 점수·즐겨찾기 여부를 넣지 않는다(토큰 회원 저장 데이터를 읽는 API는 `/api/members/me/` 아래). 점수 조건 충족은 화면이 신용 리포트 점수로 계산하며, `minScore`가 null이면 조건 없음이다.
- 기존 파일은 수정하지 않았다. SIM-03(시뮬레이터 추천 API)은 이번에 만들지 않았다.

## DB·API 변경
- DB: 없음 (기존 LOAN_PRODUCT·LOAN_PRODUCT_WORKER_TYPE·LOAN_PRODUCT_FEATURE·LOAN_PRODUCT_FAVORITE 사용)
- API(신규):
  - `GET /api/loan-products` → `{ items: [상품] }`
  - `GET /api/loan-products/{productCode}` → 상품 1개
  - `GET /api/members/me/favorite-loan-products` → `{ items: ["LP001", ...] }` (최근에 담은 순)
  - `PUT`·`DELETE /api/members/me/favorite-loan-products/{productCode}` → 200 `{}` (멱등)
  - 상품 필드: productId, productCode, name, providerName, summary, description, eligibility, rateMinPct, rateMaxPct, limitAmount, minScore(null 가능), workerTypeCodes[], termText, repaymentMethod, requiredDocuments[], features[], cautionText, dummyYn(boolean)
  - 새 오류 code: 404 `PRODUCT_NOT_FOUND`
- 영향을 받는 기능·팀원: 프론트 `features/loans`(claude2가 같은 모양으로 연결 중). `summary`·`cautionText`·`dummyYn`은 화면 mock 이름 목록에 없던 추가 필드다. API 정의서 2-7 갱신은 하지 않았다(나중).

## 확인
- 확인함: `mvnw.cmd -Dtest="Loan*Test" test` 16건 통과(서비스 10, API 계약 6). `mvnw.cmd test` 전체 342건 실패 0, BUILD SUCCESS.
- 확인 못 함: 실제 Oracle에서 LoanMapper.xml SQL 실행(테스트는 H2·mock이라 SQL은 검증되지 않았다. 매퍼 IT는 만들지 않았다). 프론트와의 실제 연동. `/api/loan-products/**`는 `/api/**` 로그인 필요 규칙을 따라 관리자 토큰도 통과한다(SecurityConfig 미수정).

## 다음 사람이 알아야 할 것
- 즐겨찾기 INSERT는 `INSERT … SELECT … FROM DUAL WHERE NOT EXISTS`(Oracle 문법)이고 동시 중복은 `DuplicateKeyException`을 성공으로 처리한다. Oracle 더미 DB에서 한 번 확인이 필요하다.
- REQUIRED_DOCUMENTS는 '·'로 나눈다. 서류 이름 안에 '·'가 있으면 쪼개진다(현재 시드에는 없음).
