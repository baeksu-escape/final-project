# FP-194·206 신용 라운지 화면과 관리자 신고 접수 화면 (mock 연결)

- **날짜:** 2026-11-15
- **작성자:** 동주 / Claude Code
- **브랜치:** `feature-C/FP-191-community`
- **관련 N-ID:** N-06-1~6, N-33-1·2, N-34-1~3
- **관련 결정:** D-25(알림 기능 없음), 탈퇴 회원 글 표시(11/12)

## 무엇을, 왜 바꿨나
- 신용 라운지 2단계로 화면을 만들었다. 1단계는 백엔드 API였다(커밋 `eb69911`, 로그 `2026-11-15_dongju_FP-191-신용라운지-API.md`). 기준 UI는 'Avenue 기능 데모 v2'의 `vBoard`, `reportPanel`, `vARep`이다.
  - FP-194 게시판: 목록·검색·페이지, 상세·댓글, 글쓰기, 내 글 수정·삭제
  - FP-206 신고 창, 관리자 신고 접수: 필터, 묶음 목록, 상세, 처리, 자동 숨김 기준 변경
- 키가 없어 아직 서버에 붙이지 못한다. 그래서 1단계 응답 DTO와 필드 이름·모양이 똑같은 mock으로 개발했다. 서버에 붙일 때는 `VITE_USE_MOCK=false`만 바꾸면 된다.

## 바뀐 파일
| 파일 | 변경 내용 (1줄) |
|------|-----------------|
| `frontend/src/features/community/**` (새 폴더) | API 함수 2개, 코드값, mock 데이터·처리기, 화면 컴포넌트 7개, 페이지 2개, `community.css` |
| `frontend/src/common/routes/AppRoutes.jsx` | 신용 라운지·신고 접수 자리의 `PlaceholderPage`를 실제 페이지로 바꿈(README 규칙대로 한 줄씩 + import 2줄) |
| `frontend/src/common/mocks/mockHandlers.js` | mock 처리 함수에 `path`(쿼리 포함 주소)를 함께 넘김. 기존 처리 함수는 `{ body, token }`만 쓰므로 동작이 같다 |

## DB·API 변경
- DB: 없음
- API: 없음. 1단계에서 만든 `/api/board/posts/**`, `/api/reports`, `/api/admin/reports/**`, `/api/admin/settings`를 쓴다.
- 영향을 받는 기능·팀원
  - **공통 mock을 쓰는 모든 팀원:** 처리 함수가 이제 `({ body, token, path })`를 받는다. 쿼리 파라미터가 필요하면 `new URL(path, 'http://x').searchParams`로 꺼내 쓰면 된다. 기존 코드는 고칠 필요가 없다.

## 확인
- 확인함
  - `npm run lint`: 오류 0
  - `vite build`: 성공
  - node로 mock 처리기를 직접 호출해 규칙을 확인했다.
    - 목록 2쪽·검색
    - 본인 글 신고 409, 남의 글 수정 403, 중복 신고 409, 하루 4번째 신고 429
    - 기준 5건 자동 숨김, 일반 사용자의 관리자 API 403
    - 대상별 묶음 목록, 신고자 가림
    - 반려 후 다시 보임, 다시 처리하면 409
    - 기준 11 입력 400, 삭제 후 404
- 확인 못 함
  - 브라우저 화면 동작: 동주님이 `npm run dev`로 확인한다.
    1. `employee`로 신용 라운지에 들어간다.
    2. `self`·`freelancer`로 신고한다.
    3. `admin`으로 신고 접수 화면을 본다.
  - 실제 서버 연결: 공용 Oracle 키를 받은 뒤 1단계 확인과 함께 한다.
