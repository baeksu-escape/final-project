- **날짜:** 2026-11-18
- **작성자:** 오범영 / Claude Code
- **브랜치:** `feature-B/FP-221-api-docs-folder` (Jira FP-221)
- **관련 N-ID:** 전체 (API 문서), N-21-2·N-21-9·N-22-3(PR #83 반영)
- **관련 결정:** D-20(오류 형식, 미정 그대로)

## 무엇을, 왜 바꿨나
- API 정의서와 B팀 명세서를 저장소 밖(공유 링크)에서만 관리해, 팀원이 저장소에서 찾을 수 없었고 C팀 문서(`api_spec.md`)와 업무가 갈렸다.
- 세 팀이 한 파일을 함께 고치면 PR마다 충돌이 나서, 정의서(목차, 범영) 1개 + 팀별 명세서 3개로 나눴다. 광희 님 동의(API는 범영이 관리) 후 진행.
- B팀 명세서는 코드 주석 약 40곳이 "B팀 명세서 4-3"처럼 장 번호로 가리켜서 **장 번호를 그대로** 두고 파일만 옮겼다.

## DB·API 변경
- DB: 없음
- API: 없음 (문서 위치만 바뀜)
- 영향을 받는 기능·팀원: 모든 팀. C팀 문서 경로가 바뀌어 광희·동주 님 작업 브랜치에서 `api_spec.md`를 고쳤다면 병합 때 새 경로로 옮겨야 한다. A팀은 bfe6b94 이후 바뀐 A팀 API가 있으면 `api_spec_a.md`를 고친다.

## 다음 사람이 알아야 할 것
- 이제 이 폴더가 원본이다. 공유 링크(옛 페이지)는 더 갱신하지 않는다.
- API를 추가·변경하면 자기 팀 명세서를 같이 고치고, PR 본문에 "추가·변경한 API(ID, 경로)"를 적는다. 정의서는 범영이 반영한다.
- 지난 작업 로그의 옛 경로(`api_spec.md`)는 당시 기록이라 고치지 않았다.
