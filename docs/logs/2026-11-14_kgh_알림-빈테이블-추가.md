# 알림 저장용 빈 테이블 추가

- **날짜:** 2026-11-14
- **작성자:** 권경환 / Codex
- **브랜치:** `KGH_Work`
- **관련 N-ID:** 공통 헤더 알림(기능 번호 미정, N-19와 별개)
- **관련 결정:** D-05, D-23, D-25

## 무엇을, 왜 바꿨나
- 사용자가 전달한 회의 결정에 따라 알림 테이블만 준비했다. 알림 데이터·시드·API·생성·발송 로직은 추가하지 않았다.
- 다운로드의 테이블 설명 문서에서 USER_, _ID, _CODE, _AT 명명 규칙을 참고했다. 원본 문서는 수정하지 않았다.
- D-05는 기준 DDL을 따르는 확정 항목으로, D-25는 추가 대상 테이블 반영 완료로 정리했다. 알림 기능 범위·우선순위는 D-23에 남긴다.

## DB·API 변경
- DB: USER_NOTIFICATION 추가. 수신 회원 FK, 종류·제목·내용·내부 이동 경로·읽은 시각·생성 시각을 저장할 구조만 준비한다.
- API: 없음.
- 영향을 받는 기능·팀원: 공통 헤더 알림 구현 담당, DB 적재 담당.

## 확인
- 확인함: 상권 제거·DDL 패키지 일치 검사 5개, 자산·대출 상태 검사 5개, 알림 빈 구조 검사 1개 통과. 공백 검사 통과.
- 확인 못 함: 실제 Oracle 생성·조회, 전체 데이터 재생성·전체 테스트·알림 화면 연동. 최종점검 때 진행할 예정이다.

## 다음 사람이 알아야 할 것
- 기존 DB에는 create_user_notification.sql을 한 번만 수동 실행한다. APP_USER가 먼저 있어야 한다. Oracle DDL은 자동 COMMIT되며 이미 존재하면 오류로 중단한다.
- 신규 스키마는 기준 DDL에 포함되어 있으므로 추가 SQL을 별도 실행하지 않는다.
- 실제 알림 종류·생성·발송 규칙은 이번에 정하지 않았다.
