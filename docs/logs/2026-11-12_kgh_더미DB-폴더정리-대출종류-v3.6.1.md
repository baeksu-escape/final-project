## 무엇을, 왜 바꿨나
- 폴더 이름에 버전을 넣지 않는 원칙에 따라 `dummy_db/v0_2/`의 DDL·시드·생성기를 `dummy_db/`로 옮기고 옛 v2.4 묶음을 지웠다(이력은 git). 생성기 이름은 `tools/build_db.py`, 표 수는 DDL에서 읽는다.
- 서비스 더미 대출 원장·금융 응답에 대출 종류(`loan_type_code`)·금리 방식(`rate_type`)을 추가했다(데이터 패키지 v3.6.1). 학습 데이터 값은 그대로다.
- 검수 지적(출력 폴더 제한 설명, 옛 이름, 출처 표현, TODO(D-27) 복원, CHANGES 위치·날짜, BOM)을 반영했다.
- 카드 한도를 반올림 없이 `(KC1000001 - L00000002) × 1000`으로 계산하도록 교체했다(원천 누락·음수는 NULL).

## DB·API 변경
- DB: 저장소 위치가 `docs/spec/sql/dummy_db/`로 바뀌었다. v0.3.2 시드는 대출 종류·금리 방식과 동의 ID를 반영한다.
- API: 없음(서비스 더미 금융 응답 `loans[]`에 `loan_type_code`·`rate_type` 추가)
- 영향을 받는 기능·팀원: A팀 Spring(대출 불러오기), DB 담당, 시드 SQL 경로를 쓰는 팀원

## 확인
- 확인함: `docs/spec/sql/dummy_db/tools/tests` 31개 통과(테스트 키, 400명 원천). `fastapi_server/data_generation/tests` 99개 중 오류 2개(Windows 심볼릭 링크 권한 WinError 1314, 기존 환경 문제), 실패 0. manifest 90개 해시 재계산.
- 추가 확인: 사용자가 팀 키로 시드를 재생성했다(51표, 오류 없음). 원천 경로가 있으면 테스트 34개 전부 통과, 없으면 31개 통과·3개 건너뜀.
- 확인 못 함: Oracle 적재.

## 다음 사람이 알아야 할 것
- 시드 SQL(10_~)은 사용자가 팀 키로 재생성해 대출 종류·금리 방식과 동의 ID를 반영했다.
- 카드 한도(`CARD_LIMIT_AMT`)는 결정된 KC1000001 − L00000002 방식을 적용한다.

## 생성기 v0.3.2 대응

- 기준 DDL은 `docs/spec/sql/avenue_ddl.sql`(v0.3.2, 51개 표)이다. 사용자가 팀 키로 시드를 재생성했다(표 51, 오류 없음).
- `build_db.py`에 `||`·`TO_CHAR`·`LIKE/ESCAPE`·`NOT LIKE`와 빈 문자열의 NULL 처리를 추가했다. 기본 DDL은 `docs/spec/sql/avenue_ddl.sql`이며 `01_create_tables.sql`은 그 바이트 사본이다. 시드 파일 머리말의 버전 숫자는 제거했다.
- `USER_LOAN.CONSENT_ID`는 IMPORTED 157행 전부 채웠다. 원천 경로가 있는 테스트 34개가 00/99 바이트 비교를 포함해 전부 통과했다. 원천 경로가 없으면 31개 통과·3개 건너뜀이다.
- 확인 못 함: Oracle 적재.
