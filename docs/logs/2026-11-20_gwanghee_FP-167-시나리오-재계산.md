- **날짜:** 2026-11-20
- **작성자:** 임광희(C팀) / Claude Code
- **브랜치:** `feature-C/FP-167-scenario` (Jira FP-167, FP-165 하위)
- **관련 N-ID:** N-17-1 저장값 조회, N-17-2 조건 입력, N-17-3 공통 재계산 틀, N-17-4 상환 여력 재계산, N-17-5 비교 표시
- **관련 결정:**
  - 저장 데이터를 읽는 API는 `/api/members/me/**`에 둔다(FP-170 11/19, 우찬 님 합의).
  - 상환 부담률은 N-16-1·N-20-4와 같은 함수를 쓴다.
  - 정책금리는 동주 님 FP-153 한국은행 기준금리 적재 SQL을 쓴다.

## 무엇을, 왜 바꿨나
- 시나리오 테스트 API 2개를 추가했다. API 정의서의 DIAG-04 옛 경로 `POST /api/diagnosis/scenario/recalculate`(프론트 mock만 있음)를 대신한다.
  - `GET /api/members/me/scenario-base`
    - 기준값을 돌려준다: 월 소득(12개월 평균)·지출·상환액, 변동금리 대출 잔액, 총자산, 현재 정책금리, 계산 가정.
  - `POST /api/members/me/scenario-recalculate`
    - 조건(금리 %p, 소득 %, 지출 %)을 반영해 지금과 조건 반영 후의 월 잉여·상환 부담률을 계산한다.
    - 월 이자 변화, 잉여 차이, 버틸 수 있는 개월 수, 판정(`SHORTFALL`·`IMPROVED`·`STILL_POSITIVE`)도 함께 돌려준다.
    - 점수는 구하지 않고 저장하지 않는다.
- 금리 변화는 **변동금리 대출 잔액에만** 반영한다. 시나리오 화면(경환 FP-210)과 같은 규칙이다.
- 버틸 수 있는 개월 수 = ⌊총자산 × 25% ÷ 월 부족액⌋이며, 적자일 때만 값이 있다.
  - 25%는 명세에 기준이 없어 화면 가정을 임시로 쓴다(`TODO(팀 결정)`).
- 기준 소득은 현금흐름 전망과 같은 함수(`IncomeVolatilityService.loadIncomeHistory`)를 쓴다.
  - 그래서 private을 package-private로 바꿨다. 동작은 같다.
- `ScenarioRecalculateRequest`를 새 모양(`ratePctPoint`·`incomePct`·`expensePct`)으로 바꿨다.
  - FP-217에서 "FP-167에서 고치거나 지운다"고 주석을 단, 쓰는 곳이 없던 옛 DTO다.

## 11/20 리뷰 반영 (PR #112)
- **무엇을, 왜**
  - 금리 변화가 변동금리 잔액으로 구한 이자를 **전체** 월 상환액에 더하고 0으로만 막고 있었다. 그래서 금리가 크게 내려가면 고정금리 상환액까지 줄었다. 또 대출별 금리 하한이 없어 연 3% 대출에 −5%p를 넣으면 −2%로 계산됐다.
    - 이제 변동금리 대출을 행 단위(잔액·연 금리·월 원리금)로 읽고, 대출마다 금리를 0% 아래로 내리지 않는다.
    - 이자 변화는 변동금리 대출의 상환액에만 더한다(0 하한). 고정·`UNKNOWN` 대출의 상환액은 그대로다.
  - 서버 `HALF_UP`(−0.5 → −1)과 mock `Math.round`(−0.5 → 0)가 음수 0.5원에서 달랐다. mock에 서버와 같은 반올림 함수를 넣었다.
  - API 경로·응답 필드는 그대로다. 계산 가정 문구 두 줄만 새 규칙에 맞게 고쳤다.
- **바뀐 파일**
  - `dto/scenario/VariableLoanRow.java`(새 파일)
  - `ScenarioMapper`(.java/.xml): `selectLatestVariableLoanBalance`를 `selectLatestVariableLoans`(행 목록)로 바꿨다. 이 PR에서 새로 만든 쿼리라 develop에 영향이 없다.
  - `ScenarioService`
  - 테스트: `ScenarioServiceTest`(고정 상환액 유지·대출별 금리 하한·±0.5원 반올림 3개 추가), `ScenarioMapperIT`
  - mock: `diagnosisMockHandlers.js`·`diagnosisMockData.js`
  - 문서: `api_spec_c.md`
- **확인**
  - `./mvnw clean test` 414개 통과
  - DB 통합 테스트 5종 11개 통과(JWT·AES·HMAC은 일회용 값으로 덮어씀)
  - `npm run lint` 오류 0
  - node로 mock 직접 호출
    - 문서 예시(+2%p·소득 −40%)는 그대로 이자 +20,000원, 적자 425,815원, 17개월이다.
    - −5%p는 이자 −50,000원, 상환액 30만 원(고정 15만 원 유지)이다.
- **경환 님 안내 필요**: 시나리오 화면(FP-210)의 `calculateScenario.js`도 "전체 상환액 + 이자 변화" 방식이다. 서버 응답을 쓰면 새 규칙이 그대로 반영된다. 화면에서 직접 계산하는 부분을 맞출지는 경환 님이 정한다.

## 다음 사람이 알아야 할 것
- 버틸 수 있는 개월 수의 25%는 `ScenarioService.SURVIVABLE_ASSET_RATIO_PCT` 상수 하나다.
- 팀 회의에서 바꾸기로 하면 **기존 필드는 두고 필드를 추가**하는 방식으로 고친다. 검토 중인 안은 아래와 같다.
  - 비율을 화면 조건으로 받기
  - 범위로 보여 주기
  - 직군별 목표 개월 수
- develop의 옛 시나리오 mock(`POST /api/diagnosis/scenario/recalculate`)은 "월소득 6배"를 유동자산으로 가정한다. 새 API와 가정이 다르니 새 화면은 `recalculateMemberScenario`를 쓴다.
- 로컬 DB에 `FACT_POLICY_RATE` 데이터가 없으면 `policyRate`가 `null`이다. `docs/spec/sql/add_policy_rate_bok_base_rate.sql`을 실행하면 된다.
