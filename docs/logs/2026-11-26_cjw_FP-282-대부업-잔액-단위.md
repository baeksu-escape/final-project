## 다음 사람이 알아야 할 것
- 병합 뒤 공용 FastAPI를 다시 시작해야 반영된다.
- 이미 저장된 평가는 자동으로 바뀌지 않는다. 아래 읽기 전용 조회로 대상을 찾아 해당 계정은 점수를 다시 산출한다.

```sql
SELECT A.ASSESSMENT_ID, A.USER_ID, A.MODEL_VERSION, A.ASSESSED_AT, A.ALT_SCORE, F.FEATURE_VALUE, F.SHAP_SCORE
  FROM ASSESSMENT A JOIN ASSESSMENT_FACTOR F ON F.ASSESSMENT_ID = A.ASSESSMENT_ID
 WHERE F.FEATURE_CODE = 'LA0099212'
   AND TO_NUMBER(F.FEATURE_VALUE DEFAULT NULL ON CONVERSION ERROR) > 0
 ORDER BY A.ASSESSED_AT DESC;
```

- 저장소의 시드 평가(`load_seed_assessment_lgbm_base_0_2.sql`)는 신용 항목이 빈 값으로 계산돼 이 수정의 영향이 없다. 시드 회원의 신용 정보(`IMPORTED`)가 점수에 반영되지 않는 문제는 별도 작업이다.
- 단위를 맞춰도 대부업 잔액이 클수록 점수가 오를 수 있다(모델이 학습한 방향). 처리 방침은 팀 결정 전이다.
