# 시드 회원 근무기간 채우기 + 비교 분석용 시드 회원 점수 넣기 SQL

- **날짜:** 2026-11-24
- **작성자:** 오범영 / Claude Code
- **브랜치:** `feature-B/seed-work-period`
- **관련 N-ID:** N-05 데이터 입력(근무기간 필수), N-12-2 점수 산출, N-13 비교 분석(RPT-05 내 위치)
- **관련 결정:** 동주 11/24 합의(회원별 값, 자영업자·프리랜서 최소 12개월, 대상 `DUMMY_YN='Y' AND ROLE_USER`), 미동의 82명은 그대로(범영 11/24)

## 무엇을, 왜 바꿨나
- 시드 회원 400명의 근무기간(`APP_USER.WORK_PERIOD_MONTHS`)이 모두 NULL이라 점수 산출 조건(입력 완료)을 못 채웠다. 동주는 로컬에서 직군 고정값(24/36/24)으로 채우려 했고, 회원별 값으로 바꾸기로 했다.
- 시드에는 평가(ASSESSMENT) 행이 없어 비교 분석이 비어 있었다. 점수는 모델이 내야 하므로 범영 로컬에서 일괄 산출(로컬 임시 batch, 커밋 안 함)한 결과를 SQL로 뽑아, 팀원·공용 DB는 batch·FastAPI 없이 SQL만 실행하게 했다.
- 실행 순서: `update_seed_user_work_period.sql` → `load_seed_assessment_lgbm_base_0_2.sql`.

## DB·API 변경
- DB: 구조 변경 없음. 데이터만 — `APP_USER.WORK_PERIOD_MONTHS`(시드 400명 UPDATE), `ASSESSMENT`·`ASSESSMENT_FACTOR`(시드 회원 318명분 INSERT)
- API: 없음
- 영향을 받는 기능·팀원: 비교 분석(동주), 관리자 통계(같은 쿼리), 시드 회원으로 리포트·점수 추이를 보는 화면. 데모 계정 3개의 근무기간도 바뀐다.

## 확인
- 확인함: 근무기간 SQL 계산식(Decimal 재현)과 시드 400행 대조 불일치 0, 생성기 `WorkPeriodTests` 2개 통과
- 확인함: 범영 로컬에서 근무기간 SQL → 일괄 산출 → 사이트 비교 분석 정상 표시
- 확인함: 점수 넣기 SQL 파일 — 평가 318(급여 102·자영업 107·프리랜서 109), 항목 12,084(318×38), 회원·REQUEST_ID 중복 0, 끝까지 완성
- 확인 못 함: 점수가 없는 새 DB에 넣기 SQL 실행(범영 DB는 이미 같은 점수가 있어 전부 건너뜀). 생성기 기존 테스트 1개는 범영 PC에 `bcrypt` 모듈이 없어 실패(이번 변경과 무관)

## 다음 사람이 알아야 할 것
- 점수 넣기 SQL은 **LGBM-BASE-0.2 기준**이다. 비교 분석은 ACTIVE 모델 점수만 세므로, 로컬 ACTIVE 모델이 0.2가 아니면 넣어도 안 보인다. 모델이 바뀌면 일괄 산출 후 `export_seed_assessment.sql`로 다시 뽑는다.
- 82명은 시드의 시작 동의 상태가 미동의(생성 가정 80%)라 점수가 없다(대안 데이터 없음). 그대로 두기로 했다.
- 두 SQL 모두 시드 회원 수 400을 고정 검사한다. 시드 회원이 늘면 두 파일의 숫자를 같이 바꾼다.
- 일괄 산출을 SQL Developer `DBMS_OUTPUT`으로 뽑으면 약 1MB에서 끊긴다(첫 시도 52명). 그래서 조회 결과 한 행 = 파일 한 줄 방식으로 뽑는다.
