## DB·API 변경
- DB: `USER_ASSET_SNAPSHOT.TOTAL_ASSET_AMT`는 NULL 허용(기존 CHECK >= 0 유지). `NO_LOAN_YN CHAR(1)`은 Y/N/NULL 허용, 기본값 없음.
- API: 경로·응답 필드는 변경하지 않았다. 입력 완료·상태 저장 규칙은 README에 전달하며 실제 입력 API 구현은 우찬 담당이다.
- 영향을 받는 기능·팀원: N-05-3·4·8, DB·입력 API 담당. 자산 NULL을 사용하는 재무 진단은 0원으로 취급하지 않아야 한다.

## 다음 사람이 알아야 할 것
- 기존 DB는 ALTER 파일로 스키마만 변경한다. 기존 행의 새 열은 NULL로 유지하며 임의의 미입력 회원을 Y로 보정하지 않는다.
- 완전한 합성 원장으로 대출 유무를 확인한 커밋 시드는 Y 253명·N 147명이다. 이미 적재된 DB에 INSERT 시드를 재실행하지 않는다. 기존 DB의 시드 Y/N 보정은 적재 이력·현재 변경 여부를 확인한 뒤 별도로 처리한다.
- 입력 완료: 자산은 TOTAL_ASSET_AMT IS NOT NULL, 대출은 같은 회원·기준월의 USER_LOAN 행 존재 또는 NO_LOAN_YN=Y.
- "해당 없음" 저장 시 행이 없으면 NULL 자산과 Y로 생성, 기존 총자산은 보존한다. 이후 대출 추가 시 N으로 변경한다. 동의 철회에 따른 대출 삭제는 Y 선택을 뜻하지 않는다.
- Oracle DDL은 자동 커밋되므로 미커밋 업무가 없는 별도 세션에서 실행한다. API·재무 진단의 실제 적용은 이 작업에 포함되지 않는다.
