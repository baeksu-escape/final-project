## DB·API 변경
- **DB:** 구조 변경 없음. 데이터만: 등급 구간 `CUT-0.4`, `SCORE_BAND_OFFER` 점수 구간, `LOAN_PRODUCT.MIN_ALT_SCORE`(727→712, 654→645), 모델 0.3 등록·평가 표본·같은 라벨 AUC.
- **기존 DB 실행 순서:** `add_cutoff_cut_0_4` → `register_model_lgbm_base_0_3` → `load_model_eval_sample_lgbm_base_0_3` → `update_model_metrics_same_label_lgbm_base_0_3` → 서버 파일 0.3 교체·health → `activate_model_lgbm_base_0_3` → `activate_cutoff_cut_0_4` → 0.3 시드 평가.
- **API:** 필드·경로 변경 없음. `cutoffVersion`·`gradeBands` 값이 모델 버전에 따라 달라진다.
- **영향:** 점수를 내는 PC는 0.3 묶음이 필요하다(DB ACTIVE가 0.3인 경우). 0.2 평가의 시뮬레이터는 "점수를 다시 산출" 안내가 난다. Mock(`DEV-DUMMY`)은 `CUT-0.3`으로 답하므로, 새 DDL로 만든 DB에서 Mock을 쓰면 평가 등급(CUT-0.3)과 금리·한도 참고 구간(CUT-0.4)이 다를 수 있다.
