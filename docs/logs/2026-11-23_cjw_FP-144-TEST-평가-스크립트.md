# FP-144 최종 성능 지표 — TEST 평가 스크립트 추가 (사전 기준 C26, 모델 0.2)

- **날짜:** 2026-11-23
- **작성자:** 최재욱(B팀 모델·정의서 담당) / Claude Code
- **브랜치:** `feature-B/FP-144-final-test-eval` (Jira FP-144, 상위 FP-125)
- **관련 N-ID:** N-12(점수 모델 평가), N-25(모형 성능)
- **관련 결정:** 정의서 10장 C26(TEST 평가 사전 기준), C25(모델 0.2), C27·C28(등급 구간 CUT-0.3)

## 무엇을, 왜 바꿨나
- 발표용 최종 성능 지표를 정하려면 TEST를 한 번 평가해야 한다. 지금 학습·내보내기 스크립트는 TEST 행을 읽자마자 버리므로, TEST를 읽는 **별도 평가 스크립트**를 새로 만들었다. 기존 스크립트의 동작은 바꾸지 않았다.
- 사전 기준은 정의서 C26(11/20)에 이미 기록돼 있고, 스크립트는 그 값을 상수로 옮겨 쓴다(기준 AUC·정상 범위 ±0.05·연체 라벨 차이 ±0.04). 시험이 상수와 C26 본문이 같은지 검사한다.
- 안전장치: `--confirm-test-once` 없이는 TEST를 읽지 않음, 추적 파일에 커밋하지 않은 변경이 없을 때만(코드를 먼저 커밋한 뒤) TEST 실행, 고정 경로 실행 기록이 있으면 재실행 거부(`--rerun-reason`은 평가 코드 오류를 고친 재실행에만), 서버 모델 파일 해시·`meta.json` 버전(0.2)·재현 확인이 맞지 않으면 TEST를 열기 전에 중단.
- **이 PR에는 TEST 결과가 없다.** TEST는 코드 커밋·병합 뒤 사용자가 지시했을 때 한 번만 실행하고, 결과 숫자는 그때 이 로그에 이어 적는다.

- 정의서 10장 C29에 같은 내용을 요약해 두었다. 9장·`decisions.md`의 "최종 등급 경계는 FP-144 이후 다시 확인한다"는 문구는 이번에 고치지 않았다(경계를 이대로 확정할지는 팀 결정이다. 등급 비율이 VALID와 비슷하다는 근거만 이 로그에 있다).

## 다음 사람이 알아야 할 것
- TEST는 **한 번만** 본다(C26). 실행 전 순서: 이 PR 병합(또는 최소한 코드 커밋) → 작업 트리 깨끗함 확인 → `python -m training.final_test_eval --split TEST --confirm-test-once`. 결과는 `docs/spec/final_test_eval_result.json`·`.md`에 남고 같은 파일이 있으면 다시 실행되지 않는다.
- 결과를 본 뒤에는 모델·지표·정상 범위·등급 경계를 바꾸지 않는다. 범위 밖이나 설계 방향과 반대인 결과도 숨기지 않는다. 모델을 고치고 싶으면 새 버전(예: 0.3)으로 보고 VALID로 다시 검증한다(이미 본 TEST로는 평가하지 못한다).
- C26의 정상 범위는 기존 집단 기준이라 씬파일은 판정 없이 참고 값으로만 낸다(리허설에서 씬파일 5시드 평균이 범위를 벗어나 보이는 항목이 있는데, 판정 대상이 아니다). 평가 표본의 씬파일에는 이력이 긴 비교군(`young_established`)이 섞여 있다.
- TEST 실행 뒤에 할 일: 이 로그에 결과 숫자 추가, 정의서 10장 새 행(C29)에 평가 완료 기록, 9장·`decisions.md`의 "최종 경계는 FP-144 이후 다시 확인"은 결과를 보고 팀과 정한다.
- 로그 파일명의 작성자 약어 `cjw`는 제안이다.
