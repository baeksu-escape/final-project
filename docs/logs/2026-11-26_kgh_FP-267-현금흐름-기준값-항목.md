## 무엇을, 왜 바꿨나
- 현금흐름 화면이 기타 지출과 대출 원리금을 항목별로 보여 줄 수 있게 DIAG-08-1 응답에 목록 2개를 추가했다.
- 11/25 팀 결정에 따라 현금흐름 화면에서 예상 점수(DIAG-09 호출·점수선·납부 상태 입력)를 제거했다. 월 지출 구성은 마지막 예측 응답 기준으로 항목을 펼쳐 보여 주며, 적자 개월 수, 되돌리기 버튼, "잉여" → "여유 자금" 문구, 가장 빠듯한 달 배치도 반영했다.
- 최근 12개월 소득 표는 접기·배지를 적용하고 변동성 API와 분리했다. 소득 부족 달 카드도 화면에 맞추고, 화면 안 "부족" 기준(고정지출 기준·월 지출(원리금 포함) 기준)을 짧게 표시했다. `features.md`의 N-21·N-22·N-17, `decisions.md`의 D-32, diagnosis README를 함께 갱신했다.
- 기존 필드·경로·메서드·매퍼 id는 바꾸지 않았다(추가만). 광희 님께 알리고 확인받았다.
- 정렬: 기타 지출은 월 금액 큰 순(같으면 EXPENSE_ID 순), 대출은 LOAN_ID 순.

## DB·API 변경
- DB: 없음(기존 테이블 조회만).
- API: DIAG-08-1 응답에 `baseOtherExpenseItems[]`(expenseGroupCode·expenseCategory·description·monthlyAmount)와 `baseLoanItems[]`(loanId·loanTypeName·monthlyPaymentAmount) 추가. DIAG-08(POST)은 `null`.
- 영향을 받는 기능·팀원: N-21 현금흐름 화면(경환), API 작성자 광희.

- 확인 못 함: 동시 저장 상황(직접 재현하지 않음). 목록 합 방식으로 바꾼 뒤 실제 서버 응답과 금액 큰 순 정렬은 위에서 확인했다.

## 다음 사람이 알아야 할 것
- 대출 종류 이름은 자산·부채 API와 같이 DIM_LOAN_TYPE을 JOIN해서 가져온다. 대출 종류는 FK가 걸려 있어 빠지는 행이 없다(광희 확인).
- 기타 지출·월 원리금 기준값과 월 지출 합계(고정지출 + 기타 지출 항목 합)를 항목 목록의 합으로 구해, 합계와 목록이 같은 조회 결과에서 나온다. 동시 저장에도 어긋나지 않으며 트랜잭션·격리 수준은 지정하지 않았다(광희 의견, 저장소에서 격리 수준을 쓴 사례가 없어 다른 API와 기준을 맞춤).
- `selectLatestTotalExpense`·`selectLatestLoanMonthlyPayment` 매퍼 메서드는 지우지 않았다. DIAG-08-1 경로는 더 부르지 않지만 `ScenarioService`(N-17-1)와 `IncomeVolatilityMapperIT`가 쓴다.
- 매퍼 XML 안에서는 `<`를 그대로 쓰면 파싱 오류로 서버가 뜨지 않는다. 지출 그룹 조건은 `!=`로 썼다.
