- DB: 없음(기존 테이블 조회만).
- API: DIAG-08-1 응답에 `baseOtherExpenseItems[]`(expenseGroupCode·expenseCategory·description·monthlyAmount)와 `baseLoanItems[]`(loanId·loanTypeName·monthlyPaymentAmount) 추가. DIAG-08(POST)은 `null`.
- 영향을 받는 기능·팀원: N-21 현금흐름 화면(경환), API 작성자 광희.

## 다음 사람이 알아야 할 것
- 대출 종류 이름은 자산·부채 API와 같이 DIM_LOAN_TYPE을 JOIN해서 가져온다. 대출 종류는 FK가 걸려 있어 빠지는 행이 없다(광희 확인).
- PC·휴대폰 동시 접속에 대비해 `forecastSavedCashFlow`를 `@Transactional(readOnly = true, isolation = Isolation.SERIALIZABLE)`로 묶었다. Oracle에서 메서드 안의 조회가 모두 시작 시점 데이터를 보므로 합계와 목록이 어긋나지 않는다. 프로젝트에서 격리 수준을 지정한 첫 사례다.
- 매퍼 XML 안에서는 `<`를 그대로 쓰면 파싱 오류로 서버가 뜨지 않는다. 지출 그룹 조건은 `!=`로 썼다.
