- **날짜:** 2026-11-23
- **작성자:** 최재욱(B팀 모델·정의서 담당) / Claude Code
- **브랜치:** `feature-B/FP-248-cutoff-cut-0-3-activate` (Jira FP-248, 상위 FP-126)
- **관련 N-ID:** N-04(등급 구간), N-12(점수·등급), N-18·N-25·N-37(등급 경계를 쓰는 화면·대출 상품)
- **관련 결정:** `decisions.md` D-01, 정의서 10장 C27(CUT-0.3)·**C28(이번 전환)**, 11/23 사용자 결정(모델 0.2 유지·화면 문구만 추가, 등급 경계 CUT-0.3 적용)

## 무엇을, 왜 바꿨나
- 모델 0.2로 점수 분포가 바뀌어 25/50/25 경계를 `CUT-0.3`(0~653 / 654~726 / 727~1000)으로 다시 계산해 두었고(C27, DRAFT), 이번에 **서비스 등급 구간을 `CUT-0.3`(ACTIVE)으로 전환**한다. `CUT-0.1`(665/780)은 RETIRED로 내린다.
- 점수대별 금리·한도(`SCORE_BAND_OFFER`)의 점수 구간과 대출 상품 최소 점수(`LOAN_PRODUCT.MIN_ALT_SCORE`)도 새 경계에 맞춘다: 구간 0~664 / 665~779 / 780~1000 → 0~653 / 654~726 / 727~1000(금리·한도 값은 그대로), 상품 최소 점수 780(7개) → 727, 665(2개) → 654, 0점(8개)은 그대로.
- **TODO(D-01) 팀 확정 필요:** 상품 최소 점수 727·654는 "새 우수·보통 하한에 맞춘다"는 제안값이다. 최종 경계는 FP-144(TEST) 이후 다시 확인한다.

## DB·API 변경
- DB: 구조 변경 없음. 기준 데이터 상태 2행(`SCORE_CUTOFF_VERSION`)과 더미 데이터 값(`SCORE_BAND_OFFER` 3행, `LOAN_PRODUCT.MIN_ALT_SCORE` 9행)이 바뀐다. **저장된 평가 행은 건드리지 않는다**(평가마다 자기 `CUTOFF_VERSION`을 가진다, 이전 평가는 `CUT-0.1`).
- API: 응답 필드는 그대로이고 `cutoffVersion` 값과 등급 경계가 달라진다(`CUT-0.1` → `CUT-0.3`, `gradeBands` 구간 값).
- 영향을 받는 기능·팀원: 범영(공용 DB 전환·FastAPI 배포), 프론트 담당(등급 상수·mock), 백엔드 시험 담당(아래 목록), 동주(N-25 등급 비율), 대출 상품(N-37)·시뮬레이터(N-18)

## 확인
- 확인함: FastAPI 테스트 191개 통과(`.venv`, 새 시험 4개 포함), DB 도구 테스트 52개 통과(건너뜀 3). DDL과 `01_create_tables.sql` 사본이 같고(`cmp`), `seed_report.json`의 `ddl_sha256`을 LF 정규화 DDL 해시로 갱신했다. 시드 값(금리·한도 3행 구간, 상품 최소 점수 {0, 654, 727}, 생성기 상수)이 시험과 같다.
- 로컬 Oracle(11/23, 사용자 확인, `C##AVENUE`·SID `xe`): 시작 상태 조회 → `activate_cutoff_cut_0_3.sql` 실행 → 다시 실행 → 오류로 멈추는 경로(구간·금리·한도 구간을 바꾼 뒤 실행) → `rollback_cutoff_cut_0_3_to_0_1.sql` 실행 → 다시 전환까지 5단계를 모두 실행했고 기대대로 동작했다고 확인받았다. 단계별 오류 번호·조회 결과 원문은 이 로그에 옮기지 않았다.
- 백엔드(11/23, 최신 `develop` 합친 브랜치): 단위 시험 `./mvnw test` 466개 통과(실패 0, 오류 0). 통합 시험은 로컬 Oracle(`CUT-0.3` ACTIVE)에서 `-Ddb.it=true -Dtest=ScoreBandOfferMapperIT`로 실행: 고치기 전 2개 실패(CAUTION 기대·STANDARD, 665 기대·654), 단언을 새 값으로 고친 뒤 2개 통과. 다른 통합 시험(`*IT`)은 실행하지 않았다.
- 확인 못 함: 공용 DB 적용, 프론트 반영과 화면 확인, 백엔드의 나머지 통합 시험, 대출 상품 화면과 시뮬레이터에서의 변화, `-20151`(CUT-0.3 행 없음·상태 이상)·`-20161`~`-20163`(되돌리기 사전 확인)의 오류 경로 실행.
