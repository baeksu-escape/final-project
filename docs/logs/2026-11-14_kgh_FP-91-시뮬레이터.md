## 무엇을, 왜 바꿨나

- 신용케어 시뮬레이터 화면(`/simulator`)을 서버 API에 연결했다. 입력 10개를 바꾸면 0.5초 뒤 자동으로 다시 계산한다(SIM-02 `POST /api/members/me/credit-care-recalculate`). 실제 점수에는 반영하지 않는다.
- 내 실제 값 10개와 출발 점수는 SIM-01 `GET /api/members/me/credit-care-base`로 불러오며, [내 실제 값으로 되돌리기]도 이 값을 쓴다. 되돌릴 때는 새로 계산을 요청하지 않는다.
- 점수를 가장 많이 깎은 요인 3개를 보여 준다. 첫 화면은 SIM-01의 `topReductionFactors`, 재계산 뒤에는 SIM-02의 값을 쓴다. 모델 계산상 기여이며 점수가 낮아진 원인을 뜻하지 않는다.
- [예시 값 넣어 보기]는 칸에 예시 값을 넣고 일반 입력과 같이 자동 계산을 거친다. 예시 점수 변화는 시연 예시 계산이며 실제 효과를 보장하지 않는다.
- 같은 점수대 참고 금리·한도는 SIM-04(`GET /api/simulation/score-band-offer`)로 조회한다.
- 추천 상품 3개는 LOAN-01 목록을 읽어 화면이 고른다(점수 조건 충족·회원 직군 기준). SIM-03 API는 만들지 않았고 대출 상품 화면의 공용 `LoanProductCard`를 쓴다.
- 입력 오류는 해당 칸 아래에 보이고, 상태 줄은 입력 확인·계산 실패일 때만 붉은색이다.
- mock 모드(`VITE_USE_MOCK`)는 같은 응답 모양의 mock 핸들러가 대신 답한다.
