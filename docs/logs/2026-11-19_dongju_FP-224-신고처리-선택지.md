# FP-224 관리자 신고 처리 선택지를 삭제·반려 두 개로 줄임 (숨김 유지 제거)

- **날짜:** 2026-11-19
- **작성자:** 동주 / Claude Code
- **브랜치:** `feature-C/FP-224-adminReportTwoResults`
- **관련 N-ID:** N-34-3
- **관련 결정:** D-10(신고 처리), 동주 11/19 결정(화면+서버에서 숨김 유지 제거, DB는 그대로)

## 무엇을, 왜 바꿨나
- 관리자 신고 처리 결과에서 '숨김 유지(KEEP_HIDDEN)'를 뺐다. 이제 [삭제]·[반려] 두 개만 고른다.
- 화면에서만 빼면 API로는 여전히 보낼 수 있어서, 서버도 새 요청의 `KEEP_HIDDEN`을 400으로 막는다.
- DB의 CHECK 제약(`CK_CRP_RESULT`)과 이전 처리 기록은 그대로 둔다. 예전에 숨김 유지로 처리한 기록은 관리자 상세의 '처리 기록'에 그 이름으로 계속 보인다.
- 기본 선택은 되돌릴 수 있는 [반려]로 했다(되돌리기 어려운 [삭제]가 기본이면 실수로 지울 수 있어서).

## DB·API 변경
- DB: 없음(CHECK 제약·이전 행 그대로)
- API: ADM-13 `PATCH /api/admin/reports/{reportId}`의 `resultCode` 허용값이 `KEEP_HIDDEN|DELETE|REJECT`에서 `DELETE|REJECT`로 줄었다. `KEEP_HIDDEN`은 400 `INVALID_INPUT`(field `resultCode`, "처리 결과는 삭제·반려 중에서 골라 주세요.").
- 영향을 받는 기능·팀원
  - 범영(B팀 API 정의서 ADM-13: "숨김 유지·삭제·반려" → "삭제·반려")
  - 문서 담당(`docs/ai/features.md` N-34-3 입력·처리의 '숨김 유지' 문구)

## 확인
- 확인함: `./mvnw clean test` 371개 통과(`AdminReportServiceTest` 7개, `CommunityApiContractTest` 10개 포함), `npm run lint` 오류 0, `npm run build` 성공
- 확인 못 함: 화면 동작. 동주가 `npm run dev`로 관리자 로그인 → 신고함 → 신고 상세에서 선택지 두 개·기본 반려·이전 '숨김 유지' 기록 표시를 직접 확인해야 한다.

## 다음 사람이 알아야 할 것
- 신고가 자동 숨김 기준(기본 5건)에 못 미쳐 아직 보이는 글·댓글은, 관리자가 숨길 수 없고 삭제만 할 수 있다(숨김 유지가 하던 일).
- `KEEP_HIDDEN` 값은 DB·상수·화면 표시 목록에 남아 있다. 이전 기록을 읽기 위한 것이니 지우지 않는다.
- 신고 처리는 관리자 화면의 시스템 로그(`SYSTEM_LOG`, N-28)에 남지 않는다. 남기려면 `AdminReportService.process`에서 공통 `SystemLogService.record`를 부르면 된다(이번 범위 밖).
