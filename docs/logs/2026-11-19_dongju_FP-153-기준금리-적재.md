# FP-153 한국은행 기준금리를 기존 표 FACT_POLICY_RATE에 넣는 SQL 추가 (N-17)

- **날짜:** 2026-11-19
- **작성자:** 동주 / Claude Code
- **브랜치:** `feature-C/FP-153-publicStats`
- **관련 N-ID:** N-17-2, N-17-4
- **관련 결정:** 없음 (아래 「다음 사람이 알아야 할 것」의 N-15 방향은 팀 합의 필요)

## 무엇을, 왜 바꿨나
- N-17 시나리오 테스트(FP-167)는 "금리 +1%p" 같은 변화를 더할 **출발 금리**가 필요한데, `FACT_POLICY_RATE`가 0행이라 막혀 있었다.
- 한국은행 ECOS 기준금리 월별 값(2024.01~2026.10)으로 `FACT_POLICY_RATE` 34행을 넣는 SQL을 만들었다.
- 기존 DDL·SQL은 건드리지 않고(동주 방향), 이미 있는 표에 데이터만 넣는 새 SQL 파일 하나로 처리했다.

## 바뀐 파일
| 파일 | 변경 내용 (1줄) |

| `docs/spec/sql/README.md` | 「먼저 내 상황에 맞는 경로를 고른다」 표에 한 행 추가 |

## DB·API 변경
- DB: DDL 변경 없음. `FACT_POLICY_RATE` 데이터 34행 추가(`RATE_NAME` = '한국은행 기준금리', 2024-01-31 ~ 2026-10-31, 최근 값 3.000%)
- API: 없음
- 영향을 받는 기능·팀원
  - N-17 담당(FP-167): `RATE_NAME = '한국은행 기준금리'`이고 `BASE_DATE`가 가장 늦은 행을 출발 금리로 쓰면 된다(지금 2026-10-31, 3.000%).
  - DB 담당: 공용 DB에 `add_policy_rate_bok_base_rate.sql` 실행.

## 확인
- 확인함: 원본 CSV에서 스크립트로 SQL을 만들고, SQL의 34개 날짜·값을 CSV와 다시 대조해 모두 같음을 확인했다(CRLF, 가장 긴 줄 171자).
- 확인함(로컬 Oracle, 동주 11/19): SQL Developer에서 실행해 `ROW_COUNT` 34, `LATEST_DATE` 2026-10-31, 최근 값 3(%)이 나왔다.
- 확인 못 함: 같은 파일을 두 번 실행해도 34행인지(MERGE 재실행), 공용 DB 적용.

## 다음 사람이 알아야 할 것
- **원자료:** 한국은행 ECOS 1.3.1 한국은행 기준금리 및 여수신금리 > 한국은행 기준금리, 주기 월(2026-11-19 내려받음). 원본 CSV는 저장소 밖 `C:\workspace\data_raw\public_stats\`에 있다.
- 월 값은 그 달 마지막 날로 넣었다. 새 달 값이 나오면 같은 형식으로 행을 더해 다시 실행하면 된다(MERGE).
- **FP-153의 나머지 표는 이번에 넣지 않았다.**
  - `FACT_HFS_STAT`·`FACT_HFS_WORKER_STAT`: N-15 동년배·같은 직군 비교는 공공통계 대신 **서비스 회원 표(소득·자산·대출)에서 평균을 계산**하는 방향으로 검토 중(동주 11/19). 공공통계에는 프리랜서 구분이 없고, 회원 데이터로 계산하면 세 직군이 추정 없이 다르게 나오기 때문이다. 광희(N-15 API)와 합의가 필요하고, 정해지면 `features.md` N-15-2("공공통계에서 가져온다") 수정도 필요하다.
  - `FACT_INDUSTRY_AGE_INCOME`: 쓰는 기능이 없어 비워 둔다(광희 확인).
  - 참고로 더미 회원 400명은 20대가 60%이고 30대 이상 평균 부채가 19만~107만 원으로 거의 0이다. 회원 평균으로 비교할 때 화면에서 어색해 보일 수 있다(더미 데이터 담당에게 공유 필요).
