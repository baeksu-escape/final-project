- **날짜:** 2026-11-14
- **작성자:** 경환 / Codex

- **관련 N-ID:** N-24-2·3·4·5
- **관련 결정:** C조 동주의 정적 JSON 전환 전달과 사용자의 상권 5개 표 제거 승인

## 무엇을, 왜 바꿨나
- 상권 분석은 DB·API 없이 프론트 정적 JSON을 사용하므로 상권 전용 표를 기준 DDL에서 제거했다.
- 신용모델·회원·평가·직군 공공통계 구조와 기존 회원 시드 값은 유지했다. C8 지도 코드 열은 추가하지 않는다.

## DB·API 변경
- DB에서 제거한 표는 `DIM_ADM_DONG`, `DIM_SERVICE_CATEGORY`, `FACT_DONG_SALES`, `FACT_DONG_STORE`, `FACT_DONG_LIVING_POP`이다.
- 다른 기능용 `FACT_HFS_STAT`, `FACT_HFS_WORKER_STAT`, `FACT_INDUSTRY_AGE_INCOME`, `FACT_POLICY_RATE`는 유지한다.
- N-24는 프론트 `frontend/public/data/market/`의 JSON을 사용한다. 이 파일들은 C조 브랜치에서 제공하며 이번 작업에서 프론트 코드는 수정하지 않았다.
- 기존 DB용 삭제 SQL은 자식 표부터 순서대로 처리하고 없는 표는 건너뛴다. `CASCADE CONSTRAINTS`·`PURGE`는 쓰지 않으며 자동 적재 경로에 연결하지 않았다. 기존 DB에서 해당 표에 데이터가 있으면 그 데이터도 삭제된다.
- API 구현 변경은 없다. 영향을 받는 담당은 N-24·C조와 DB 담당이다.

## 확인
- 확인함: 원격 develop `8303c69`가 현재 HEAD에 포함되고 수정 전 작업 트리가 깨끗했다.
- 확인함: `test_market_schema.py` 고정 예제 5개, 기존 `test_no_loan_schema.py` 회귀 검사 5개 통과(Python 3.14.7). 빈 예제를 메모리에서만 처리했으며 회원 원천·시드를 재생성하지 않았다.
- 확인함: 기존 HEAD와 DDL 정의를 대조해 승인한 5개 표만 제거됐고 나머지 46개 표 정의·기준 INSERT는 동일했다.
- 확인함: 제거한 표를 제외한 생성 보고서의 기존 필드·시드 행 수는 동일하다. 문서 로컬 링크 17개와 CRLF 허용 공백 검사 통과.
- 확인함: Claude 읽기 전용 로직 검수에서 치명·높음 문제 없음. 외부 API 초안의 DIAG-10·11 상권 API 표기가 아직 이전 DB 방식이라는 지적은 아래 인수인계에 남겼다. Claude는 코드·문서를 읽었으며 테스트·Oracle 실행은 하지 않았다.
- 확인 못 함: 실제 Oracle 삭제·재실행, 전체 데이터 재생성·전체 테스트는 최종 점검에서 진행할 항목이다.

## 다음 사람이 알아야 할 것
- 소스 DDL 수정만으로 기존 Oracle의 상권 표가 삭제되지는 않는다. 전용 삭제 SQL을 대상 스키마에 별도 적용한다.
- 현재 초기화 묶음은 46개 표만 다루므로 옛 상권 표를 지우는 데 `run_all.sql`을 사용하지 않는다.
- 과거 작업 로그와 11/13의 51개 표 적재 확인은 당시 이력으로 유지한다. 새 46개 표 개정본의 Oracle 실행 확인과 혼동하지 않는다.
- 범영의 외부 API 아티팩트에는 DIAG-10·11 상권 API와 제거된 표가 남아 있어 문서 담당자가 정적 JSON 전환을 반영해야 한다. 이번 작업에서 외부 문서를 수정하거나 메시지를 보내지는 않았다.
- 이 브랜치에는 C조의 상권 JSON이 아직 병합되지 않았다. N-24 화면의 실제 데이터 연결 검증은 해당 파일 반영 후 진행한다.
