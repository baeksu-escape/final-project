# 대안 모델 SHAP 요인 추출·포맷팅 모듈 (training/explain.py)

- **날짜:** 2026-11-17
- **작성자:** 최재욱(B팀 모델·정의서 담당) / Claude Code
- **브랜치:** `feature-B/FP-138-shap-factors`
- **관련 N-ID:** N-14(영역별 영향도 SHAP), N-12-2
- **관련 Jira:** FP-138(SHAP 요인 추출 및 포맷팅 모듈). 서비스 연결은 FP-141(범영 님)
- **관련 결정:** 점수 환산 명세서 O-3, 순위 규칙 DDL `FEATURE_RANK` 주석(11/13 범영 확정), 정의서 10장 C22

## 무엇을, 왜 바꿨나
- 서비스 ML-03 응답의 `shap`(기준점 + 항목별 SHAP 점수)을 지금은 Mock(고정 가중치)이 만든다. 학습한 대안 모델에서 같은 형식으로 만들어 주는 모듈을 `fastapi_server/training/explain.py`에 추가했다. 서비스 연결(Mock 교체)은 하지 않았다(FP-141).
- 형식과 규칙은 Mock과 같다: `{baseScore, factors[{rank, featureCode, featureValue, shapValue, shapScore}]}`, `baseScore + Σ shapScore = 대안 점수`, 순위는 |shapScore| 내림차순·동률은 항목 이름 가나다순.
- 계산: `shap.TreeExplainer` 기본값, SHAP 점수 = −FACTOR × SHAP(log-odds), 기준점 = `expected_value`의 점수 환산. 정수 반올림은 합이 점수와 같도록 최대 잉여 방식(점수가 0·1000으로 잘려도 합 규칙 유지).
- 기존 모델·시뮬레이터 재계산용으로 SHAP 없이 점수·불량 확률만 구하는 `score_one`도 넣었다. 등급은 만들지 않는다(D-01 팀 결정).

## DB·API 변경
- DB: 없음
- API: 없음. 서비스 응답(ML-03) 형식은 Mock 그대로이며 값만 진짜 모델에서 나온다(FP-141에서 연결할 때).
- 영향을 받는 기능·팀원: 범영 님(FP-141): `AlternativeExplainer`를 서비스 시작 때 한 번 만들고 `explain(build_features(...))` 결과를 응답에 끼운다. 기존 파일은 수정하지 않았다.

## 확인
- 확인함: FastAPI 테스트 85개 통과(기존 68 + 새 17). 저장한 `artifacts/alternative.joblib`에서 `expected_value + Σ SHAP = raw margin`이 6자리까지 일치. 합성 요청 6건(직군 3종, 위험·양호·결측 입력)에서 `baseScore + Σ shapScore = 점수`가 모두 성립하고 factors 키가 Mock과 같음. 위험 입력의 최대 감점이 `DQ1200001`(연체 6건, −88점)로 직관과 맞음. 설명기 생성 약 0.2초.
- **주의(결과 해석):** 기준점은 694점(Mock은 시연용 639점). 모델 한계(AUC 약 0.65)로 "양호"로 만든 입력이 기준점(694)보다 낮은 659점이 나오는 등 직관과 어긋나는 결과가 있다. 같은 입력에서 기존 모델과 대안 모델 점수가 크게 다른 경우도 있다(프리랜서 입력: 기존 779, 대안 644). 두 모델 점수 상관이 0.27이다. 코드 문제가 아니라 모델·라벨 차이이며 정의서 2-1·C20에 설명이 있다.
- 확인 못 함: 서비스 연결(FP-141, 범영 님), 요청마다 SHAP을 계산할 때의 응답 시간, 다른 PC에서의 재현, 등급 경계(D-01).

## 다음 사람이 알아야 할 것
- SHAP은 모델이 쓴 기여도이며 인과관계가 아니다. 화면에는 "작용한 정도"로만 보여 준다.
- `training/explain.py`의 O-3 상수(PDO·FACTOR·OFFSET)는 `pipeline/mock_scorer.py`와 같은 값이다. 시험이 두 곳이 같은지 검사하니, 한쪽만 바꾸면 시험이 실패한다.
- FP-141에서 Mock을 교체하면 `mock_scorer.py` 상수와의 비교 시험은 새 위치에 맞게 고친다.
- 로그 파일명의 작성자 약어 `cjw`는 제안이다.
