# FP-203 저장 데이터 조회 API를 로그인 회원 기준으로 변경 (userId 쿼리 제거) + 입력 검사 보강

- **관련 결정:** 없음 (임시 개방 경로를 닫는 것은 A조 협의 예정)

## 무엇을, 왜 바꿨나
- `GET /api/diagnosis/income-volatility`, `GET /api/diagnosis/cash-flow/forecast`가 주소의 `?userId=`를 그대로 믿고 조회했다.
- `/api/diagnosis/**`가 임시 개방 경로라 로그인 없이 숫자만 바꿔 남의 소득·지출·원리금을 볼 수 있었다(IDOR).
- 이제 회원 번호는 로그인 토큰(`@AuthenticationPrincipal AuthUser`)에서만 꺼낸다. 토큰이 없으면 401 `UNAUTHORIZED`다.
  - A조·범영 님 컨트롤러와 같은 방식이다.
- JWT 필터는 임시 개방 경로에서도 실행되므로, 공통 설정(임시 개방 목록)은 건드리지 않고 광희 님 파일만 고쳤다.

## DB·API 변경
- DB: 없음
- API: GET 2개의 요청에서 `userId` 쿼리를 없앴다(보내도 무시). 응답에 `401 UNAUTHORIZED`가 추가됐다. 경로·응답 필드는 같다.
- API (추가): 예측 기간 `forecastMonths`는 3·6·12만 받는다(없거나 0이면 6, 그 밖은 400). POST 계산 API에 빈 본문을 보내면 200 대신 400이다. 명세 N-21-2(예측 기간 3·6·12개월)에 맞춘 것이다.
- 영향을 받는 기능·팀원:
  - 이 API를 붙일 화면(경환 님 FP-94·96, 동주 님 FP-202)은 `?userId=` 없이 로그인 상태로 부르면 된다.
  - 프론트 함수 인자가 바뀌었다: `getIncomeVolatility()`, `getCashFlowForecast(condition)`. 지금 호출하는 화면은 없다.
