# 학습 데이터 v3.7.0: 전체 행 사용, 연체 라벨 재설계, 소득·지출 생성 규칙

- **날짜:** 2026-11-26
- **작성자:** 최재욱(B팀 모델·정의서 담당) / Claude Code
- **브랜치:** `feature-B/label-v37` (Jira 키 확정 전 임시 이름)
- **관련 N-ID:** N-12-2(점수 모델 학습), N-25(모형 성능 비교)
- **관련 결정:** 11/26 팀 회의(연체 라벨을 상식에 가깝게), 팀 확정(효과 크기·기준), 데이터 생성기 수정 담당 재욱. 정의서 10장 C32(데이터)·C33(모델 0.3 사전 기준)

## 무엇을, 왜 바꿨나
- 연체 라벨이 대출 잔액·소득·상환 부담과 무관해 대출이 늘어도 점수가 오르는 사례가 있었고, 상환액>소득 7.1%·12개월 적자 20.2% 같은 값이 있었다.
- 교육용 합성 원본 155,746행 중 직군 해당 139,347명을 모두 쓰고, 연체 라벨에 가정 효과를 더하고, 소득·지출 생성 규칙을 바꿨다. 대출 원장은 그대로다.
- C32·C33은 코드를 고치기 전, 모델 결과를 보기 전에 기록했다.

- 없음. 서비스 시연 회원·외부 API 더미 출력은 바뀌지 않는다.

## 확인
- 확인함(저장소 밖 복사본, Python 3.11.9 + requirements.txt 고정 버전):
  - 전체 생성 후 `verify`, `verify_thinfile`, `verify_thinfile_general`, `verify_nonfinancial_sources`, `verify_input_features_6m`·`12m`, `verify_data_split`, `verify_delinquency_label` 통과. C32 데이터 확인 기준 18개 항목 PASS(양성 9.95%, 설계 AUC 0.772, 6개월 이상 적자 18.4%, 월소득 중앙 335만 원 등).
  - 서비스 더미 18개 파일이 수정 전 코드 출력과 바이트 단위로 같음. `base_207`이 원본과 같음. 씬파일 분할이 v3.6.1과 같음. 새 규칙을 끈 `extend` 결과가 수정 전 코드와 같음.
  - 분할 TRAIN 97,543 / VALID 20,903 / TEST 20,901, 이전 12,000명은 모두 TRAIN.
  - 전달 묶음의 열 구성이 v3.6.1과 같고 학습 코드가 읽음. `data_generation` 테스트 112개 중 110개 통과(2개는 Windows 심볼릭 링크 권한 오류, 수정 전과 같음), `fastapi_server` 테스트 229개 통과(지금 `data/training` 기준).
- 확인 못 함:
  - `verify_statistics`는 실패한다. 통계 원자료 CSV의 줄바꿈(CRLF) 때문에 해시만 다르고 값은 같으며 이번 변경과 무관하다.
  - `verify_loan_extension`·`verify_assumption_sensitivity`·`verify_nonfinancial_experiment`와 해당 생성·실험은 실행하지 않았다.
  - 모델 학습·평가, TEST.
