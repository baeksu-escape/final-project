# N-16 자산·부채 저장값 조회 API (DIAG-03-1)

- **날짜:** 2026-11-20
- **작성자:** 임광희(C팀) / Claude Code
- **브랜치:** `feature-C/FP-239-financial-health-base` (Jira FP-239, FP-165 하위)
- **관련 N-ID:** N-16-1 건전성 지표, N-16-2 위험 단계, N-16-4 보유 대출 표
- **관련 결정:**
  - 저장 데이터를 읽는 API는 `/api/members/me/**`에 둔다(FP-170 11/19, 우찬 님 합의).
  - 미입력은 0원으로 바꾸지 않는다(O-15 A안).
  - 경환 님 요청(11/20): 응답에는 저장값만 넣고, 같은 직군 평균(`peer`)은 화면이 DIAG-01에서 붙인다.

## 무엇을, 왜 바꿨나
- 자산·부채 건전성 화면(경환)은 지금 화면이 가진 값을 DIAG-03 POST(FP-166, DB 안 읽음)에 보내 계산한다. 회원의 **저장값**을 돌려주는 API가 없었다(FP-166 로그의 "DB 조회 연결은 범위 밖").
- `GET /api/members/me/financial-health`를 추가했다. 정의서 DIAG-03-1의 옛 경로 `GET /api/diagnosis/health`를 대신한다.
  - 응답: 기준월, 총자산, 연소득, 총부채, 연 원리금, 보유 대출 목록(필드 이름은 화면 adapter와 같음)
  - 비율·위험 단계는 넣지 않는다. 화면은 이 값으로 기존 DIAG-03 POST를 부른다.
- 미입력 규칙(동주 님 DIAG-01과 같음)
  - 총자산: 자산 행이 없거나 NULL이면 `null`
  - 총부채·연 원리금: 대출 행이 있으면 합계, 없고 `NO_LOAN_YN='Y'`(해당 없음)면 0, 둘 다 아니면 `null`
  - 연소득: 기준월 포함 최근 12개월(달력)이 모두 있을 때만 `calculateAnnualIncome`(N-20-3)으로 합한다. 자영업자·프리랜서가 빠진 달이 있으면 `null`이다. 일부 합으로 연소득이 낮게 보이면 상환 부담률이 높게 나오기 때문이다. 급여소득자는 소득 이력 함수가 월급을 12개월로 펼쳐 주므로 월급 × 12다.
- DB를 읽지 않는 계산 전용 `FinancialHealthService`는 그대로 두고, 저장값을 읽는 서비스를 따로 만들었다(`MemberFinancialHealthService`).

## DB·API 변경
- DB: 없음(기존 표 `USER_INCOME_MONTH`·`USER_ASSET_SNAPSHOT`·`USER_LOAN`·`DIM_LOAN_TYPE` 읽기만)
- API: `GET /api/members/me/financial-health` 추가. 정의서 DIAG-03-1 행 갱신(경로, 🟡 → ✅)은 PR 본문에 적어 범영 님이 반영한다.
- 영향을 받는 기능·팀원: 경환 님 자산·부채 화면. 연결은 경환 님이 한다.
