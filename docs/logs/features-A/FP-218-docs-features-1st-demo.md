## 확인
- 확인함
  - 1단계 코드 확인 결과
    - 로그아웃: `AppHeader.handleLogout`가 `window.location.replace(PATHS.HOME)`(`/`)으로 보낸다.
    - 탈퇴: `WithdrawalCard`가 `logout({ notice })` 뒤 `AUTH_PATHS.LOGIN`으로 보낸다.
    - 관리자 2단계 인증: `AdminAuthService`가 `EmailCodeSender`로 관리자 이메일에 보내고, AUTH-01 응답에는 `maskedEmail`(가린 이메일)만 담는다. 기존 ⚠️ 줄의 "휴대폰"은 틀린 내용이라 정정했다.
    - 가입 동의: FP-219 `SignupPage`의 동의 체크는 `(필수) 개인신용정보 수집·이용` 1개다. 서버(`AuthRequests.Signup` 주석)는 이 체크로 필수 2개(이용약관·개인정보)를 함께 기록하고, `agreeMarketing`은 화면에 없어 미동의로 기록한다. 기존 ⚠️ 줄의 "필수 2개 + 선택 1개"를 정정했다.
    - 가입 규칙(FP-219 `validation.js`·`AccountRules.java`)
      - 이름 `^[가-힣]{2,20}$`
      - 닉네임 `^[A-Za-z0-9가-힣]{2,7}$`
      - 휴대폰 화면 접두 `010`
      - 생일 범위 `1930-01-01`~`(올해−20)-12-31`, 서버는 출생연도 1930~(올해−20)
      - 지시서 문구와 같다.
    - DB 상한: DDL `CK_APU_BIRTH_YEAR`는 `BETWEEN 1930 AND 2006`이다(주석에도 "최종 검사는 Spring에서").
    - 메인: develop `landingExample.js`는 640(CAUTION)·778(STANDARD), 경계 665·780이고, 차이는 화면에서 계산한다.
    - 휴대폰 발송 설정: FP-219 `AvenueProperties.PhoneMode { LOG, FIXED }`. 이메일은 `EmailMode { LOG, FIXED, SMTP }`라서, N-02-3 줄은 휴대폰만 "문자로 보내지 않는다"고 적었다.
