## 무엇을, 왜 바꿨나
- 시뮬레이터는 프론트 mock만 있었다. 이번에 Spring이 FastAPI ML-04를 실제로 부르게 했다(SIM-02). 슬라이더의 처음 값을 주는 SIM-01도 새로 만들었다.
- 출발 평가는 점수가 나온(SCORED) 최근 평가다.
  - 최신 평가가 MODEL_ERROR 등으로 산출 불가여도 그 앞의 SCORED 평가를 쓴다.
  - SCORED 평가가 하나도 없을 때만 404 `ASSESSMENT_NOT_FOUND`다.
  - 저장된 피처값은 서버 안에서만 쓰고, 화면에는 입력 10개 값만 보낸다.
- 현금흐름 화면의 [예상 점수]용 DIAG-09를 만들었다.
  - `ScoreInputAssembler.build()`로 요청을 만들고 소득·지출만 바꾼 뒤 `PredictionClient.score()`를 한 번 부른다. 저장하지 않는다.
  - 사용자 선택 4건:
    - 소득은 전망 식을 과거 달마다 적용한다.
    - 고정지출은 FIXED 항목을 비율대로 조정한다.
    - 납부 상태는 아직 점수에 반영하지 않는다.
    - 비교 기준은 저장된 최근 SCORED 점수다.
- 실패하면 저장하지 않고 화면에 알린다.
  - ML-04: 422 → 400, 409 → 409, 그 밖 → 503
  - ML-03(DIAG-09): 4xx → 400, 그 밖 → 503

## DB·API 변경
- DB: 테이블·컬럼 변경 없음. 읽기 쿼리 1개(`selectLatestScored`)를 추가했다.
- API (모두 새로 추가, 기존 경로·필드 변경 없음):
  - `GET /api/simulation/credit-care/base` (SIM-01): 응답 모양은 이번에 처음 정했다. 목록·상태는 PR 본문에 적어 범영 님이 [API 정의서](../spec/api/api_definition.md)에 반영한다.
  - `POST /api/simulation/credit-care/recalculate` (SIM-02): Spring 구현. 계약은 기존 api_spec 제안 그대로다.
  - `POST /api/diagnosis/cash-flow/expected-score` (DIAG-09): 응답 모양은 이번에 처음 정했다(🟡).
- 영향을 받는 기능·팀원:
  - 범영 님: PredictionClient·AssessmentMapper에 추가했다. PR 리뷰어로 지정한다.
