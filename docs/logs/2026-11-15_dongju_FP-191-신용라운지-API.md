Spring 빈 이름이 겹쳐 서버가 켜지지 않아서, 신고 쪽을 `CommunityReportController`·`CommunityReportService`(테스트 `CommunityReportServiceTest`)로 바꿨다. URL `/api/reports`와 동작은 그대로다. 병합 후 `./mvnw clean test` 265개 통과.
- **11/17 PR 검토 반영:**
  - COMM-03·04 글 본문에 1300자 제한 추가(`@Size`, 넘으면 400 `INVALID_INPUT`, 화면 `maxLength`·mock도 같은 값). 본문도 제목·댓글처럼 앞뒤 공백을 지우고 저장한다.
  - **DB 변경 — 본문 열 CLOB → `VARCHAR2(1300 CHAR)`** (팀 의견, 동주 11/17 A안 결정)
    - 이유: CLOB 대신 일반 문자열로 두면 검색(`LIKE`)과 매퍼(`jdbcType=CLOB` 제거)가 단순해진다. Oracle 기본 설정에서 VARCHAR2는 4000바이트까지이고 한글은 1자 3바이트라, 처음 정한 3000자 대신 1300자(한글만 써도 3900바이트)로 줄였다. DB 설정 `MAX_STRING_SIZE=EXTENDED`는 모든 DB에 적용해야 하고 되돌릴 수 없어 쓰지 않았다.
    - 바뀐 파일: `avenue_ddl.sql`(C9 이력·열·COMMENT) + 사본 `dummy_db/01_create_tables.sql`, `dummy_db/seed_report.json`의 `ddl_sha256`, 새 파일 `alter_board_post_content_varchar2.sql`, `docs/spec/sql/README.md` 경로 표 1행, `BoardMapper.xml`, `BoardDtos.java`, `CommunityApiContractTest.java`(1300자 통과·1301자 400), 프론트 `communityCodes.js`(`CONTENT_MAX`).
    - 기존 DB: CLOB 열은 바로 VARCHAR2로 바꿀 수 없어(ORA-22859) alter 파일이 새 열 추가 → 복사 → 기존 열 삭제 → 이름 변경 순서로 바꾼다. 1300자를 넘는 글이 있으면 자르지 않고 멈춘다. `CONTENT`는 표 맨 뒤 열이 된다(매퍼는 이름으로 읽어 영향 없음). 시드의 `BOARD_POST`는 0행이라 시드는 다시 만들지 않았다.
    - 공용 DB 적용은 DB 담당에게 알려 순서를 맞춘다. 범영(API 정의서): COMM-03·04 본문 최대 1300자.
  - 같은 사람이 거의 동시에 두 번 신고해 DB 유니크 인덱스(`UX_CRP_REPORTER_*`)에 걸리면 500 대신 409 `DUPLICATE_REPORT`로 답한다.
  - ADM-14 조회에서 DB 값을 못 읽으면 최솟값(3) 대신 서버가 실제로 쓰는 기본값(5)을 보여 준다(`EditableSettings.Rule`에 기본값 추가).
  - 그대로 두기로 한 것(동주 11/17): 글을 지워도 그 글의 미처리 신고는 남는다(관리자 상세에 '삭제됨'으로 보이고 처리 가능). 하루 신고 횟수와 관리자 처리 중 새 신고가 함께 닫히는 경우는 동시 요청일 때만 생기고 영향이 작아 막지 않았다.

  - 본문 열 변경 뒤: `./mvnw clean test` 273개 통과, `npm run lint` 통과, DDL 도구 테스트 52개 `OK (skipped=3)`, DDL 사본 `cmp` 일치. 동주 로컬 Oracle에서 alter 파일 실행 후 `CONTENT VARCHAR2 1300 C N` 확인(11/17). 빈 스키마에 새 DDL 전체 실행과 글 작성·수정 화면 확인은 아직 안 함.
