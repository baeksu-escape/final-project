## DB·API 변경
- DB: 없음 (실행 계획 SQL은 읽기·통계 갱신만)
- API: 없음. 오류 응답 모양·문구 그대로이고 서버 로그만 늘어남
- 영향을 받는 기능·팀원: 모든 API의 오류 로그(우찬 님 공통 파일 — 리뷰 요청), 정의서를 보는 전원

## 확인
- **E2E 자동 점검(로컬 DB, `LGBM-BASE-0.1`, demo_employee): PASS 15 / FAIL 0.** 실제 모델·SHAP 38개·피처 칩 18/38, 같은 requestId 재요청 시 같은 결과, 시뮬레이터·예상 점수는 진단 내역을 늘리지 않음
- **실행 계획(로컬 DB, ASSESSMENT 22행·ASSESSMENT_FACTOR 763행):** requestId 조회 `INDEX UNIQUE SCAN`(UK_ASM_REQUEST_ID), SHAP 요인 `INDEX RANGE SCAN`(UK_ASF_RANK). 최신 평가·진단 내역·점수 보유 여부는 22행이라 `TABLE ACCESS FULL`(정상). 통계를 10만 행·회원 1만 명으로 가정하면 최신 평가 쿼리가 `INDEX RANGE SCAN`(IX_ASM_USER_ASSESSED)으로 바뀜 → **인덱스 추가 불필요.** N-25 표본은 별도 표라 `ASSESSMENT`에는 서비스 회원 평가만 쌓임
- **백엔드 전체 테스트 392개 통과**(`./mvnw test`). 새 로그 예: `API 오류 409 DUPLICATE_NICKNAME POST /api/members/me/__test/conflict`, `처리하지 못한 오류: java.lang.IllegalStateException at SecurityTestController.boom:59 (POST …)`
- 정의서·명세서 상대 링크 41개 검사 → 깨진 링크 0
- 확인 못 함: 수동 점검 M-01~06(FastAPI 끈 상태, 새 회원가입 전체 흐름 등)은 화면으로 따로 해야 함

## 점검 중 발견한 것
- 로컬 DB의 `demo_employee` 월급이 **24,046,340원(오타)**이라 예상 점수가 크게 틀어졌다 → 화면에서 2,404,634원으로 고침. 공용 DB 시연 계정도 같은 오타가 있는지 확인 필요.
- 고친 뒤에도 모델 방향이 상식과 다른 작은 사례가 남음(지출 2배 +11점, 카드 사용률 95%가 10%보다 높음, 카드 정보 없음이 가장 낮음). 연동 문제가 아니라 모델 학습 방향 문제 → 재욱 님께 사례 표 전달, 단조 제약(monotone_constraints) 시험 후 `LGBM-BASE-0.2` 채택 여부 결정(11/27 전).
