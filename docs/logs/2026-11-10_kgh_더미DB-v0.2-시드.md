# v0.2 별도 더미 DB 생성기·시드 검사

- **날짜:** 2026-11-10
- **작성자:** kgh / Codex
- **브랜치:** `KGH_Work`
- **관련 N-ID:** N-02-4, N-05-2~6, N-12, N-18, N-37
- **관련 결정:** 승인된 v3.6.0 계획 4절 B안. 미확정 대출은 사용자 추가 승인으로 `OTHER`·`UNKNOWN`. 급여 소득은 기준월 1행, 지출 FIXED 1행, 평가 시드는 비움.

## 무엇을, 왜 바꿨나
- 옛 DB 묶음을 보존하면서 받은 v0.2 46테이블 DDL 기준의 새 생성기를 추가했다. `message.txt`는 머리말에 이미 출처·날짜·초안 표시가 있어 바이트 그대로 복사했다.
- DDL 타입·길이·CHECK의 NULL 처리·PK·UNIQUE·복합 FK·조건부 UNIQUE INDEX 및 원천 대조를 모두 통과해야 SQL을 쓴다. 옛 DB 폴더로 출력하는 동작도 거부한다.
- AES-256-GCM/HMAC 규격을 구현했다. 개발 키가 없어 고정 공개 테스트 키로 임시 폴더에서만 전체 시드를 생성했다. 커밋용 키는 선택하지 않았고 개인정보 시드를 저장소에 복사하지 않았다. 저장소 `run_all.sql`은 생성 전 실행을 막는다.
- 3단계 교차 검수 반영: 미동의 회원 대출을 MANUAL로 보존하고 전 회원 상환 합계를 대조한다. 동의는 응답 status가 아닌 members.csv의 external_data_consent로 판단한다. 옛 DB DROP 가드·HMAC 최소 32바이트·한글 복구·점수대별 더미 범위도 반영했다.

## DB·API 변경
- 새 `v0_2` 묶음만 추가했다. 옛 생성기·SQL·README 20개 파일은 시작 전 해시와 모두 같다. API 변경 없음. 학습·버전·manifest·handoff 파일은 w8 담당이며 수정하지 않았다.
- 기준월은 임시 2026-08(TODO(D-16)). 회원별 지출·대출·자산은 한 세트다. 대출 월 상환액은 원천 기준월 합계를 원장 연 상환액 비중으로 정수 배분해 합계를 보존한다.
- 공과금 테이블은 DDL 개정 후 추가 예정이다. 기존 공과금 원장·응답은 그대로 두고 이번 SQL 적재에서만 제외했다. `map_bill_rows()`는 개정 후 재사용할 수 있다.
- 영향을 받는 기능·팀원: N-02-4 개인정보(인증·백엔드), N-05 입력·외부 데이터와 N-16·N-20 상환 계산(입력·DB·FastAPI 담당), N-12·N-37 참고 금리/한도(리포트·상품 담당). 학습 데이터·manifest·배포 묶음은 w8이 최종 통합한다.
- 받은 USER_LOAN DDL에는 CONSENT_ID 열이 없어 DDL을 고치거나 존재하지 않는 열을 시드에 넣지 않았다. 개정 DDL에 열이 생기면 MANUAL은 NULL, IMPORTED는 LOANS 동의 ID를 연결한다.

## 다음 사람이 알아야 할 것
- 커밋용 개인정보 시드 키 운영은 미정이다. README에 개인 개발 키로 로컬 재생성 또는 별도 보관소의 공유 개발 키 운영을 제안만 했다. 테스트 키 SQL은 임시 폴더에만 있으며 저장소에는 없다.
- 카드 한도·재직/활동 기간·로그인 비밀번호 해시 원천이 없어 NULL로 뒀다. 원천 또는 시연 로그인 방식은 담당 팀 결정이 필요하다. 임의의 값·가짜 해시를 넣지 않았다.
- 설치는 기존 데이터 생성 가상환경에 승인된 cryptography 50.0.2와 전이 의존성만 추가했다. 상위 FastAPI requirements·환경설정/비밀값 파일은 읽거나 수정하지 않았다. manifest와 버전 갱신은 w8이 마지막에 한다.

- 최종 문서 검수 반영(2026-11-10, 사용자 승인): 저장소 99_check.sql의 USER_LOAN 기대값을 203으로 동기화하고 전체 원천 테스트에서 DROP·99_check 생성본과 저장소본 바이트 동등성을 검사했다. 최종 서비스 더미(genF) 지정 DB 테스트 17건 통과. SERVICE_DUMMY_DATA 앞쪽·검사 표도 기관 응답 전원 OK / external_data_consent는 시작 상태 / 동의 확인은 목 서버 요청 시로 통일했다. Oracle 실제 적재는 미확인, 키·개인정보 시드는 저장소에 추가하지 않았다.
