- `final_test_eval.py`에 `--version`을 넣어 0.3 설정(C35 범위, 후보 등급 경계, C34 해시 대조, 별도 기록·결과 파일)을 추가했다. 기본값은 0.2다.

## 추가 변경: 단조 제약 4개 (같은 날, C36~C38)
- 서비스 점검(TEST 미사용)에서 시뮬레이터의 대안 데이터 값을 나쁜 쪽으로 바꿨는데 대안 점수가 오르는 회원이 있었다(통신 21명, 공과금 9명, 간편결제 118명 / 시드 318명).
- 재욱 결정으로 `telecom_late_months`(+1)·`telecom_on_time_streak`(−1)·`utility_late_months`(+1)·`dp_payment_count_12m`(−1)을 v03에 더했다(19개). C36을 먼저 기록한 뒤 모델을 다시 만들었다. **VALID와 시드 결과를 본 뒤의 변경**이고, 간편결제 건수의 방향은 라벨 설계가 아니라 정책 결정이다.
- 새 VALID 결과(C37): 11개 항목 통과, 대안 AUC 0.7383, 비금융 대안−기존 +0.0190, 점검 사례 216 / 722 / 757, 등급 경계 후보 644 / 712. TEST 기준은 C38. C34·C35는 이전 모델의 기록으로 남긴다.
- 바뀐 파일: `training/config.py`, `final_test_eval.py`(C38·C37 해시 행), 테스트 2개, 학습 README, 정의서 C36~C38, `docs/spec/model_v03_valid_check_c36.json`.
- 확인함: FastAPI 테스트 250개 통과, 0.3 VALID 리허설에서 C38 기준값 4개 "같음", 서비스 코드 경로(불러오기·ML-01·02·03·04)와 시드 318명 점검에서 시뮬레이터 9개 항목의 반대 방향 0명.
- 남은 것: 간편결제 월 30→0건의 영향이 시드 평균 −57.5점으로 커졌다(이전 −5점). 서버 등급 구간은 아직 CUT-0.3이라 모델 전환 때 CUT-0.4를 함께 바꿔야 한다.

## TEST 평가 (11/27, C39)
- `python -m training.final_test_eval --version 0.3 --split TEST --confirm-test-once`를 커밋 `f200cf5`에서 **한 번** 실행했다. 위 "확인 못 함"의 TEST는 이 실행으로 확인했다.
- 판정 대상 AUC가 모두 C38 정상 범위 안이다: 기존·연체 0.6835, 대안·비금융 0.7480, 대안·연체 0.6821, 기존·비금융 0.7290. 같은 라벨 대안−기존은 연체 −0.0015, 비금융 +0.0190.
- 결과 `docs/spec/final_test_eval_result_v03.json`·`.md`, 실행 기록 `final_test_eval_run_v03.json`. 모델·데이터·기준은 바꾸지 않았다.

## 다음 사람이 알아야 할 것
- **TEST는 이미 실행했다. 다시 실행하지 않는다**(평가 코드 오류를 고친 재실행만 `--rerun-reason`으로). 모델이나 데이터를 고치려면 새 버전으로 만들고 이 TEST로 평가하지 않는다.
- 모델 파일은 로컬 `fastapi_server/data/model_v03/`(Git 제외)에 있고 해시는 **C37**에 있다. 다시 학습해 덮어쓰면 설명 파일의 시각이 달라져 해시 대조에서 멈춘다. 이전(C34) 모델은 `data/model_v03_c34/`에 있다.
- 비금융 효과 라벨에서 대안의 우위는 +0.0190이다(0.2의 VALID는 +0.0511, 데이터·라벨이 달라 직접 비교하지 않는다).
