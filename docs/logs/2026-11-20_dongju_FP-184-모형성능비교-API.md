# 관리자 모형 성능 비교 API(ADM-01·02, N-25) 추가 — 평가 표본으로 컷오프별 지표·ROC·직군별 오거절률 계산

- **날짜:** 2026-11-20
- **작성자:** 동주 / Claude Code
- **브랜치:** `feature-C/FP-184-modelPerformance`
- **관련 N-ID:** N-25-1, N-25-2, N-25-3, N-25-4
- **관련 결정:** decisions.md N-25(지표 6개, 오분류 비용 = 오승인×5), 11/19 동주(집단 LEGACY·THINFILE만, 컷오프 600~800·기본 700), 피처 정의서 C20(같은 라벨끼리 비교), B팀 명세서 ML-03(DB의 ACTIVE가 스위치)

## 무엇을, 왜 바꿨나
- 관리자 「모형 성능 비교」 화면(FP-185)은 mock으로만 돌았다. B조가 평가 표본 표 `MODEL_EVAL_SAMPLE`(FP-235, 3,085행)과 같은 라벨 AUC(`METRICS_JSON.same_label_comparison`)를 넣어서, 이걸로 계산하는 서버 API를 만들었다.
- 응답 모양은 FP-185에서 정한 제안안(mock)과 같다. 단위만 팀 규칙에 맞췄다: 비율·ROC 좌표는 % 소수 둘째 자리(API README 3장), AUC는 0~1 확률(정의서 1장).
- 비교할 모델은 `MODEL_REGISTRY`의 ACTIVE 모델이다. 그 모델의 평가 표본이 없으면 "지금 상태로는 처리할 수 없음"이라 409 `MODEL_EVAL_NOT_READY`를 준다(B팀 명세서 용어집의 409 뜻).
- 계산은 Spring 서비스에서 한다. 한 집단이 최대 1,800행이라 요청마다 계산해도 충분하고, 결과를 저장하지 않는다.

## DB·API 변경
- DB: 없음(DDL·SQL 그대로). 읽기만 한다: `MODEL_REGISTRY`, `MODEL_EVAL_SAMPLE`, `DIM_WORKER_TYPE`, `MODEL_ARTIFACT`.
- API: 새로 구현
  - ADM-01 `GET /api/admin/model-performance?group=LEGACY|THINFILE&label=DELINQ|NONFIN&cutoff=600~800`(기본 LEGACY·DELINQ·700)
  - ADM-02 `GET /api/admin/model-performance/roc?group=&label=`
  - 새 오류 code 409 `MODEL_EVAL_NOT_READY`
- 영향을 받는 기능·팀원
  - 범영(정의서 관리·리뷰 검수): 11/20 새 규칙(PR #124 — 2장 API 행은 만든 사람이 수정, 1장 오류 code 표는 범영)대로 이 PR에서 2장 ADM-01·02 상태 ✅와 맨 위 최근 변경 7번만 고쳤다. 경로·원천·담당 FP-184는 FP-160 후속 PR #122에서 이미 반영됐다. **새 오류 code 409 `MODEL_EVAL_NOT_READY`는 1장이라 PR 본문에 적어 범영이 1장 표에 넣는다.**
  - 공용 DB(PR #124 규칙: SQL이 든 PR의 작성자가 병합 후 실행, 범영은 검수): 이 PR에는 변경 SQL이 없어 공용 DB 작업이 없다. API는 `MODEL_REGISTRY`의 ACTIVE 모델을 읽으므로 코드 수정 없이 모델을 따라간다. **공용 DB를 0.2로 바꿀 때(🆕 11/20, 0.2 전환 PR 작성자)** `create_model_eval_sample.sql`(표가 없을 때) → `load_model_eval_sample_lgbm_base_0_2.sql` → `update_model_metrics_same_label_lgbm_base_0_2.sql`까지 실행해야 이 화면이 나온다(0.2 등록·전환 SQL 다음). 표본이 없으면 409, 시드 평균이 없으면 LEGACY AUC가 `SINGLE_SEED`로 나온다. 0.1이 ACTIVE인 동안은 `…_0_1.sql` 두 개가 같은 역할이다.
  - B조(재욱): 모델을 다시 학습하면 새 `MODEL_VERSION`으로 평가 표본을 다시 적재해야 화면이 나온다.

## 확인
- 확인함: `./mvnw clean test` 전체 404개 통과(새 14개 포함, 실패 0).
- 확인함(로컬 Oracle, 동주 11/20): #99 표 생성·적재 후 화면에서 LEGACY·연체 라벨 표본 1,800명·불량 174명, AUC 0.605 / 0.599(5개 시드 평균), 컷오프 이동 시 지표·직군별 값·ROC 점 갱신.
- 확인 못 함: THINFILE 값을 B조 로그(1,285명·불량 122명, 연체 라벨 AUC 0.5712 / 0.5654 — 0.1 기준)와 대조, 공용 DB 적용.
- 🆕 11/20 0.2 맞춤: 로컬 DB를 0.2 ACTIVE로 바꾼 뒤 develop 병합. 코드는 ACTIVE를 읽어 그대로이고, 문서(정의서 ADM 행, `api_spec_c.md` 응답 예시·409 안내, 이 로그)만 0.2로 고쳤다. 0.2 기준 기대값: LEGACY·연체 라벨 AUC 0.6047 / 0.6078(5개 시드 평균), 표본·불량 수는 0.1과 같다(라벨은 모델과 무관).

## 다음 사람이 알아야 할 것
