# API 정의서·공용 DB 적용 방식 변경, FP-143 수동 점검 결과, 0.2 전환 SQL 문구

- **날짜:** 2026-11-20
- **작성자:** 오범영 / Claude Code
- **브랜치:** `feature-B/FP-238-api-docs-sync` (Jira FP-238)
- **관련 N-ID:** 없음(문서 운영)
- **관련 결정:** 11/20 범영 팀 공지 — ① 정의서 2장 API 행은 만든 사람이 기능 PR에서 고치고 범영은 리뷰에서 검수 ② 모든 변경 SQL(모델 전환 포함)은 PR 작성자가 병합 후 공용 DB에 실행하고 DB 변경 채널에 남김. DB 담당(범영)은 실행하지 않고 검수만

## 무엇을, 왜 바꿨나
- 지금까지는 API를 만든 사람이 알려 주면 범영이 정의서에 모아서 반영했다. 그래서 정의서가 코드보다 늦었다. 11/20 기준 DIAG-01(동주 #120)과 DIAG-04(광희 #118)의 경로가 옛 값으로 남아 있었다.
- 그래서 앞으로는 바뀐 내용을 가장 잘 아는 사람이 같은 PR에서 정의서 행을 고치고, 범영은 리뷰에서 검수한다. 1장 공통 규칙·오류 code 표·장 구성은 계속 범영이 관리한다.
- 공용 DB 적용도 같은 이유로 바꾼다. 변경 SQL을 만든 사람이 병합 후 공용 DB에 직접 실행하고, 채널에 정해진 양식으로 한 줄 + 답글 `공용 DB 적용 완료`를 남긴다. 범영은 실행하지 않고 PR 리뷰와 점검 조회로 검수만 한다. 모델 전환·등급 구간 ACTIVE 전환도 그 PR 작성자가 하되, 서버 모델 파일·코드와 시점을 맞춰야 해서 실행 전에 채널에 미리 알린다.
- FP-143 수동 점검 M-01~06을 병합 뒤에 마쳐 결과를 작업 로그에 남긴다.
- SQL 파일·문서 곳곳의 "공용 DB 실행은 DB 담당이 한다" 문구를 새 규칙("PR 작성자가 병합 후 실행")으로 모두 맞췄다. 머리말이 옛 규칙이면 파일을 연 사람이 헷갈리기 때문이다.
