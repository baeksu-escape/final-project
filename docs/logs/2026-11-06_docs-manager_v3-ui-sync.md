- **관련 결정:** D-01, D-05, D-06, D-09, D-10, D-11, D-12, D-14, D-21~D-27

## 무엇을, 왜 바꿨나
- 기능 명세서가 v1(통합)에서 v3(세부 기능 N-xx-n)로 바뀌었고, 11/06에 UI(Avenue 기능 데모 v2)가 확정됐다.
- 정리 원칙: **UI에 구현된 결정은 UI를 따르고**, UI에 없는 것은 v3를 따른다.
- 이 원칙으로 정한 주요 사항: 등급 Caution, 가산점 제거, 테마·카드 접기 유지(번호 미정), 개인정보 AES 암호화 저장, 지도는 네이버, 소득 12개월 필수(정보 부족 6개월 대신), 시연 계정 [채우기] 방식, 관리자만 2단계 인증.

## 확인
- 확인함
  - 시트 `기능 명세서 v3` 탭 A~K열과 `v2→v3 변경 내역` 탭을 읽고 옮겼다. 상위 기능별 세부 개수가 요약 표와 일치하는지 자동 검사했다(32개 모두 일치).
  - UI 코드에서 근거를 직접 확인했다: 등급 경계·이름, 메뉴 9개, 12개월 필수, 신고 5건·3~10건·하루 3번, 비밀번호·출생연도·동의 규칙, 5회 잠금, 관리자 2단계 인증, 위험 기준, 변동 계수 12%, 컷오프 550~750, 간이 예측 경로 없음.
  - 세 문서 사이의 D 번호 참조가 모두 `decisions.md`에 있는지 검사했다.
- 확인 못 함
  - 코드·SQL·데이터에 "Poor"나 가산점이 남아 있는지는 보지 않았다(md만 확인).
  - UI 아티팩트의 스타일과 상권 지도 문서 내부는 읽지 않았다.
