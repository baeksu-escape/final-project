# 회원 월 입력 기간을 6개월에서 12개월로 (데이터 v3.5.11 / 더미 DB v2.3)

- **날짜:** 2026-11-05
- **작성자:** kgh / Claude Code
- **브랜치:** `KGH_Work`
- **관련 N-ID:** N-22(소득 변동성 진단, 비수기 판별), N-05(데이터 입력), N-21(현금흐름 실적 12개월)
- **관련 결정:** 없음(새 결정: 회원 월 입력 12개월, 결정: kgh). `docs/ai/decisions.md` 반영은 문서 담당자에게 제안 예정

## 무엇을, 왜 바꿨나
- N-22 비수기 판별에는 12개월 소득이 필요하다. v3.5.7에서 6개월(2026-03~08)로 줄였던 회원 월 입력(소득·생활지출·상환액)을 최근 완결 12개월(2025-09~2026-08)로 늘렸다.
- 12개월을 다 입력하지 않으면 입력 부족(`INSUFFICIENT_INPUT`)이다. 더미 회원 400명은 모두 12개월을 채운다.
- 학습 모델 표의 6개월 집계(`input_features_6m.csv`, `*_6m` 열)는 이름·의미·값을 그대로 두고, 기간 설정만 새 키 `members.model_feature_months`로 나눴다.

## DB·API 변경
- DB: 테이블·컬럼 구조 변경 없음. 코멘트 2개(`MEMBER_MONTHLY_INPUT` 테이블, `MEMBER_CREDIT_GRADE.GRADE_STATUS_CODE`)와 `MEMBER_MONTHLY_INPUT` 시드(4,800행)가 바뀜. 행 순서가 바뀌어 `INPUT_ID` 값이 새로 매겨짐.
- API: 없음
- 영향을 받는 기능·팀원
  - 백엔드 등급 산정: `INSUFFICIENT_INPUT` 판정 기준이 12개월 미완료로 바뀜
  - 프론트 데이터 입력 화면(N-05): 현재 화면은 기준월 1개와 급여소득자 월급 1개 값만 받고, 자영업자·프리랜서 월별 소득은 최소 1개월이다. 12개월 입력 방식은 프론트 담당과 정해야 함(이번 작업에서 고치지 않음)
  - 모델 팀: 모델 표의 6개월 집계 값은 그대로라 영향 없음

## 다음 사람이 알아야 할 것
- `members.input_months` = 회원이 입력하는 달(12개월), `members.model_feature_months` = 모델 표 집계 달(6개월). 집계 달은 입력 달의 마지막 연속 6개월이어야 한다(검증기가 확인).
- 학습 전달 묶음(`tools.build_handoff`)은 다시 만들지 않았다. 모델 표 값은 같지만 묶음에 들어가는 README는 이번 문서 수정 전 내용이다. `tools/handoff_README.md` 제목·생성 버전 문구는 아직 v3.5.10이다(묶음을 다시 만들 때 함께 정한다).
- `manifest.json`의 해시는 저장소 기준(LF 줄바꿈) 내용으로 계산돼 있다. `field_dictionary.csv` 항목은 이번 작업 전부터 CRLF 기준 해시라 저장소 파일과 맞지 않는다(이번에 고치지 않음).
- 팀 결정 필요: `docs/ai/decisions.md`에 "회원 월 입력 12개월" 확정 행 추가, `decisions.md:40`의 "6개월 미만이면 정보 부족" 기준을 그대로 둘지.
