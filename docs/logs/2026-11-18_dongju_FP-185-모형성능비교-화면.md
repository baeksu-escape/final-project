# 관리자 모형 성능 비교 화면(N-25)을 mock으로 만들고 ADM-01·02 응답 필드를 정함

- **날짜:** 2026-11-18
- **작성자:** 동주 / Claude Code
- **브랜치:** `feature-C/FP-185-modelPerformanceUi`
- **관련 N-ID:** N-25-1, N-25-2, N-25-3, N-25-4
- **관련 결정:** 투표 D6(두 합성 집단 합쳐 보되 집단별로도), decisions.md N-25(컷오프 550~750·기본 650, 지표 6개, 오분류 비용 = 오승인×5)

## 무엇을, 왜 바꿨나
- 관리자 첫 화면 `/admin/model`이 준비 중 화면이었다. API(FP-184)는 비교 데이터가 아직 DB에 없어(`ASSESSMENT` 0건) 나중에 하고, 화면을 실제 응답과 같은 모양의 mock으로 먼저 만들었다.
- B팀 API 정의서에는 ADM-01·02의 경로만 🟡로 있어서, 응답 필드를 아래처럼 정했다.
- 고객 집단은 합성 학습 데이터(v3.6.0)에 실제로 있는 두 집단(`legacy`, `thinfile`)에 맞춰 **전체 / 기존 이력 집단 / 금융 이력 부족** 3개로 했다. 데모 v2의 '합성 집단 A·B'는 데이터에 없는 이름이라 쓰지 않았다.
- FP-184(API)는 별도 브랜치와 별도 PR로 한다.

## DB·API 변경
- DB: 없음
- API(새 응답 필드 제안, 아직 서버 없음):
  - ADM-01 `GET /api/admin/model-performance?group=ALL|LEGACY|THIN_FILE&cutoff=550~750`
    → `{ group, cutoff, sampleCount, legacy: { modelVersion, auc, accuracy, misclassCost, goodRejectRate, badApproveRate, approvalRate }, alternative: { 같은 필드 }, byJob: [{ jobType, sampleCount, legacyGoodRejectRate, alternativeGoodRejectRate }] }`
  - ADM-02 `GET /api/admin/model-performance/roc?group=…` → `{ group, legacy: { auc, points: [{ fpr, tpr }] }, alternative: { auc, points } }`
  - 비율은 0~1 소수이고, 차이(대안 − 기존)는 화면이 계산한다. 잘못된 집단이나 컷오프는 400 `INVALID_INPUT`이다.
- 영향을 받는 기능·팀원: 범영(B팀 API 정의서 ADM-01·02 필드 반영 — 동주가 전달 예정), FP-184(이 필드 이름을 그대로 구현)
