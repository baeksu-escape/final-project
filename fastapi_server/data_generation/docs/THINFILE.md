# 씬파일러·20대 시연 집단

기존 집단(12,000명)은 원본의 긴 신용이력 때문에 금융이력 부족 사례와 20대가 적다. 이를 보완하려고 씬파일 시나리오 3개 집단과 이력이 충분한 20대 비교 집단을 새로 생성한다(`build_thinfile.py`). 기존 행의 나이·기간을 잘라 만든 복제본이 아니다.

## 집단 설계

아래 범위와 각 600명은 시연·파이프라인 시험용 **설계값**이며 금융사·CB사의 공식 기준이나 국내 구성비가 아니다.

| cohort | 설계 | 나이 | 인원 |
|---|---|---|---:|
| no_credit | 현재·과거 대출/신용카드/보증 기록 없음 | 20~59세, 20대 표집확률 70% | 600 |
| short_history | 신용거래 시작 30~730일, 대출 0~1개·카드 0~1개, 둘 중 하나 이상 | 20~59세, 20대 표집확률 70% | 600 |
| sparse_history | 카드 1개, 대출 0개, 이력 3~8년, 최근 12개 30일 구간 중 카드 이용 최대 2개 구간 | 30~59세 | 600 |
| young_established | 이력 3년 이상, 대출 1~2개·카드 2~3개 | 23~29세 | 600 |

- 첫 세 집단은 `is_thinfile_scenario=1`, 비교 집단은 0이다. 20대라는 이유만으로 씬파일러로 분류하지 않는다.
- 직군은 집단마다 급여소득자·자영업자·프리랜서 200명씩이다. 이 구성도 인구통계가 아니다.
- 나이를 먼저 정하고 신용이력 길이를 그 안에서 만든다(19세 이전으로 넘어가지 않음).
- 예금·체크카드나 소득·지출 기록이 있는 것은 신용카드·대출 이력이 없는 것과 모순되지 않는다. 휴면 후 재진입, 해지 계좌만 있는 사람, 학생·무직은 포함하지 않는다.

## 생성 방식

원본 학원 생성기(`reference/academy/generate_dataset_original.py`)의 대출·카드·연체 원장 구조를 `thinfile_engine.py`에 적용했다. 대출·카드의 개수·기간·이용 구간을 먼저 정하고, 업권별·기간별·금액구간별 207개 항목을 원장에서 집계한다.

- 대출 총잔액 기초값은 short_history 50만~1,500만 원, 다른 집단 300만~5,000만 원이다. 계좌별 배분 잡음이 있어 실제 총잔액은 범위와 정확히 같지 않다. 업권·종류·금리·잔여기간은 기존 교육용 생성 규칙이며 씬파일러 실제 분포의 근거는 없다. 부채를 소득에서 역산하지 않는다.
- 보증, 상환 완료 대출, 추가 예금 개설은 만들지 않는다.
- 연체 사건은 실제 생성된 신용계좌에 연결하며 개설 전 사건은 없다. 계좌당 최대 1건이다. 카드 사건은 그 카드의 사용액이 양수인 30일 구간에만 생긴다. 여러 연체의 중첩·회복은 생략한다.
- 소득·생활지출·자산·월별 현금흐름은 기존 집단과 같은 규칙(`extend.py`)을 쓴다. 1인 가구 전체의 자산 비율을 20대에도 쓰는 한계가 있다.
- 통신·공과금 미납은 금융 연체 이력과 연동되고 여러 달 이어질 수 있다(`NONFINANCIAL_LABEL.md`).

## 0, 미관측, 등급 없음

`base_207.csv`는 기존 스키마 호환용 원시 집계다. 비율의 분모가 없으면 0이고, 등급 미산출 시 `CB=5`, 제시 한도·금리는 0을 **자리표시자**로 둔다. 이 값을 중간 등급이나 대출 거절로 해석하지 않는다. 모델에는 `model_inputs.csv`, 화면에는 `ui_credit_summary.csv`를 쓴다.

- `cb_available=0`: no_credit, sparse_history, short_history 중 이력 180일 미만. 프로젝트의 미산출 처리 가정이며 공식 조건이 아니다. 이때 `model_inputs.CB`와 `ui_credit_summary.educational_grade`는 빈 값이고, `credit_information_status=insufficient_history`다.
- 신용이력 자체가 없으면 SP·과거 연체 건수·최장 연체기간도 모델용 파일에서 빈 값이다. 사건이 없다는 0을 '성실 상환'으로 오해하지 않게 하려는 것이다.
- 최근 6개 30일 구간에 카드 사용이 없으면 `CL0631905`는 빈 값, `credit_usage_available=0`이다.
- 대출이 없다는 건수·잔액 0과 DSR 0은 유효한 값이다.
- 산출된 CB는 `clip(rint(3 + 0.45·log1p(대출 수) + 0.015·CL0631905 + 0.5·DQ1200001 + N(0, 0.5)), 1, 10)`의 교육용 등급이다. 실제 CB 점수가 아니다.
- 미래 신용 사용 여부와 라벨 설계 확률은 `target_metadata.csv`에만 있다. `cohort`, `label_origin`, ID와 함께 학습 특성으로 넣지 않는다.

## 월별 데이터와 시나리오

- `card_monthly.csv`의 `month_offset=0`은 기준일 2026-09-18부터 거슬러 올라간 최근 30일이다. 완결 달력월이 아니므로 월별 현금흐름과 직접 조인하지 않는다.
- `monthly_history.csv`는 2025-09~2026-08 완결 달력월의 소득·지출이다. 신용계좌 개설 전에도 있을 수 있다.
- `loan_monthly_budget.csv`는 현재 계좌의 연간 상환 추정액을 12등분하고 개설 전 달을 0으로 둔 **예산**이다. 개설 월은 월말에 계좌가 있으면 한 달분을 배정한다(일할 계산 없음). 실제 과거 원리금 경로가 아니다.
- 씬파일 집단의 `annual_debt_service_krw`·`dsr`은 위 12개월 예산 합계/소득이다. 207열 `LRZ021201`(향후 연간 상환 추정액)에 대응하는 값은 `snapshot_annual_debt_service_krw`·`snapshot_dsr`이다. 현재 차입 부담은 `snapshot_dsr`, 과거 12개월 예산은 `dsr`로 본다.
- `scenarios.csv`는 소득 20% 감소, 생활지출·상환 예산 고정 조건의 예시다.

## 라벨

씬파일 집단의 라벨은 기존 학원 라벨을 복사하지 않고, 원장의 가상 위험요인과 잡음으로 미래 연체 월수를 새로 만든다. 기존 집단과 라벨 생성 정의·분포가 다르므로 학습·평가 때 집단별 결과를 함께 본다.

- 현재 신용거래가 없는 사람도 미래에 신용을 쓸 수 있다고 가정한다. 미래 신용 사용 확률은 no_credit 35%, sparse_history 20%, 나머지 100%(가정)다. 미래에 신용을 쓰지 않은 고객의 라벨은 0이다. "쓰지 않아서 0"과 "썼지만 연체하지 않아서 0"은 의미가 다르다.
- 기본 위험확률은 신규 집단 전체 평균 10%로 맞춘 뒤 미래 신용 사용 여부를 적용하므로, 최종 양성률은 10%가 아니며 집단마다 다르다. 실제 씬파일러의 위험 수준 추정이 아니다.
- 기본 라벨에는 비금융 정보의 효과가 없다. 비금융 효과를 가정한 라벨은 `labels_nonfinancial.csv`다(`NONFINANCIAL_LABEL.md`).

## 카드 원장과 207열 카드 필드

**카드별 원장 `card_account_monthly.csv`**: 카드별 12개 30일 구간(키 `account_id`, `month_offset`). 고객의 일시불·할부·현금서비스 총액을 그 구간에 개설된 카드에 양수 가중치로 배분하며, 카드 합계는 고객 합계와 같다. `is_main_card`(12개 구간 사용액 합이 최대인 카드)와 `qualifies_latest_300`(최근 구간 사용액 300천 원 이상)은 **계좌 기준 참고 표시**이며 207열 카드 필드의 정의가 아니다. 체크카드 사용액은 고객 단위 `card_monthly.csv`에만 있다. 청구·결제·미상환 잔액·카드별 한도는 모형화하지 않는다.

**207열 카드 필드**: 기존 집단과 같은 이름의 열이 같은 의미를 갖도록 원본 학원 생성기의 고객 단위 규칙으로 계산한다.

| 필드 | 계산 |
|---|---|
| 주사용 카드(`CF0331605`, `CF0631605`, `CF123160x`) | 고객 월 총사용액 × 고객별 비율 45~95%. 카드 2장 이상이면 월별 참여 87% 적용. 카드 1장이면 고객 전체 사용개월수와 같다 |
| 30만원 조건 카드(`CF0332605`, `CF0632605`, `CF123260x`) | 최근 구간 고객 총사용액이 300천 원 이상이면 비율 30~95%와 월별 참여 82% 적용. 카드 1장이어도 전체 사용개월수보다 작을 수 있다 |
| `CS0000050` | 최근 구간 현금서비스가 있으면 `min(활성 카드 수, 1 + Poisson(0.3))`, 없으면 0. 실제 고유 기관 수나 잔액 기관 수가 아니다 |
| `CL0631905` | 고객 단위 이용률을 최근 6개 구간 중 카드가 개설돼 있던 구간만 평균. 6개 구간 모두 개설이면 원본 생성기와 같은 값 |
| `CL0631906` | 최근 6개월 평균 현금서비스 금액 / 가상 현금서비스 한도(카드 한도 × 0.4) |

계좌별 사실이 필요한 분석은 `card_account_monthly.csv`를 쓴다.

## 실행과 검증

```bash
python -m generate.build_thinfile                                 # 기본: 집단당 600명, seed 20261030
python -m generate.build_thinfile --per-cohort 60 --out /tmp/small # 시험 생성
python -m verify.verify_thinfile_general                         # 범위·합계·부분집합 불변식
python -m verify.verify_thinfile                                 # 원장 대조와 재현성(verify_card_accounts 포함)
```

`per-cohort`는 3 이상이어야 한다. `plan.csv`는 생성된 설계표이며 CLI는 편집한 plan을 입력받지 않는다. `verify_card_accounts.py`는 계좌 원장의 합계·개설 전 사용 금지·연체 연결과, 207열 카드 필드의 불변식(부분 개월수 ≤ 전체, 카드 1장 고객의 주사용 필드 = 전체, 30만 원 미달 고객의 조건 필드 = 0, `CS0000050` 범위, `CL0631905` 개설 구간 평균)을 검사한다.

참고: SCI평가정보 2025-01-09 보도자료(https://sci.co.kr/filedown/20250109.pdf)는 금융이력 부족 고객 평가에 비금융정보를 쓰는 방향을 설명한다. 이 문서의 수치 출처로 쓰지 않았다.
