# 대출 원장·상환 일정

기존 집단과 씬파일 집단의 대출 계좌별 원장과 미래 상환 일정이다(`build_loan_extension.py`). 실제 금융기관 원장이 아니다.

## 원장의 출처

- **기존 집단:** 원본 학원 생성기의 기본 설정(n=155,746, seed 20260918)을 대출 집계 구간까지 다시 실행해 SYN ID에 해당하는 행의 계좌를 꺼낸다. 실행 중 98개 원본 필드가 `data/base_207.csv`와 같은지 비교한다. 집계값에 맞춰 임의로 배분한 것이 아니라 원본 생성 과정의 원장을 재현한 것이다.
- **씬파일 집단:** `thinfile/loans.csv`를 그대로 쓴다.

## 파일 (`loan_extension/`)

| 파일 | 내용 |
|---|---|
| `legacy_loans.csv` | 기존 집단 대출 원장(천원 단위, 씬파일 원장과 같은 열) |
| `loans.csv` | 두 집단 합계. `balance_krw`, `snapshot_annual_service_krw`(원), 상환 방식·금리 유형 가정 열 추가. `sector`·`kind`·`institution_id`는 원본 코드 |
| `schedule.csv` | 계좌·시나리오·월별 월초 잔액, 원금, 이자, 상환액, 월말 잔액. 만기까지 |
| `service_comparison.csv` | 원본 연간 상환 근사액과 새 일정의 향후 12개월 합계 차이 |
| `customer_horizons.csv` | 무대출 고객 포함 전 고객 × 2개 시나리오 × 3/6/12개월 상환 합계. 연소득은 원본 값이며 미래 예측이 아니다 |

## 가정

1. 기준일 2026-09-18, 일정의 첫 월은 2026-10이다. 기준일 이후 9월의 남은 상환과 일할 이자는 넣지 않는다. 향후 12개월 합계는 2026-10~2027-09 기준이다.
2. 모든 계좌를 원금균등상환으로 가정한다. 잔액을 잔여 개월로 나눈 정수 몫을 매달 갚고, 나머지 원은 앞쪽 달에 1원씩 배분한다. 과거 계약을 복원한 것이 아니다.
3. 월 이자 = 월초 잔액 × 연금리 / 12, 원 단위 반올림(ROUND_HALF_UP). 수수료·중도상환·연체·추가 대출은 없다.
4. 고정/변동금리는 계좌 ID 해시의 홀짝으로 정한 시연용 배정이다. 실제 비중이 아니다.
5. `baseline`은 금리 유지, `rate_plus_2pp`는 첫 달부터 변동금리 계좌만 2%p 올린다.
6. 원본 `annual_service_thousand`(현재 잔액의 연이자 + 근사 원금)는 잔액이 줄어드는 새 일정과 다르다. 원본 필드와 207열·DSR은 그대로 두고, 미래 일정 합계는 따로 쓴다.
7. 과거 `monthly_history.csv`의 상환액은 바꾸지 않는다. 미래 일정은 과거 월별 현금흐름과 섞지 않는다.

## 실행

`python -m generate.build_loan_extension` 다음 `python -m verify.verify_loan_extension`. 원본 생성기의 대출 구간을 메모리에서 실행하므로, 원본 생성기의 해당 구간이 바뀌면 이 스크립트도 다시 확인해야 한다.
