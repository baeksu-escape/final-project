# 대출 원장·상환 일정

기존 집단과 씬파일 집단의 대출 계좌별 원장과 미래 상환 일정(만기일시·원리금균등·원금균등)이다(`build_loan_extension.py`). 실제 금융기관 원장이 아니다.

## 원장의 출처

- **기존 집단:** 원본 학원 생성기의 기본 설정(n=155,746, seed 20260918)을 대출 집계 구간까지 다시 실행해 SYN ID에 해당하는 행의 계좌를 꺼낸다. 실행 중 98개 원본 필드가 `data/base_207.csv`와 같은지 비교한다. 집계값에 맞춰 임의로 배분한 것이 아니라 원본 생성 과정의 원장을 재현한 것이다.
- **씬파일 집단:** `thinfile/loans.csv`를 그대로 쓴다.

## 파일 (`loan_extension/`)

| 파일 | 내용 |
|---|---|
| `legacy_loans.csv` | 기존 집단 대출 원장(천원 단위, 씬파일 원장과 같은 열) |
| `loans.csv` | 두 집단 합계. `balance_krw`, `snapshot_annual_service_krw`(원), 상환 방식(`repayment_method`, 근거 `repayment_method_basis`)·금리 유형 가정 열 추가. `sector`·`kind`·`institution_id`는 원본 코드 |
| `schedule.csv` | 계좌·시나리오·월별 월초 잔액, 원금, 이자, 상환액, 월말 잔액. 만기까지 |
| `service_comparison.csv` | 원본 연간 상환 근사액과 새 일정의 향후 12개월 합계 차이 |
| `customer_horizons.csv` | 무대출 고객 포함 전 고객 × 2개 시나리오 × 3/6/12개월 상환 합계. 연소득은 원본 값이며 미래 예측이 아니다 |

## 가정

1. 기준일 2026-09-18, 일정의 첫 월은 2026-10이다. 기준일 이후 9월의 남은 상환과 일할 이자는 넣지 않는다. 향후 12개월 합계는 2026-10~2027-09 기준이다.
2. 상환방식은 대출 종류(`kind`)별 확률표(`reference/repayment_method_assumptions.json`)에서 계좌 ID 해시로 배정한다(v3.5.9). 위험도·라벨과 무관하게 배정하므로 상환방식은 부도 예측력이 없는 것이 정상이다. 과거 계약을 복원한 것이 아니다.
   - `bullet`(만기일시): 매달 이자만 내고 마지막 달에 원금 전액을 갚는다.
   - `equal_payment`(원리금균등): 월 납입액 = P·r/(1−(1+r)^−n)(r=연금리/12)를 원 단위 ROUND_HALF_UP하고, 원금 = 납입액 − 이자. 마지막 달에 남은 잔액을 모두 갚는다. 금리 +2%p 시나리오에서는 오른 금리로 납입액을 다시 계산한다.
   - `equal_principal`(원금균등): 잔액을 잔여 개월로 나눈 정수 몫을 매달 갚고, 나머지 원은 앞쪽 달에 1원씩 배분한다.

   | kind | 종류 | 만기일시 | 원리금균등 | 원금균등 | 근거 |
   |---|---|---|---|---|---|
   | 1 | 주택담보 | 0.48 | 0.39 | 0.13 | 만기일시 0.48은 통계(은행 주담대 비거치 분할 51.6%, 2018년 말, [기사](https://www.hankyung.com/article/201903033681Y)). 분할 안의 3:1은 가정 |
   | 7 | 기타 부동산담보 | 0.48 | 0.39 | 0.13 | 주담대 값을 옮긴 가정 |
   | 0 | 신용(무담보) | 0.80 | 0.15 | 0.05 | 만기일시가 기본이라는 상품 설명([하나은행](https://www.kebhana.com/cont/mall/mall08/mall0802/mall080204/1462446_115200.jsp))이 근거, 비율 값은 가정 |
   | 2 | 신차 할부 | 0 | 1.00 | 0 | 가정 |
   | 8 | 신차 외 할부 | 0 | 1.00 | 0 | 2번과 같은 가정. 8번 정의는 코드 사용 방식으로 추정 |
   | 3·4 | 예적금·유가증권 담보 | 1.00 | 0 | 0 | 가정 |
   | 5 | 보증 | 1.00 | 0 | 0 | 가정 |
   | 6 | 학자금 | 0 | 1.00 | 0 | 가정(원문 미확인) |

   통계는 은행 기준이지만 모든 업권에 똑같이 적용했다. 값마다 `basis`·`source`·`note`는 설정 파일에 있다.
3. 월 이자 = 월초 잔액 × 연금리 / 12, 원 단위 반올림(ROUND_HALF_UP, 모든 방식 공통). 연금리는 원장에 쓸 때 소수 4자리(0.01%p)로 ROUND_HALF_UP 고정한다(v3.5.8). 원장·일정·더미 API·DB가 같은 금리를 써서 DB 금리로 이자를 다시 계산해도 같다. 수수료·중도상환·연체·추가 대출은 없다.
4. 고정/변동금리는 계좌 ID 해시의 홀짝으로 정한 시연용 배정이다. 실제 비중이 아니다.
5. `baseline`은 금리 유지, `rate_plus_2pp`는 첫 달부터 변동금리 계좌만 2%p 올린다.
6. 원본 `annual_service_thousand`(현재 잔액의 연이자 + 근사 원금)는 잔액이 줄어드는 새 일정과 다르다. 원본 필드와 207열·DSR은 그대로 두고, 미래 일정 합계는 따로 쓴다. 이 근사액은 금리를 고정하기 전 값으로 계산돼 있으므로 원장의 고정된 금리와 아주 작은 차이가 남는다(라벨·모델 표를 바꾸지 않으려는 선택).
7. 과거 `monthly_history.csv`의 상환액은 바꾸지 않는다. 미래 일정은 과거 월별 현금흐름과 섞지 않는다.

## 실행

`python -m generate.build_loan_extension` 다음 `python -m verify.verify_loan_extension`. 원본 생성기의 대출 구간을 메모리에서 실행하므로, 원본 생성기의 해당 구간이 바뀌면 이 스크립트도 다시 확인해야 한다.
