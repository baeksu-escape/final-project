# 비금융 추가 정보 실험

추가 정보에 신호를 넣었을 때 모델 파이프라인이 그 신호를 찾아내는지 확인하는 통제 실험이다(`run_nonfinancial_experiment.py`). 실험 전용 라벨을 따로 만들어 쓰며, 기존 라벨과 비금융 효과 라벨(`NONFINANCIAL_LABEL.md`)은 바꾸지 않는다. 실제 예측력 검증이 아니다.

## 설계

- 기존 12,000명과 씬파일 4개 집단을 각각 따로 학습·평가한다. 집단 간 AUC 차이는 위험 차이나 모델 우열의 근거가 아니다.
- 집단별 고정 70/30 고객 분할(seed 42), 라벨 난수 seed 501~505로 5회 반복한다. 표준편차는 라벨 난수 변화에 따른 변동이며 신뢰구간이 아니다.
- 금융 입력 8개: CB, SP, 대출 건수·잔액, 연체 건수, KC5000016, 연간 상환액, 카드 이용률. 추가 입력 6개: 연소득, 지출비율, DSR, 소득 변동계수, 통신·공과금 미납 월수. DSR처럼 금융과 겹치는 정보가 있어 순수 비금융 변수의 인과효과 실험은 아니다.
- 조건 세 가지: `no_effect`(금융 지수만으로 확률 생성), `weak`(금융 지수 + 추가 지수 1 표준편차당 로짓 0.5), `weak_degraded`(weak와 같은 라벨, 추가 입력에 잡음과 20% 무작위 누락).
- 확률 절편은 학습 고객 평균 10%에 맞춘다. 모든 고객에게 미래 신용 노출이 있다고 가정하므로 씬파일 기본 라벨의 노출 가정(35%/20%)과 다르다. 가중치와 목표 확률은 가정이며 `config.json`에 기록된다.
- 확률·실험 라벨·ID·집단명·기존 라벨은 모델 입력에 넣지 않는다. 전처리와 모델은 학습 고객으로만 적합한다.

## 해석

- `no_effect` 조건에서는 추가 입력이 AUC를 올리지 않아야 하고, `weak`에서는 올라야 한다. 이 차이로 파이프라인이 신호를 찾는지 본다.
- 씬파일 집단은 평가 고객이 집단당 약 180명이라 변동이 크다. AUC 상승이 확률 정확도(Brier) 개선을 보장하지도 않는다.
- 집단당 수십 명으로 시험 생성하면 평가 집단에 한쪽 라벨만 남아 AUC를 계산할 수 없다. 이 규모의 성능 수치는 해석하지 않는다.
- 결과에 맞춰 효과 가중치나 seed를 조정하지 않는다. 보고에 쓸 때는 집단·조건·합성 라벨임을 함께 적는다.

## 파일과 실행

`python -m experiments.run_nonfinancial_experiment` 다음 `python -m verify.verify_nonfinancial_experiment`. 결과는 `nonfinancial_experiment/`에 생긴다: `config.json`(가중치·시드·입력), `split.csv`(학습/평가 고객), `experiment_labels.csv`(실험 라벨·설계 확률, 학습 입력 금지), `heldout_predictions.csv`, `metrics.csv`(ROC-AUC·AP·Brier·log loss), `paired_differences.csv`, `summary.csv`.
